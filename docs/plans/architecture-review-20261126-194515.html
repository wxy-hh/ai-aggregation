Problem

Problem

run-stream.ts 通过解析 done/error 推导 LiveRun 终态，订阅实现又按 chunk 解析一次；它与 AgentRunner、ChatCompletionLifecycle 的终态词汇和判定点不同。

Solution

由 AgentRunner 声明唯一终态事实，LiveRun、RunEventLog 与完成生命周期共同消费；传输 implementation 只负责编码与重放，不再拥有业务终态。

Deletion test：删除字节反解后，注册表失去终态；能力本身必要，但应移动到已经知道语义终态的 AgentRunner seam。
  • locality
    终态词汇集中定义
  • leverage
    回收与结算共享事实
  • tests
    跨 module 终态矩阵可测
与 ADR-0061 §6 同向：由运行器写入唯一终态并标记 LiveRun。保留进程内 RunEventLog，不引入 Redis、数据库运行态或 seq。

验证盲区 · 实施前先补测试入口

tooling/eval/__tests__/ 不在 apps/web/vitest.config.ts:11 或 packages/shared/vitest.config.ts:5 的收集范围内；根 test:eval 也只指向 Web 的旧评测目录。候选 01 / 04 应先让现有运行器测试进入标准测试命令。

明确排除 · 不按文件大小重构

ChatStreamProjector、ChatCompletionLifecycle 已有清晰 interface 与测试 depth；ChatWorkspace 剩余体量主要是展示实现；conversation-orchestrator 整体仍是 ADR-0046 的唯一协调 seam，均不列为独立候选。

Top recommendation

先实施候选 01：真实的 Case Executor

它把真实 Agent 执行与 dry-run 回放放到同一个可测 seam；没有这块 depth，候选 03 的看板与候选 04 的 AblationMatrix 仍只能展示不可验证的数字。
