# /chat 智能对话向 Agent 渐进式演进待办计划 (Chat-to-Agent Evolution Plan)

> **设计哲学与思考原点**：
> 1. **把表象问题投影到底层问题**：不要在表象层无限堆砌 Prompt 和单体多步步数；Agent 的本质不是“能连续聊很多轮”，而是**提高信息加工与交付的有效密度**，把人从繁琐的操作回路中解放出来。
> 2. **先小验证，再押大注**：拒绝一步到位的庞大通用多智能体架构。每一个演进阶段都必须有明确的单点验证场景、量化基准与业务转化数据，跑通闭环后再规模化。
> 3. **Context not Control（上下文而非控制）**：人负责定义目标、注入业务 Context 并把控关键副作用；Agent 负责拆解路径与自治执行，通过结构化界面透明化进展。
> 4. **避免模型单体过拟合**：单一模型实例同时承担意图理解、网页长文解析、长篇撰写与工具调用，必然导致注意力涣散。走向专业化的轻量分工（Planner / Worker / Evaluator）。
> 5. **构建数据飞轮**：摆脱每次请求无状态消耗的孤岛模式，把高质量交互产物与知识库打通，让系统越用越贴合用户业务。

## 二、 阶段演进细则 (Progressive Milestones)

### Phase 1：数据闭环与信息检索升维（先跑通最小正反馈）

> **目标**：不改动复杂的底层执行流，先将「知识库」与「Agent 产物」连接成双向通路，并升级 RAG 深度。

#### 1. `AGENT-KB-LOOP`：产物回写知识库与双向数据闭环 (P0)
- **底层痛点**：用户在 `/chat` 耗费算力跑出的行业研报、竞品分析表、清洗代码或定制方案，会随会话关闭被淹没；下次开启新会话依然要重新搜索、重新整理。知识资产无法复利累积。
- **演进设计**：
  1. **工作台一键沉淀**：在 `Artifacts` 工作台与消息操作栏增加「沉淀至知识库」动作。
  2. **智能分面建档**：Agent 后台根据产物类型自动提取标准标题、摘要（Summary）、核心标签（Tags），并作为高优先级切片写入用户指定的知识库。
  3. **问答对反哺**：针对多次修改确认的高价值问答，支持「提炼为官方 FAQ 对」，沉淀为带有权威置信度的 Ground Truth。
- **关联模块**：`apps/web/src/components/chat/`、`packages/db/src/rag/`、`apps/web/src/app/api/knowledge-bases/`。
- **验收与数据指标**：
  - 产物转入知识库链路端到端耗时 $\le 1.5\text{s}$；
  - 统计指标：**沉淀知识的次周二次召回率（Secondary Recall Rate）**。

#### 2. `AGENT-DOC-TREE`：知识库层级大纲与定向下钻检索 (P0)
- **底层痛点**：目前的 RRF 混合检索直接检索平铺的 500 字 chunk。面对“总结该系统的权限架构设计”或“对比两份规章差异”等全局宏观问题时，切片碎片化严重，经常“只见树木不见森林”。
- **演进设计**：
  1. **解析层大纲提取**：在 `apps/worker` 解析 Word/Markdown/PDF 时，构建自顶向下的章节大纲树（Document Outline Tree），存入文档元数据。
  2. **双层探索工具**：新增只读工具 `knowledge_outline`。当意图涉及“整体框架/大纲/章节归纳”时，模型先查目录树，锁定相关章节。
  3. **定向下钻切片**：结合已有的 `headingPath`，仅加载相关章节下的高置信度切片，降低无关噪音对上下文窗口的侵蚀。
- **关联模块**：`apps/worker/src/workers/rag-index/`、`apps/web/src/app/api/chat/_lib/agent/tools/`。
- **验收与数据指标**：
  - 复杂长文档概括类提问的幻觉率下降 $\ge 40\%$；
  - 全局检索场景消耗的 Token 上下文减少 $\ge 35\%$。

### Phase 2：交付物中心化与透明化规划（重构用户感知）

> **目标**：改变「文字气泡对话」的交互形态，让用户聚焦于「实体产物演进」与「Agent 执行步骤」。

#### 3. `AGENT-WORKSPACE`：交付物中心化工作台 (P1)
- **底层痛点**：用户要的是一份完整的 PRD、代码、或者对比表格，而不是几屏气泡对话。纯文本流式输出在长篇交付时极难阅读与比对。
- **演进设计**：
  1. **界面重心翻转**：默认在右侧（或宽屏中心）展开实时更新的 Canvas/Artifacts 面板。
  2. **对话区降维**：左侧/底部对话框定位为「指令流与即时状态机」，只展示阶段摘要与用户指令。
  3. **增量演进与 Diff 对照**：支持模型在多轮对话中针对产物的特定章节进行局部 Patch 更新，并提供可视化 Diff 比对，允许用户一键回滚。
- **关联模块**：`apps/web/src/app/chat/`、`apps/web/src/stores/chat-store.ts`、`packages/shared/src/chat-stream-contract.ts`。
- **验收与数据指标**：
  - 长文本交付场景的用户单次阅读停留时长与滚动摩擦显著下降；
  - 产物复制与导出（Markdown/HTML）行为转化率提升 $\ge 50\%$。

#### 4. `AGENT-PLAN-DAG`：显式目标拆解与可干预计划卡片 (P1)
- **底层痛点**：目前的 ReAct 循环是完全的黑盒。模型盲目调用 3-5 次工具，用户在屏幕前只能干等，遇到偏离意图无法及时纠正，只能点击 Stop 重新来过。
- **演进设计**：
  1. **前置 Planner 节点**：收到复杂任务后，模型首步输出结构化执行计划（3-5 个 Checkpoint，如：1. 检索竞品数据 → 2. 分析优劣势 → 3. 产出最终表格）。
  2. **交互式计划卡片**：前端渲染为可视化任务进度条，用户可实时点击暂停、修改后续步骤或补充上下文（Human-in-the-loop 前置）。
  3. **状态持久化**：计划步骤与执行结果状态绑定，支持刷新后断点回看。
- **关联模块**：`apps/web/src/app/api/chat/_lib/agent/agent-runner.ts`、`apps/web/src/components/chat/`。
- **验收与数据指标**：
  - 用户中途中止（Abort）后的二次提问修正率提升；
  - 复杂任务端到端完成率（Task Success Rate）从基线提升 $\ge 25\%$。

### Phase 3：多节点分工与有界副作用（工程可靠性突破）

> **目标**：解决单模型过拟合瓶颈，使 Agent 从只读查询走向受控的现实业务处理。

#### 5. `AGENT-EVAL-CHECK`：独立质检节点与反思自愈 (P2)
- **底层痛点**：同一个模型实例既当运动员又当裁判员，当它抓取到错误网页或检索切片不相关时，极易自我合理化，给出似是而非的错误结论。
- **演进设计**：
  1. **Evaluator 独立校验**：在收尾步（Summary Step）之前，引入独立的轻量校验逻辑（基于规则或轻量快速模型），对照用户原始约束检查关键事实（如：是否涵盖所有指定的比较维度？引用切片是否有效支撑结论？）。
  2. **自愈反思回路**：未通过质检时，将具体的质检反馈注入模型下一轮决策上下文，触发定向补充检索或修正。
  3. **硬熔断防线**：质检自愈最多允许 1 次重试，避免死循环消耗 Token 额度。
- **关联模块**：`apps/web/src/app/api/chat/_lib/agent/`、`apps/web/src/app/api/chat/_lib/agent/agent-config.ts`。
- **验收与数据指标**：
  - 核心事实幻觉与逻辑遗漏率下降；
  - 单请求调用成本控制在安全预留预算内（不突破 `AGENT_MAX_STEPS` 限制）。

#### 6. `AGENT-HITL-ACTION`：受控写操作与人机协同确认 (P2)
- **底层痛点**：现有工具全部为只读检索工具，无法替用户执行实际工作任务（如发送通知、更新外部数据库、触发后台定时任务）。
- **演进设计**：
  1. **工具权限分级**：将工具清晰划分为 `read-only`（只读，直接执行）与 `mutating`（具副作用写操作，受控执行）。
  2. **两阶段提交确认协议**：当模型决定调用 `mutating` 工具（如 `send_email`、`update_record`）时，流中暂停并推送 `tool_approval_request` 事件，前端渲染出参数确认卡片。
  3. **人机闭环授权**：用户在界面点击「确认执行」或「修改参数」后，客户端携带凭证通知服务端继续恢复执行。
- **关联模块**：`packages/shared/src/chat-stream-contract.ts`、`apps/web/src/app/api/chat/`、`apps/web/src/lib/api/agent-tools.ts`。
- **验收与数据指标**：
  - 误触发与高危写操作事故率为 0；
  - 拓展应用从“问答助手”升级为“自动化工作台”。

### Phase 4：主动智能与知识生态（持续进化的数据飞轮）

> **目标**：让系统具备主动性，知识库不再被动等待检索，而是主动净化与预取。

#### 7. `AGENT-AUTO-AUDIT`：知识冲突主动仲裁与前置实体预取 (P3)
- **底层痛点**：企业/个人知识库随时间推移积累了大量废弃文档，同一概念存在多版本矛盾；且每次查询知识库都需要模型往返等待数秒。
- **演进设计**：
  1. **后台知识体检 Worker**：定期分析向量空间中的临近但高差异断言，标记疑似“过时/矛盾”文档，并在知识库工作台生成体检报告。
  2. **会话级前置实体预取**：当用户在绑定了特定知识库的项目会话中输入时，轻量拦截器分析关键词，在首字输出前异步完成 Top-1 实体背景注入，消除工具调用的首轮等待。
  3. **冲突仲裁提示**：检索命中冲突切片时，显式提示来源文档版本与时间戳差异，由模型客观呈现差异而非主观捏造。
- **关联模块**：`apps/worker/src/workers/`、`apps/web/src/lib/rag/`。
- **验收与数据指标**：
  - 知识库问答首包时间（TTFT）缩短 $\ge 30\%$；
  - 知识库版本陈旧误导投诉率归零。

## 三、 演进度量衡与逃逸指标 (Metrics & Guardrails)

张一鸣在九周年演讲中谈到：“随便说 All-in 有时候是一种偷懒。”在 Agent 的演进上，绝对不靠主观感觉来评判好坏，必须建立完整的工程与产品对照看板：

```
                    ┌─────────────────────────┐
                    │      业务价值顶层指标     │
                    │   端到端任务成功率 (TSR)   │
                    │   用户 7 日产物复用率     │
                    └────────────┬────────────┘
                                 │
         ┌───────────────────────┴───────────────────────┐
         ▼                                               ▼
┌─────────────────────────┐                     ┌─────────────────────────┐
│       效率与体验指标      │                     │       工程与成本防线     │
│ - 达到满意交付的平均轮数  │                     │ - 单任务平均 Token 消耗 │
│ - 关键信息检索命中准确率  │                     │ - 超时与死循环熔断率    │
│ - 首字延迟与交付总耗时    │                     │ - 连败中断与异常降级率  │
└─────────────────────────┘                     └─────────────────────────┘
```

1. **核心北极星指标**：
   - **TSR (Task Success Rate，端到端任务成功率)**：用户输入复杂需求后，无需人工大范围重写直接采用 Artifacts 交付物的比例（目标：从现状 ~40% 提升至 $\ge 75\%$）。
   - **知识复用率 (Knowledge Reuse Ratio)**：通过 Agent 沉淀至知识库的内容，在 30 天内被其他会话或检索再次命中的频次与比例。

2. **成本与安全防线（不可逾越的红线）**：
   - 单请求严格继承已有的 240 秒运行时间预算与单步 Token 上限，禁止因节点拆分导致成本失控；
   - 任何涉及用户数据覆写或外部系统变更的操作，严格走人在回路（HITL）确认，坚决守住安全底线。
