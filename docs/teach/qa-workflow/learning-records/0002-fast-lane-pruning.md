# 0002: 流程拒绝一刀切，快慢车道剪裁与时间盒控制

研发闭环流程不是教条式的瀑布模型，必须按需求规模进行自适应剪裁；交互式浏览器真机验收必须遵守「不超过 5 条用例 / 15 分钟」的时间盒红线，杜绝“小需求写10分钟、浏览器验2小时”的成本失控。

## Status
active

## Evidence
- 小型修改（文案、样式、局部 Bug）：走快车道，直接 `/implement` 并通过 TDD 验证，若触及 P0 则补跑 1~2 条冒烟，无需冗长的 ADR 盘问与工单拆解。
- 中型特性/重构（如 Candidate 01）：跳过 3A 工单拆解，直接从 Spec 进入 TDD，浏览器只跑受影响的核心链路（4 条用例）。
- 回归测试分工：已验收过的确定性逻辑，沉淀为 Playwright 无头脚本（`test:e2e`，秒级跑完、零模型 Token 消耗），交互式浏览器仅负责新特性的首次探查与视觉留痕。

## Implications
团队成员应树立成本意识：交互式真机验证只针对核心新行为，严禁全量拉起交互式浏览器跑几十个历史用例。
