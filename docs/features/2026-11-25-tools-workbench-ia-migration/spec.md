# 技术规格：我的工具独立工作台与个人中心信息架构收敛

Spec Authority: `docs/features/2026-11-25-tools-workbench-ia-migration/spec.md`（唯一事实源；`.scratch/tools-workbench-ia-migration/spec.md` 为供 QA 检查器解析的工作副本）

## Problem Statement

用户在个人中心（`/profile`）完成身份、额度与安全操作，却要在同一条长滚动页里管理两类供给侧扩展配置——私有 Webhook 工具与个人远程 MCP 服务器。这带来三个叠加的问题：

**长度**：个人中心是一条不分节的单页长滚动，基本信息之后紧接着两个重量级配置板块（工具列表含抽屉表单与调用日志抽屉、MCP 服务器列表含工具白名单抽屉），用户要滚动多屏才能到达邮箱绑定、对话记忆与安全退出。

**语义混杂**：「账户设置」里混入了开发者向的外部能力接入配置，与头像、邮箱绑定、账户注销不同属一类信息，观感上像把工具台塞进了后台管理页。

**入口错位**：同一批配置在产品内没有属于自己的「工位」——用户必须先知道「它在个人中心里」才能找到它，而应用启动台（Apps Modal）、移动端抽屉等全局入口都不指向它。

结果是个人中心既不像账户页也不像工作台，两头不靠；而真正把工具用起来的人（从对话页的可用工具面板反查配置）却要为每次跳转付出跨页定位成本。

## Solution

1. **独立工作台**：新增 `/tools` 路由作为「我的工具」专属工作台，页内并列两个分区——「我的工具」（私有 Webhook 接口配置，保留既有列表、抽屉表单、调用日志抽屉与全部既有能力）与「MCP 服务」（个人远程 MCP 服务器登记与工具白名单管理，完整保留 ADR-0064 的安全边界、审批策略与快照语义）。两类扩展同属「给智能体接外部能力」，由同一批用户在同一段旅程中配置，因此合并为一个工作台而非两个独立页面。

2. **启动台获得正式入口**：在应用启动台「专业生产力」分组新增「我的工具」卡片，排在「知识库」之后。启动台是全局模块索引，新模块在此获得与其他模块一致的发现路径与置顶能力；移动端抽屉、移动端顶栏标题、桌面侧边栏置顶因共用同一份应用注册表而自动生效。

3. **个人中心回归高信噪比**：移除个人中心内的两个重量级配置板块，保留一张**静态**入口卡片（图标 + 标题 + 一句话说明 + 跳转箭头），不携带配置计数、不触发任何配置接口请求，使个人中心加载成本不因本次迁移上升。原位置的个人中心其余布局（基本信息、邮箱绑定、对话记忆、安全退出、危险区域、右侧资源消耗侧栏）保持现状不动。

4. **从对话侧的每一条路径精确落位**：对话页可用工具面板中「管理工具」「管理 MCP」两个入口与两个空态引导链接，全部指向新工作台对应的分区锚点，使「从对话找到配置」这条最主路径从「跳页再肉眼定位」降为「跳页即到位」。空态文案同步更新，去除「个人中心」指代。

5. **入口迁移对既有治理语义零影响**：MCP 工具的发现、白名单、审批策略、快照失效、审计与计费口径全部保持 ADR-0064 既有语义，本次仅改变配置界面的物理位置与入口路径。

## User Stories

**A. 我的工具工作台的可达性与定位**

1. 作为登录用户，我想从应用启动台「专业生产力」分组看到「我的工具」卡片，以便像进入知识库、简历制作那样直接打开我的扩展工具工作台。
2. 作为登录用户，我想在启动台搜索「工具」时能命中「我的工具」卡片，以便不知路径时也能搜到。
3. 作为登录用户，我想在移动端抽屉中看到「我的工具」入口，以便在手机上也能进入工具管理。
4. 作为登录用户，我想在移动端打开工具工作台时顶栏显示「我的工具」标题，以便知道自己在哪一页。
5. 作为登录用户，我想在桌面侧边栏把「我的工具」置顶，以便把它固定在常用位置。
6. 作为登录用户，我想把「我的工具」从侧边栏取消置顶，以便按需调整侧边栏构成。
7. 作为未登录访客，我想访问工具工作台时被引导至登录页并在登录后回到工具工作台，以便不丢失原本想去的页面。
**B. 工作台内的两个配置分区**

8. 作为登录用户，我想在工作台首屏同时看到「我的工具」与「MCP 服务」两个分区，以便集中管理两类扩展而不必记住多个菜单位置。
9. 作为登录用户，我想在 Webhook 工具分区看到每个工具的显示名、调用名、URL 域名、方法徽章与凭证状态标识，以便确认配置是否符合预期。
10. 作为登录用户，我想在 MCP 服务分区看到每个服务器的名称、地址与工具数量状态，以便掌握当前登记了哪些外部服务。
11. 作为登录用户，我想从工作台直达区段而不必先滚过另一个分区，以便从启动台进入时直接看到目标内容。
12. 作为登录用户，我想在 Webhook 工具数量达到上限时看到计数徽标与「添加新工具」按钮被禁用，以便知道还能再加几个。
13. 作为登录用户，我想在 MCP 服务器数量达到上限时看到计数徽标与「添加新 MCP 服务器」按钮被禁用，以便知道还能再加几个。
14. 作为访问者，我想在认证引导尚未完成时看到「登录后即可管理」的引导卡片而不是报错或空白，以便理解为何暂时看不到配置。

> 入口守卫与页面内引导的分工：未登录访客访问 `/tools` 由中间件拦到登录页（携带 `redirect=/tools` 回跳意图，见 US 7）；页面内的「登录后即可管理」引导作用于**认证引导尚未完成**的短窗口（Cookie 已存在但 accessToken 未就绪），两者不冲突。

**C. Webhook 工具配置的完整能力保持**

15. 作为登录用户，我想在工具工作台新建一个私有 Webhook 工具，以便智能体能在对话中自主调用我的接口。
16. 作为登录用户，我想从既有模板快速填充工具表单，以便少填重复字段。
17. 作为登录用户，我想在表单校验不通过时看到字段级中文错误，以便知道哪里填错了。
18. 作为登录用户，我想在提交后遇到后端业务错误时看到后端返回的中文原因，以便定位是 URL、方法还是参数的问题。
19. 作为登录用户，我想在测试连接成功时看到状态码与耗时，以便确认接口可达。
20. 作为登录用户，我想在测试连接失败时看到中文失败原因，以便排查。
21. 作为登录用户，我想在测试连接被限流时看到友好提示而不是报错堆栈，以便知道稍后重试即可。
22. 作为登录用户，我想单独切换某个工具的启停状态，以便控制它是否进入后续 Agent 会话。
23. 作为登录用户，我想编辑既有工具的 URL、参数与凭证配置，以便随接口演进更新。
24. 作为登录用户，我想在删除工具前经过二次确认，以便不误删。
25. 作为登录用户，我想查看某个工具的调用日志，以便排查历史调用失败原因。
26. 作为登录用户，我想在创建 POST 类型工具时看到「默认需要确认后才会执行」的说明，以便理解 ADR-0041 的审批语义。
27. 作为登录用户，我想对既有 POST 工具关闭逐次确认，以便对低风险接口减少打断。

**D. MCP 服务的完整能力保持**

28. 作为登录用户，我想在 MCP 服务分区登记一个远程 MCP 服务器（名称、HTTPS Streamable HTTP 地址、可选静态鉴权头），以便标准 MCP 服务无需改平台代码即可接入。
29. 作为登录用户，我想在提交非 HTTPS、私网、回环或云元数据地址时被明确拒绝并看到中文原因，以便平台不成为 SSRF 通道。
30. 作为登录用户，我想在保存时服务暂时不可达仍保留配置并看到「发现失败」，以便不用重填表单就能稍后重试。
31. 作为登录用户，我想点「刷新工具」后看到该服务暴露的工具名、描述与参数摘要，以便决定信任哪些。
32. 作为登录用户，我想在发现或刷新失败时看到超时、鉴权失败、协议不支持等明确原因且不看到任何密钥，以便排障且不泄凭证。
33. 作为登录用户，我想编辑服务器时鉴权头取值永不回显、只显示「已配置」，以便密钥不泄漏到前端。
34. 作为登录用户，我想修改 URL 或鉴权配置后旧工具快照与待审批卡片立即失效，以便不会用旧批准执行新目标。
35. 作为登录用户，我想逐个启用发现到的工具，未启用的工具绝不出现在模型上下文，以便控制上下文与出站面。
36. 作为登录用户，我想为每个 MCP 工具单独设置是否需要审批，以便对有副作用的调用保留人工确认。
37. 作为登录用户，我想删除服务器时其工具与待审批调用一并失效，以便不存在孤儿工具。
38. 作为登录用户，我想停用服务器后其工具不再进入后续 Agent 会话，以便即时收窄能力。
39. 作为登录用户，我想完全看不到也调用不了其他用户的 MCP 配置与工具，以便租户隔离成立。

**E. 个人中心的收敛**

40. 作为登录用户，我想打开个人中心时不再需要滚动多屏才能看到邮箱绑定与安全退出，以便快速完成账户操作。
41. 作为登录用户，我想在个人中心看到一张「我的工具」入口卡片，以便知道扩展配置搬到了哪里并一键前往。
42. 作为登录用户，我想在个人中心不看到任何 Webhook 工具或 MCP 服务器的配置列表，以便个人中心保持账户信息的高信噪比。
43. 作为登录用户，我想点击个人中心的「我的工具」入口卡片直接到达工具工作台，以便不绕路。
44. 作为登录用户，我想在个人中心看不到「已配置 N 个工具」之类的计数，以便个人中心不为这两类配置发起任何请求、保持轻量。
45. 作为登录用户，我想在个人中心保留头像、邮箱绑定、对话记忆、安全退出与危险区域等原有账户功能，以便迁移没有损失既有能力。
46. 作为登录用户，我想在个人中心右侧继续看到资源消耗统计，以便随时掌握额度使用情况。

**F. 从对话侧精确落位**

47. 作为登录用户，我想在对话页可用工具面板点击「管理工具」直接到达工具工作台的 Webhook 工具分区，以便配置入口与使用入口在同一屏内闭合。
48. 作为登录用户，我想在对话页可用工具面板点击「管理 MCP」直接到达工具工作台的 MCP 服务分区，以便不必落到工作台首页再自己找。
49. 作为登录用户，我想在对话页可用工具面板没有 Webhook 工具时，点击空态引导直接到达 Webhook 工具分区，以便立即开始添加。
50. 作为登录用户，我想在对话页可用工具面板没有 MCP 工具时，点击空态引导直接到达 MCP 服务分区，以便立即开始配置。
51. 作为登录用户，我想在对话页看到的空态引导文案不再指向「个人中心」，以便文案与新位置一致、不造成误导。
52. 作为登录用户，我想从对话页工具面板跳转后不产生多余中间步骤，以便配置与使用之间的路径不因本次迁移变长。
53. 作为登录用户，我想在对话页仍然看到 Webhook 工具与 MCP 工具的分组、来源徽标与数量统计，以便本次迁移不影响对话侧的工具可见性。

**G. 迁移的兼容性边界**

54. 作为登录用户，我想已有的 Webhook 工具配置在迁移后仍然可用，以便迁移不丢失既有扩展。
55. 作为登录用户，我想已有的 MCP 服务器登记与工具白名单在迁移后仍然生效，以便迁移不丢失既有信任决策。
56. 作为登录用户，我想迁移后会话级工具覆盖（`SessionToolOverride`）行为保持不变，以便对话内临时启停工具的语义不受影响。
57. 作为登录用户，我想迁移后 `CapabilityPack` 场景包下的工具可用性保持不变，以便不同场景包不产生意外差异。
58. 作为用户，我想本次迁移不改变任何工具调用的审批、审计与计费口径，以便既有治理承诺继续有效。

## Implementation Decisions

### 1. 路由与页面结构

- 新增受保护路由 `/tools`，与知识库、简历制作等业务页同级，位于应用路由目录下，与既有 `app/<功能>/page.tsx` 约定一致。
- 页面外壳沿用 `AppLayout` 包裹客户端工作区组件，沿用既有业务页的动态导入分包模式（`ssr: false` + 加载态骨架），保持首屏分包收益；工作区组件为客户端组件（需要交互状态与浏览器 API）。
- 页内两个分区并列，垂直排列，各自保留既有板块的卡片标题结构（图标块 + 标题 + 说明文案 + 计数徽标 + 操作按钮）。分区顺序：**Webhook 工具分区在上，MCP 服务分区在下**。
- 现有工具与 MCP 相关组件（板块、卡片、抽屉表单、调用日志抽屉、工具白名单抽屉、模板常量、辅助函数、类型）整体迁至新路由的组件目录，随迁其配套测试文件与导入路径；组件内的相对导入同步更新。
- 现有组件从 `profile-shell` 导入的卡片样式常量（玻璃卡片、抽屉遮罩）与发丝线样式需提取到共享样式常量模块，供个人中心与新工作台共同引用；**严禁**新路由跨目录导入个人中心组件模块，否则会把个人中心主体拉入新页面分包。

### 2. 分区锚点与落位

- 两个分区各自具备稳定的锚点标识：Webhook 工具分区与 MCP 服务分区各有一个。
- 对话页的跳转链接携带对应锚点，落地后页面滚动定位到该分区。
- 因页面采用客户端动态导入，浏览器原生 hash 定位在组件挂载前不会生效，需由工作区组件在挂载后读取当前 hash 并主动定位到目标分区。
- 定位实现须避让移动端固定顶栏（锚点元素预留顶部滚动偏移），滚动动效尊重 `prefers-reduced-motion` 偏好（减弱动态时改为瞬时定位）。

### 3. 应用注册表与全局入口

- 在应用启动台的应用注册表中新增一项：标识符 `tools`、标签「我的工具」、描述「接入 Webhook 与 MCP 服务，扩展智能体能力」、分组归入「专业生产力」、指向 `/tools` 路由，图标使用既有图标库中的工具类图标，配色沿用该分组既有色系。
- 该注册表是启动台、移动端抽屉、移动端顶栏标题、桌面侧边栏置顶的**唯一数据源**，因此注册一次即四处生效，无需分别改造各入口。
- 位置约束：排在同分组内「知识库」之后、「简历制作」之前，使同分组卡片顺序稳定且不置于末位。
- 侧边栏置顶的**默认**列表保持不变，不把新模块强塞进默认置顶项，避免增加侧边栏噪音；用户可自行置顶。
- 应用标识符联合类型需新增对应成员；置顶状态持久化在本地存储中，读取时对未知标识符做过滤，新标识符不影响既有用户的置顶数据。

### 4. 个人中心的收敛

- 个人中心移除两个重量级配置板块，在原「基本信息」板块之后插入一张静态入口卡片：图标块、标题「我的工具」、一句说明文案、跳转箭头，整卡可点击跳转 `/tools`。
- 该卡片为纯静态展示：不展示配置数量、不展示 MCP 或工具统计、不发起任何与工具或 MCP 相关的接口请求，不引入额外的加载态。
- 个人中心其余内容（基本信息、邮箱绑定、对话记忆、安全退出、危险区域、右侧资源消耗侧栏）保持现有布局与行为不变。
- 移除区块后清理个人中心主体中不再使用的导入与状态，避免残留无效依赖。

### 5. 对话页可用工具面板的联动

- 面板中「管理工具」链接指向工具工作台的 Webhook 工具分区锚点；「管理 MCP」链接指向 MCP 服务分区锚点。
- 两个空态引导链接（「前往个人中心添加」「前往个人中心配置」）同样指向对应分区锚点，文案改为指向「我的工具」，去除「个人中心」指代。
- 面板的其余行为不变：工具分组、来源徽标、数量统计、会话级启停开关、审批标识均保持现状。

### 6. 行为保持与不做的事

- Webhook 工具与 MCP 服务的全部业务逻辑、接口契约、错误语义、上限数值（工具 10 个、MCP 服务器 10 个）、审批策略、快照与白名单失效规则、审计与计费口径全部保持不变；本次仅迁移界面位置与入口路径。
- 两个板块的未登录引导态（含「前往登录」跳转）随组件整体迁移到新工作台，个人中心不再承载这两段引导。
- 不引入新的配置接口，不改动任何后端路由与数据模型。
- **Webhook 分区操作按钮热区对齐**：该分区的「刷新」「添加新工具」按钮原为 40px 高（`h-10`），低于项目移动端红线的 44px 触控热区要求，且与同一工作台内 MCP 分区同位置的 44px 按钮（`h-11`）不一致。本次迁移到独立工作台后两个分区同屏并列，该差异在移动端可见，故一并对齐到 `h-11`。此调整只改视觉热区高度，不改按钮行为、接口调用与文案。

### 7. 与既有决策的关系

- ADR-0064 §2 记述的「管理复用个人中心工具管理区」在**界面位置**上被本次迁移取代（管理入口移至独立工作台），但其中关于 MCP 工具发现、快照、白名单、审批策略、不可信内容边界、审计与受控验收服务的全部约束继续有效。本次不新开 ADR（可逆的信息架构重组），迁移关系在本规格中显式记录；若后续 MCP 模块规模显著增长导致需要独立页面，再单独立项。
- ADR-0041 的工具调用前确认协议语义不变，POST 工具默认需确认的说明文案随组件迁移保留。

## Testing Decisions

### 1. 什么算好测试

只断言**产品外部可观察行为**：用户在页面上看到的元素、点击后发生的导航与落位、接口请求是否发生、既有配置能力是否仍可用。不断言组件内部状态、DOM 层级细节、样式类名或实现结构。断言以中文文案、可访问名称、URL 与可见状态为准。

### 2. 接缝选择

沿用项目既有三类接缝，不新增：

- **单元/组件接缝（Vitest + Testing Library）**：工具与 MCP 板块组件测试、对话面板测试、应用启动台注册表测试。
- **浏览器真机接缝（macOS 优先 `ego-browser` 可见窗口，复用已登录会话）**：跨页面跳转与锚点落位、启动台与移动端抽屉入口、个人中心收敛后的真实观感与移动端窄屏表现。
- **集成接缝（中间件/路由层）**：未登录访问受保护路由的跳转行为。

### 3. 被测模块与既有先例

- **工具与 MCP 组件族（9 个既有测试文件）**：Webhook 工具板块、工具卡片、工具抽屉表单、工具新建弹窗、调用日志抽屉、MCP 服务器板块、MCP 工具抽屉，以及工具模板常量与辅助函数。既有先例即这些文件本身，迁移后必须保持全绿——**这是"迁移不损失既有能力"的主证据**。当前基线：迁移前在个人中心组件目录下 10 个测试文件、69 个用例全绿。
- **对话可用工具面板**：既有测试文件已覆盖工具分组与启停，扩展断言跳转目标与空态文案。
- **应用启动台注册表**：新增断言「我的工具」条目存在、分组归属正确、指向 `/tools`、可搜索命中。
- **个人中心**：新增断言个人中心不再包含工具与 MCP 配置列表、包含可跳转的静态入口卡片。
- **中间件**：未登录访问 `/tools` 跳转登录页并携带来源路径。

### 4. 浏览器真机验收覆盖（macOS `ego-browser` 可见窗口）

按宿主工具优先级，本项目 macOS 环境遵循既有铁律先探活 `ego-browser` 并使用可见窗口复用登录态；无 GUI 或探活失败时经说明后按 `docs/agents/qa-workflow.md` 降级。至少覆盖以下主链路：

1. **启动台入口链路**：打开启动台 → 「专业生产力」分组可见「我的工具」卡片 → 点击进入 `/tools`。
2. **对话锚点落位链路**：对话页打开可用工具面板 → 点「管理 MCP」→ 落到 `/tools` 且页面定位在 MCP 服务分区；点「管理工具」→ 定位在 Webhook 工具分区；两个空态引导同样精确落位。
3. **个人中心收敛链路**：打开 `/profile` → 无工具与 MCP 配置列表 → 可见静态「我的工具」入口卡 → 点击到达 `/tools`。
4. **移动端窄屏复核**：390×844 视口下 `/tools` 无横向溢出、顶栏标题正确、抽屉入口可达、两分区可正常操作；顶栏不遮挡锚点落位后的分区标题。

### 5. 真实链路与响应注入的边界

至少一条 `RealLinkSmoke` 走真实登录、真实点击、真实后端（读取用户既有工具与 MCP 配置），只断言本次新产生的用户可见终态。响应注入仅用于构造空状态、失败态等难以在真实环境复现的场景，且必须在用例中标注，不得替代真实链路。证据为带 `AssertionMarker` 的日志与目标区域截图，经 `qa-run` 落盘。

### 6. 不做的测试

- 不做视觉回归快照比对（视觉一致性由浏览器截图人工复核承担）。
- 不对工具与 MCP 的后端业务逻辑做新增单元测试（本次未改动该逻辑，既有覆盖保持全绿即为充分证据）。
- 不测试本地存储中未知应用标识符的迁移细节（仅断言新标识符不影响既有置顶数据，侧边栏置顶的持久化行为由浏览器真机用例复核）。

## Out of Scope

1. 不改动工具与 MCP 的任何后端接口、数据模型、上限数值、审批与审计语义；
2. 不重排个人中心其余内容（基本信息、邮箱绑定、对话记忆、安全退出、危险区域、右侧资源消耗侧栏）的布局与视觉；
3. 不为「我的工具」在应用启动台单开新分组（维持「专业生产力」三组结构）；
4. 不修改侧边栏默认置顶列表，不预置「我的工具」为默认置顶项；
5. 不在个人中心入口卡片上展示配置计数或统计，不为其引入任何配置接口请求；
6. 不新增底部导航项、不调整移动端底部导航构成；
7. 不为旧地址 `/profile` 加锚点或重定向兼容（本次不保留旧锚点路径，迁移期由新入口与对话侧链接覆盖）；
8. 不新增独立 ADR（信息架构重组可逆，按 `docs/agents/domain.md` 准则不滥建 ADR）；
9. 不改动首页推荐卡、命理冷冻相关清理等既有产品收敛成果；
10. 不改动 Webhook 工具与 MCP 服务器的业务逻辑、接口契约、审批与计费口径；仅按第 6 节所述对齐 Webhook 分区操作按钮的触控热区高度；
11. 除本规格直接引入的缺陷外，不改动其他仓库级 QA 流程工具的行为。唯一的例外是 `tooling/scripts/qa-browser-helper.mjs` 的截图裁剪机制：原实现用 `page.screenshot({ clip })` 直接裁剪，而该 clip 的坐标相对文档流，当页面内容滚动发生在自定义滚动容器内时会落到未滚动位置、拍不到目标元素，直接导致本特性的浏览器验收无法产出有效视觉证据（阻断性缺陷）。已改为「先截整视口（正确反映容器滚动后的渲染状态）、再按同一组视口坐标本地裁剪」，非 macOS 平台保留原 clip 行为作为回退；该修复对所有使用该 helper 的特性同样生效。
