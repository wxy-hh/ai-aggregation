> 本规格承接上游规格的 Out of Scope 条目「真实星历/地理编码服务的生产接入」，将其落地。上游规格的流程、数据模型、降级规则、视觉硬约束继续有效；本规格只替换三层数据来源，不改变任何交互与视觉。

## Problem Statement

用户填写真实出生日期、城市、时间后，看到的星盘却不是自己的：当前星座寰宇是纯前端 mock——真值层不读出生资料，只按时间精度返回三份冻结档案之一（换生日结果纹丝不动）；解读层是 12 星座模板文案库拼装；问答层是正则规则引擎。产品的核心承诺「这是我的盘」是假的，一旦被用户察觉（改生日重算结果相同），信任即崩塌。

## Solution

与八字、奇门遁甲完全同构地接入真实能力：星盘真值（本命盘 + 当周行运）由服务端星历库确定性计算，豆包/DeepSeek 只负责把真值翻译成生活语言（流式解读）与星语问答。AI 不得修改事实层。前端消费方（表单、加载仪式、结果页、历史、问答）不动，只切换三个既有异步接缝的实现。

## User Stories

**真实星盘**

1. 作为用户，我希望换不同的出生日期/城市/时间重算，星盘结果真实不同，以便相信这是我的盘。
2. 作为用户，我希望太阳、月亮、行星黄经、逆行、相位、上升、天顶、宫位均由真实星历计算，以便结果经得起与权威星历网站对照。
3. 作为选择「准确到分钟」的用户，我希望按精确时刻出完整本命盘（含宫位与四轴）。
4. 作为选择「大约时段」的用户，我希望系统在时段区间内全量采样校验稳定性，只展示经校验稳定的结论，以便不被虚构精度误导。
5. 作为选择「完全未知」的用户，我希望得到诚实的无宫位降级盘（无上升/宫位/天顶），月亮跨座等不稳定字段明确隐藏，以便用「解锁」视角理解降级。
6. 作为用户，我希望城市按自带经纬度与 IANA 时区参与计算，夏令时按出生当日真实偏移处理，以便时区口径正确。
7. 作为高纬度出生城市的用户，我希望 Placidus 失效时自动回退 Whole Sign 宫位制并被如实告知，而不是拿到错误的宫位。
8. 作为用户，我希望本周提示基于本周真实天象（行运盘与本命盘的实际相位），而非 AI 凭空编造行星位置。

**真实解读**

9. 作为用户，我希望真值一锁定就进入结果页、星盘立即可看，解读文案随后流式浮现，以便等待最短。
10. 作为用户，我希望主轴、大三要素、五个生活模块、本周行动三角、关键相位的文案由 AI 基于我的真实盘面生成，而不是模板拼装。
11. 作为用户，我希望解读严格遵守我的时间精度降级范围，AI 不解读被隐藏的不稳定字段。
12. 作为用户，我希望可以像八字/奇门一样在豆包与 DeepSeek 之间切换模型，默认豆包。
13. 作为用户，我希望加载仪式的四段进度（校准时区/定位行星/绘制宫位相位/AI 整理）对应真实事件，而非纯动画。
14. 作为解读超时或失败的用户，我希望星盘照常保留、文案区显示诚实的失败卡并可一键重试解读（真值不重算），而不是被模板文案静默冒充。

**问答**

15. 作为用户，我希望星语问答由真实 LLM 回答，引用我的盘面事实且不绝对化，每报告最多 3 问。
16. 作为用户，我希望医疗、财务、法律话题被确定性规则前置拦截并给出安全提示与自我观察方向，而不是依赖 AI 自觉。

**额度与身份**

17. 作为匿名用户，我希望不登录就能完成测算（消耗匿名免费额度），登录后经确认迁移临时记录。
18. 作为额度耗尽的用户，我希望星盘真值照常展示（确定性计算近乎零成本），仅 AI 解读区显示锁定卡与登录/充值引导，额度到位后可不重算直接续解读。
19. 作为管理员，我希望沿用既有免预留额度逻辑，不被新路由绕过计费。

**历史、分享与示例**

20. 作为用户，我希望真值完成即写入本地统一历史，解读超时可从同一条记录重试。
21. 作为用户，我希望重算后旧版本仍以修订快照保留（最多 5 份），可对比修改资料前后的结果。
22. 作为用户，我希望分享卡脱敏规则不变（不含出生日期、精确时间、地点、度数）。
23. 作为首次进入的用户，我希望入口示例星盘与真实计算同口径（由真实引擎冻结生成），以便预判最终产物。
24. 作为境外出生用户，我希望表单明确告知本期暂支持中国城市，而不是搜不到时无反馈。

## Implementation Decisions

- **总架构**：与八字/奇门同构——确定性真值本地计算，LLM 只做解读。真值层、解释层、问答层三个既有前端异步接缝换实现，消费方 UI 零改动；不新增前端接缝。
- **真值引擎**：引入 `circular-natal-horoscope-js`（纯 JS，含行星黄经/逆行、Placidus 与 Whole Sign 等 7 种宫位制、ASC/MC、相位与自定义容许度、回归/恒星黄道）。仅服务端使用，其 moment 系依赖不进客户端包。时区不使用库内 tz-lookup 反查，改用城市表自带 IANA 时区 + Node Intl 求出生当日偏移（含 DST）。
- **计算域接缝（上游规格已声明的唯一新接缝，本次换真实实现）**：`computeChartFacts(AstroBirthProfile) → AstrologyChartFacts`，数据模型沿用设计文档 §9.3（planets/angles/houses/aspects/factStability/dataCompleteness/calculationRevision/orbTableVersion）。同域内新增行运计算：以请求时刻所在自然周为窗口按日采样当前天象，筛出与本命星体成主要相位的事实产出 `TransitFact[]`。
- **降级口径**：准确到分钟＝单点完整盘；大约时段＝区间内采样比对，符号/宫位变动即标记不稳定并隐藏及其依赖解读；完全未知＝无宫位无四轴，慢星体取当日位置并标注稳定范围，月亮等快星体做跨座检测。不以中点或 12:00 补算。高纬度 Placidus 失败自动回退 Whole Sign 并在事实层标注。
- **BFF 路由**：新增单个 SSE 报告路由（仿八字 report 模式），事件顺序 `chart-facts → headline → bigThree → modules → transits → complete`，另增「解读暂不可用」事件用于额度降级；新增问答路由（仿 copilot 模式）。奇门式 BullMQ 异步不采用（单次调用可完成）。
- **LLM 调用组织**：单次调用流式，一个报告 JSON schema 边流边按分区顺序解析推送，maxOutputTokens 约 6–8k。复用 destiny 域既有模型客户端（豆包＝火山方舟 Responses + json_schema 强约束；DeepSeek＝chat/completions + json_object 弱约束注入 schema 样例）。请求体带 provider 字段，复用既有模型切换器，默认豆包。
- **解读失败不兜底**：LLM 超时/校验失败 → 真值保留展示 + 文案区诚实失败卡 + 重试解读（真值不重算）。mock 文案库仅作提示词 few-shot 样例与测试金样，永不冒充生产输出。
- **额度与鉴权**：路由内先算真值并推 `chart-facts`，再预留额度；额度不足推「解读暂不可用」事件，文案区锁定卡 + 重试入口。匿名用户与八字一致（免费额度内可测算，耗尽引导登录，登录后迁移临时记录）。解读成功按真实 usage 结算，失败释放预留；记录 AI 用量。
- **问答**：服务端前置确定性敏感话题拦截（医疗/财务/法律，规则迁移自既有 mock 问答的敏感规则），命中直接返回安全提示不过 LLM；其余问题带报告上下文走 LLM，每报告最多 3 问，回答引用盘面事实且不绝对化。
- **mock 处置**：示例盘用既有冻结脚本以真实引擎重新冻结（保证入口示例与真实产出同口径）；解读文案库迁移为提示词样例与测试夹具；敏感话题规则迁移至服务端；删除 mock 延迟工具；不保留 mock 生产开关。
- **历史与分享**：维持 IndexedDB 统一历史与修订快照（最多 5 份）机制不变；设计文档 §9.3 服务端 8 实体落库不在本期。分享脱敏规则不变。
- **城市范围**：维持现网城市表 —— 中国 309 个地级行政区 + 43 条手写 curated 条目（30 个国内主要城市 + 港澳台 + 11 个常用国际城市：东京、首尔、新加坡、伦敦、巴黎、柏林、纽约、洛杉矶、旧金山、温哥华、悉尼），共 352 条，均含经纬度与 IANA 时区；schema 全球就绪，扩全球是未来纯数据工作。表单在搜不到时如实告知该覆盖口径。上游规格 story 19/24 按此实现口径收口。
- **文档同步**：上游 feature.md 的 Out of Scope 条目「真实星历/地理编码服务的生产接入」改写为指向本规格。

## Testing Decisions

- **好测试的标准**：只测外部行为（给定输入的可见输出与状态流转），不测实现细节；确定性逻辑用纯函数单测，路由在模型客户端边界 mock，e2e 只覆盖主链路。
- **被测模块**：
  - 计算域：冻结示例盘（1995-10-08 14:30 上海）用真实引擎重算，先与权威星历来源人工核对一次再冻结为金样；时区与 DST、约时区间稳定性、未知时间月亮跨座降级、高纬 Whole Sign 回退、相位容许度版本化、真值版本稳定性；行运窗口与相位筛选。
  - 报告路由：chart-facts 先行、分区顺序、解读超时只重试解读不重算真值、额度不足时真值照常下发 + 降级事件、usage 结算/失败释放。
  - 问答路由：敏感话题前置拦截命中不过 LLM、3 问上限。
  - 降级可见性/分享脱敏/表单校验：既有测试回归。
- **先行实践**：`api/destiny/_lib/bazi-chart.test.ts`（确定性计算金样）、`api/destiny/report/route.test.ts`（流式路由）、`share/bazi-share-card.test.tsx` 与 `share-card-data.test.ts`（脱敏）、`e2e/home.spec.ts`（Playwright 主链路，更新 `e2e/constellation-universe.spec.ts` 仿此）。
- **验收**：真实 API key 端到端跑一次完整链路（测算→流式解读→问答→重算→历史→分享）；设计文档第 14 章验收清单回归。

## Out of Scope

- 全球城市扩展与地理编码服务接入（现网城市表为中国 309 个地级行政区 + 43 条 curated 条目，含港澳台与 11 个常用国际城市）。
- 设计文档 §9.3 的服务端持久化（8 实体落库、跨设备同步）。
- P1/P2 原有条目不变：宫位地图、完整近期星运（今天/7 天/30 天）、术语百科浮层、双向盘面索引、资料补全提醒、双人合盘与付费逻辑。
- 每日十二星座信息流、塔罗、真人服务市场。
- Swiss Ephemeris 级精度升级（原生模块部署风险，本期不接）。
- 壳层（导航、侧栏、页头）任何改造；视觉与交互的任何变更。

## Further Notes

- 术语沿用设计文档 §16 术语表（本命盘、大三要素、宫位、相位、行运、时间精度）；界面不出现英文占星术语。
- 「黄金主轴样例库」（既有 28 条 mock 主轴）作为提示词 few-shot 样例与内容验收基准，在提示词联调前迁移到位。
- 所有用户可见文本与代码注释使用中文；移动端优先；最小改动，不做 git 提交。
- 生成参数初值：解读 temperature 偏高保文案张力（联调确定），问答偏低保事实忠实；具体值以联调为准，不写死进规格。
