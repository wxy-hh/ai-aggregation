# 多模型聚焦比较对话 — 需求说明书

> Feature: `2026-07-13-multi-model-comparison-chat`
> 级别：标准 L ｜ 风险标签：`money`
> 来源设计：`docs/designs/multi-model-comparison-chat-design.md`
> 设计规范：`DESIGN.md`（玻璃拟态 / 柔光阴影 / 科技蓝-靛青渐变）
> 状态：待需求确认（`requirement_confirmation`）

## 1. 背景与目标

当前 `/chat` 以「选一个 provider 再对话」为主路径，无法体现平台的聚合价值。本需求把核心心智改为：**同一问题多模型并发；先看全局，再聚焦比较；选中更好的答案继续工作。**

成功后的用户认知：

- 平台是「帮我判断哪个模型更适合当前任务」的工作台，而非又一个单模型入口。
- 选 3–4 个模型不会变成拥挤的四列瀑布流。
- 比较、取舍、继续追问都不会丢失各模型自己的上下文。

## 2. v1 范围（已与用户确认）

### 2.1 做（核心闭环 MVP + 持久化）

1. **模式切换**：`/chat` 页头分段控制器「单聊 / 并行对比」，保留现有单聊实现；新建对话默认进入并行对比。
2. **模型选择**：2–4 个模型。模型集 = 讯飞星火（lite / Spark Max / Spark 4.0 Ultra）+ 豆包（Lite / Pro），共 5 个，每个变体算一个独立可选模型。默认组合 = 讯飞 lite + 豆包 lite。
3. **共享问题区**：每轮一条全宽用户 Prompt（不在每个模型列重复显示）。
4. **模型概览轨道**：所有已选模型的状态卡（排队 / 生成中 / 已完成 / 失败 / 已停止 + 耗时 + 是否聚焦 + 替换操作）。
5. **双列聚焦阅读**：默认只展示 2 篇完整回答，每列独立滚动。
6. **焦点替换**：第 3/4 个模型可在不重发请求的前提下替换左/右列。
7. **并发流式**：前端为每个模型独立请求、独立 AbortController、独立流式状态，故障局部化。
8. **分支隔离多轮**：每个模型维护独立上下文；「继续比较」把新 Prompt 追加到各模型自己的分支后再并发。
9. **单模型控制**：单模型停止、重试；错误显示模型名 + 可操作下一步。
10. **持久化**：比较会话按「会话 → 轮次 → 模型分支」结构存入 conversations/history，刷新/跨设备可恢复；历史列表中比较会话以单条记录出现。
11. **设计美化**：遵循 `DESIGN.md`（玻璃拟态 G-2/G-3、柔光阴影 Z 轴、科技蓝-靛青渐变、8px 网格、中文文案）。
12. **移动端自适应**：按设计文档 §7 + 项目移动端优先规范（安全区、44×44 热区、底部抽屉、单主滚动容器）。

### 2.2 不做（v1 延后）

- 差异高亮（diff highlight）
- 3 列阅读
- 全屏模式
- 「拿来继续」单聊子会话
- 「合并为新 Prompt」
- 比较模式附件上传（比较模式 v1 仅文本；单聊保留现有附件能力）
- 一句话差异摘要（避免引入额外模型调用）

## 3. 功能需求

### 3.1 模型清单与选择

| Provider | 变体标签 | model id |
| --- | --- | --- |
| 讯飞星火 | Spark Lite（免费） | `lite` |
| 讯飞星火 | Spark Max | `generalv3.5` |
| 讯飞星火 | Spark 4.0 Ultra | `4.0Ultra` |
| 豆包 | Doubao Lite（轻量级） | `doubao-seed-2-0-lite-260428` |
| 豆包 | Doubao Pro（专业级） | `doubao-seed-2-0-pro-260215` |

约束：最少 2 个、最多 4 个才允许并行对比；可用模型不足 2 个时自动回退单聊并说明原因。模型数量变化不立即发送，必须点「同时发送」。

### 3.2 模式与发送行为

| 模式 | 发送行为 | 结果行为 |
| --- | --- | --- |
| 单聊 | 仅向当前 1 个模型发送 | 现有单列消息流（不改） |
| 并行对比 | 向 2–4 个已选模型并发同一输入 | 模型概览轨道 + 双列聚焦阅读 |

### 3.3 并发与流式状态

状态机：`queued → streaming → completed / failed / stopped`。

| 模型状态 | 概览轨道 | 答案面板 |
| --- | --- | --- |
| 排队中 | 灰色状态点、「等待发送」 | 若被聚焦，显示骨架屏 |
| 生成中 | 蓝色状态点、已用时间 | 实时追加正文 + 流式光标 |
| 已完成 | 绿色状态点、总耗时 | 渲染 Markdown + 完整行为栏 |
| 失败 | 红色状态点、失败原因 | 显示「重试该模型」，不影响其它列 |
| 已停止 | 灰色状态点、「已停止」 | 保留已生成内容，允许重试 |

### 3.4 焦点与替换规则

| 已选模型数 | 概览轨道 | 完整回答区 |
| ---: | --- | --- |
| 2 个 | 两张状态卡均「正在比较」 | 固定双列 |
| 3 个 | 三张卡；两张有选中描边 | 双列，第三张可替换任一列 |
| 4 个 | 四张卡；两张有选中描边 | 双列，另两张各提供替换入口 |

替换不是重新请求，只把对应模型结果放进左/右阅读槽位；被替换模型回到概览轨道，不删除、不取消、不丢结果。目标模型仍在生成时，新列立即显示其当前流式内容。

### 3.5 分支隔离多轮

```text
用户问题 P1
├── 讯飞分支：P1 → A1 → P2 → A2
├── 豆包分支：P1 → B1 → P2 → B2
└── ……
```

- 「继续比较」：新 Prompt 分别追加到各模型自己的分支后再并发发送。
- 绝不允许把一个模型的答案作为另一个模型的隐藏上下文。
- 每个 `ModelRun` 持有自己的 `branchMessages`。

### 3.6 单模型控制

- `重试`：只重发该模型当前轮的分支上下文。
- `停止`：只终止该模型的 AbortController，不影响其它模型。
- 错误提示必须显示模型名 + 可操作下一步，例如「豆包暂时不可用，重试该模型」。

### 3.7 成本可见（money）

- 模型选择器与发送按钮附近展示轻量提示「将同时调用 N 个模型」。
- 重试/停止不得重复扣减；失败或配额耗尽的模型不阻塞其它模型，概览卡显示「不可用」并给原因。

## 4. 数据模型（共享契约）

```ts
type ComparisonMode = 'single' | 'compare';

interface SelectedModel {
  provider: string;          // 'xunfei' | 'doubao'
  model: string;             // 变体 id
  label: string;             // 展示名
}

interface ModelRun {
  modelKey: string;          // `${provider}:${model}`
  status: 'queued' | 'streaming' | 'completed' | 'failed' | 'stopped';
  startedAt?: number;
  completedAt?: number;
  content: string;
  error?: string;
  branchMessages: Array<{ role: 'user' | 'assistant'; content: string }>;
}

interface ComparisonTurn {
  id: string;
  prompt: string;
  runs: Record<string, ModelRun>;
  focusSlots: { left: string; right: string };
}
```

关键约束：`focusSlots` 只影响 UI 呈现，不影响请求、结果缓存或历史存储；每个 `ModelRun` 有独立的加载、错误和取消状态。

### 4.1 持久化契约（v1 新增）

- 现有 `Conversation` 为线性 `messages + provider + model`；比较会话需承载 `turns[]`（每轮含 `runs{}`）。具体扩展方案（扩字段 vs 新增结构）在计划阶段定。
- 比较会话刷新后可恢复：各轮 prompt、各模型分支内容、最终状态、已选模型组合。
- `history-store` 以单条记录呈现比较会话；删除会话时与 history 同步删除（沿用现有 `_isSyncDelete` 机制）。

## 5. 设计规范（DESIGN.md）

- **玻璃拟态**：容器级用 G-2/G-3；长文阅读区用实体高对比背景，严禁玻璃套玻璃、严禁在嘈杂背景上用玻璃。
- **阴影**：柔光 Z 轴多层叠加，忌单一脏黑重影。
- **色彩**：科技蓝 `#3B82F6` / 靛青 `#6366F1` 渐变；智能对话背光 `from-blue-500/20 to-cyan-500/20`、`text-blue-600`。
- **网格**：8px 整数倍；主内容稳定阅读宽度。
- **动效**：`duration-200/300` + `cubic-bezier` 缓动；加载用光晕呼吸 / shimmer，忌死板旋转。
- **文案**：全中文；玻璃背景上满足 WCAG 对比度，必要时 `text-shadow` 描边。

## 6. 响应式与移动端

| 屏幕范围 | 布局策略 |
| --- | --- |
| ≥ 1440px | 默认双列 |
| 1024–1439px | 默认双列，压缩/收起历史栏 |
| < 1024px | 隐藏桌面侧栏，概览轨道横向滚动 |
| < 768px | 完整答案改为模型 Tab / 左右滑动卡片；顶部固定「正在比较 2/4」 |

移动端要求：状态轨道可横滑但焦点模型始终可见；输入区固定在底部安全区上方、发送按钮 ≥ 44×44；切换模型用底部抽屉；长回答只有一个主滚动容器。

## 7. 风险与压力测试结论（money）

- **成本放大**：N 模型并发 = N 次 token 扣减；需成本可见 + 防重复扣减。
- **编排正确性**：分支隔离 / 重试 / 停止 的 bug 会直接浪费用户额度 → 触发 `rollback_units: light` + `behavior_verification: light`。
- **关键正确性**：分支隔离是核心，绝不能串上下文；这是多轮比较最容易出错处。
- **既有依赖**：复用 `/api/chat`（含鉴权、限流、配额、扣减），不新增 provider 接入；doubao 走 Responses API、xunfei 走 chat completions，二者均经 `/api/chat` 输出标准 SSE，前端 `consumeChatResponse` 可复用。
- 说明：设计文档足够详尽、关键范围决策已与用户确认，故以本节压力测试结论替代独立的 grillme 追问轮次（依加速条款），仍停在 `requirement_confirmation` 门禁。

## 8. 验收标准（对应设计文档 §10，已按 v1 收敛）

- [ ] 新建对话默认可见「并行对比」，而非先选单个 Provider。
- [ ] 用户可选 2–4 个模型（含 lite/Max/Ultra、Lite/Pro 变体），一键发送同一 Prompt。
- [ ] 4 个模型同时返回时，页面默认只展示 2 篇完整回答。
- [ ] 第 3、4 个模型可在不重发请求的前提下替换左列或右列。
- [ ] 每个模型都能独立流式、停止、失败、重试。
- [ ] 多轮追问不混用不同模型的上下文（分支隔离）。
- [ ] 比较会话刷新后可恢复各轮与各模型分支（持久化）。
- [ ] 发送按钮附近可见「将同时调用 N 个模型」成本提示。
- [ ] 移动端保持比较能力，但不硬塞双列长文。
- [ ] 所有状态、错误和操作都有中文、可理解的反馈。

## 9. 待计划阶段决策（技术方案，不在需求层定死）

- **比较状态**：新建 `comparison-store` vs 扩展 `chat-store`（倾向新建，职责清晰、不污染单聊）。
- **页面架构**：比较视图作为 `/chat` 内的独立视图组件，由模式分段控制切换；单聊保留现有实现，避免改动 45KB 的现有 page.tsx 核心逻辑。
- **持久化结构**：扩展 `Conversation`（加 `mode` + `turns`）vs 新增 `ComparisonSession` 结构（计划阶段定，需保证与 history 同步删除）。
