## 二、测试用例详细步骤与量化断言

### TC-AUTH-01: 未认证访客访问受保护页面拦截 (P0 - 冒烟阻断)
- **目标**：未认证访客 (Guest) 访问受保护业务路径 `/home`，触发 `LoginWall`，立即重定向到 `/login?redirect=%2Fhome`。
- **前置条件**：浏览器无任何认证 Cookie（清除 `refresh_token`、`auth_kind`）且本地 `localStorage` 无 `ai-app-auth`。
- **视口配置**：桌面视口 (`1280x800`) 与移动视口 (`375x667`)。
- **操作步骤**：
  1. 在浏览器地址栏输入并导航至：`http://localhost:3000/home`
  2. 观察页面跳转与加载过程。
- **自动化友好定位器**：
  - 登录标题：`h1`，包含文案 `"欢迎回到 AI 聚合平台"`
  - 用户名输入框：`input#login-username` 或 `[placeholder="请输入用户名"]`
  - 密码输入框：`input#login-password` 或 `[placeholder="请输入密码"]`
  - 登录提交按钮：`button[type="submit"]`，文案包含 `"登 录"`
- **量化预期断言**：
  - 浏览器当前 URL 变为：`http://localhost:3000/login?redirect=%2Fhome`（或携带等效 URL 编码参数）；
  - 页面在 1 秒内完成跳转并渲染登录表单，整屏 Loading 遮罩存续时间 `< 1.2s`；
  - 浏览器 Console 无未捕获的 Uncaught Exception，Network 面板无任何发往 `/api/auth/anonymous` 的请求。

---

### TC-AUTH-02: 未认证访客访问根路径重定向 (P0 - 冒烟阻断)
- **目标**：未认证访客直接访问网站根路径 `/`，直接重定向至 `/login`。
- **前置条件**：清除浏览器所有认证 Cookie 与 LocalStorage。
- **视口配置**：桌面视口 (`1280x800`)。
- **操作步骤**：
  1. 在浏览器地址栏输入并导航至：`http://localhost:3000/`
  2. 检查网络请求流与落地页面。
- **自动化友好定位器**：
  - 登录主卡片容器：`main form` 或 `button[type="submit"]`
  - 登录页标题：`h1`
- **量化预期断言**：
  - 浏览器当前 URL 立即变为：`http://localhost:3000/login`；
  - HTTP 响应重定向链路清晰（302 Redirect 或客户端即时 Replace），页面最终停留在登录页；
  - Network 面板确认：无设备指纹采集库出站、无 `/api/auth/anonymous` 接口调用。

---

### TC-AUTH-03: 账密登录成功与原路回跳 (P0 - 核心闭环)
- **目标**：未登录用户在携带 `redirect` 参数的登录页成功登录后，精确回跳至原目标路径。
- **前置条件**：数据库中存在合法测试用户（用户名：`test_qa_user`，密码：`Password123!`）；当前处于未登录状态。
- **视口配置**：桌面视口 (`1280x800`)。
- **操作步骤**：
  1. 浏览器导航至：`http://localhost:3000/login?redirect=%2Fdestiny`
  2. 在用户名输入框输入：`test_qa_user`
  3. 在密码输入框输入：`Password123!`
  4. 点击登录提交按钮：`button[type="submit"]`
  5. 观察登录成功反馈与页面跳转目标。
- **自动化友好定位器**：
  - 用户名输入框：`input#login-username`
  - 密码输入框：`input#login-password`
  - 提交按钮：`button[type="submit"]`
  - 命理工作台标志元素：`text="八字命理"` 或 `text="紫微斗数"` 或 `[data-testid="destiny-workspace"]`
- **量化预期断言**：
  - 点击提交后，页面显示成功提示（Toast 提示“登录成功”）；
  - 浏览器 URL 自动原路回跳为：`http://localhost:3000/destiny`；
  - 命理工作台正常渲染，页面顶部栏或头像菜单正常展示用户登录态（非未登录占位）。

---

### TC-AUTH-04: QQ 登录授权入口与交互通畅性 (P0 - 核心第三方通道)
- **目标**：验证登录页第三方快捷登录区域 QQ 登录入口正常工作。
- **前置条件**：处于未登录状态，打开登录页。
- **视口配置**：桌面视口 (`1280x800`) 与移动视口 (`375x667`)。
- **操作步骤**：
  1. 导航至 `http://localhost:3000/login`
  2. 定位第三方登录区域中的 QQ 图标按钮。
  3. 观察图标渲染及提示信息。
  4. 点击 QQ 图标按钮。
- **自动化友好定位器**：
  - QQ 登录按钮：`button[aria-label="使用 QQ 登录"]`
  - QQ 图标：`img[alt="QQ"]`
- **量化预期断言**：
  - `button[aria-label="使用 QQ 登录"]` 可见且可点击；
  - 点击后触发跳转或提示（若已配置 QQ 环境变量，正常跳转至 `/api/auth/oauth/qq` 或弹出授权小窗；若未配置环境变量，Toast 精确提示“QQ 登录未配置，请联系管理员”）；
  - 页面无控制台 JS 抛错。

---

### TC-AUTH-05: 已登录真实用户访问登录页反向回跳 (P1 - 状态互斥守卫)
- **目标**：已登录用户主动访问登录页或注册页时，系统自动反向导流至 `/home`。
- **前置条件**：当前浏览器持有合法登录会话（Cookie 包含 `refresh_token`）。
- **视口配置**：桌面视口 (`1280x800`)。
- **操作步骤**：
  1. 在浏览器地址栏手动输入：`http://localhost:3000/login`
  2. 回车访问并观察重定向结果。
  3. 再次手动输入：`http://localhost:3000/register` 并访问。
- **自动化友好定位器**：
  - 首页工作台标志卡片：`role="heading", text="智能对话"`
  - 侧边栏/顶部栏用户头像或昵称元素
- **量化预期断言**：
  - 访问 `/login` 后，中间件或客户端立即拦截，浏览器 URL 自动变更为 `http://localhost:3000/home`；
  - 访问 `/register` 同样自动重定向至 `http://localhost:3000/home`；
  - 屏幕不展示登录表单，直接展示工作台内容。

---

### TC-AUTH-06: 个人中心无匿名横幅且权限平权开放 (P1 - 业务纯净化)
- **目标**：验证个人中心（`/profile`）完全拔除针对匿名用户的降级横幅，面向已登录用户全面开放所有功能。
- **前置条件**：使用标准用户登录系统。
- **视口配置**：桌面视口 (`1280x800`) 与移动视口 (`375x667`)。
- **操作步骤**：
  1. 导航至：`http://localhost:3000/profile`
  2. 检查个人资料概览区。
  3. 检查自定义工具（Webhook Tools）区域与智能体执行历史（Agent Runs）区域。
  4. 移动端下检查侧边栏折叠与各面板展示。
- **自动化友好定位器**：
  - 用户名编辑入口：`button[aria-label="编辑昵称"]` 或 `text="修改信息"`
  - Webhook 工具管理区域：`text="自定义工具"` 或 `role="heading", text="扩展工具"`
  - 智能体运行记录区域：`text="Agent 运行记录"`
- **量化预期断言**：
  - 页面绝不包含任何文案为“当前为匿名体验账号”、“临时账号建议转正”的提示横幅或 Banner；
  - 自定义 Webhook 工具和 Agent 运行记录模块均处于正常可用状态（不出现“匿名账号不支持此功能”的遮罩或灰色禁用）；
  - 允许点击修改昵称与头像，无任何权限策略阻断。

---

### TC-AUTH-07: 额度耗尽与测算提示文案统一 (P1 - 业务纯净化)
- **目标**：验证全站提示文案已彻底去除面向游客/匿名账号的引导。
- **前置条件**：登录一个 Token 额度为 0 的测试账号。
- **视口配置**：桌面视口 (`1280x800`)。
- **操作步骤**：
  1. 在对话页面尝试发起一次 AI 对话。
  2. 观察触发的额度耗尽对话框（Quota Exhausted Dialog）。
  3. 导航至命理页面 `/destiny`，查看顶部解盘额度说明。
- **自动化友好定位器**：
  - 额度耗尽对话框容器：`role="dialog"`
  - 对话框主标题：`role="heading", text="额度已耗尽"`
  - 查看额度按钮：`button`, 文案为 `"查看我的额度"` 或 `"联系客服/支持"`
- **量化预期断言**：
  - 弹窗正文及提示文案中绝对不包含 `"使用账号密码登录，获得更多额度"`；
  - 弹窗主操作按钮文案为 `"查看我的额度"`（点击导向 `/profile`）或反馈入口，不再提供无意义的“立即登录”按钮；
  - 命理页面额度说明文字为统一的 `"查看我的额度"`。

---

### TC-AUTH-08: 历史旧匿名 Cookie 优雅注销降级 (P2 - 边界安全)
- **目标**：模拟用户携带历史旧匿名 Token 访问站点，验证服务端安全销毁旧会话并重定向。
- **前置条件**：在浏览器 Application -> Cookies 中手动注入旧的测试匿名 Cookie（或伪造已过期 `refresh_token`）。
- **视口配置**：桌面视口 (`1280x800`)。
- **操作步骤**：
  1. 注入 Cookie 后，浏览器直接刷新访问受保护路径：`http://localhost:3000/chat`
  2. 观察网络交互与页面响应。
- **自动化友好定位器**：
  - 登录表单：`input#login-username`
- **量化预期断言**：
  - 客户端向 `/api/auth/refresh` 发起刷新换票时，服务端返回 401 Unauthorized（Response: `{"success":false,"error":"刷新令牌已过期，请重新登录"}`）；
  - 响应头中带有 `Set-Cookie: refresh_token=; Max-Age=0`，旧 Cookie 被安全清除；
  - 页面平滑重定向至 `http://localhost:3000/login?redirect=%2Fchat`，不发生白屏或死循环刷新。
