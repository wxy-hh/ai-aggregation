## Problem Statement

从用户视角，现状有三个真实痛感：

1. **白扣费风险**：奇门分析的某一分块（策略总览 / 时机窗口 / 盘面总结）在模型推理成功、但结果写入存储失败时，用户额度已被扣减，前端看到的却是该分块失败；且受计费防重放熔断保护，任务重试无法自愈，用户既没拿到结果又损失了额度。
2. **扣费口径与其它模块不一致**：Web 端一元路由（语音翻译、简历润色等）遵循「没拿到结果就不收钱」的承诺，而奇门 Worker 走模型成功即扣费的另一套口径，同一平台两套计费语义损害用户对额度账本的信任。
3. **管理员的用量黑盒**：管理员免计费符合预期，但缺少统一归档，个人中心无法看到管理员的奇门用量分项。

## Solution

将奇门 Worker 的配额生命周期收编进全平台统一的一元配额托管管道（ADR-0002 语义），以「用户可见交付完成」为结算前提：

1. 普通用户的每一次奇门分块分析，只有「模型生成 + 结果归一化 + 结果持久化」整体成功才结算扣费；任何一步失败都全额释放预留，用户不为失败的系统故障买单。
2. 管理员维持免预留，但用量按真实 usage 归档，与 Web 一元路由的免预留审计语义一致。
3. 结算规则由共享管道单一持有，奇门 Worker 不再手写预留/结算/释放时序，模型调用模块不再暴露请求阶段钩子。

## User Stories

1. 作为一名普通用户，当我的奇门分块分析因存储故障失败时，我希望我的额度不被扣减，以便我不会为没有拿到的结果付费。
2. 作为一名普通用户，当分块失败后我点击重新生成时，我希望这是一次全新的计费请求（新幂等键），以便我能正常完成分析且不与失败的那次互相干扰。
3. 作为一名普通用户，当我的奇门分析正常完成、三分区全部展示时，我希望扣费金额与实际模型用量一致，以便我的额度账本可信。
4. 作为一名额度不足的用户，当我发起奇门分析时，我希望任务在扣减前就因额度不足被拒绝，以便模型不会被白白调用。
5. 作为一名重复触发同一分析的用户（刷新、重试、重复点击），我希望计费系统凭幂等键识别同一次请求，以便我不会被重复扣费。
6. 作为一名管理员，当我使用奇门分析时，我希望不预扣额度，但我的模型用量仍被记录归档，以便个人中心能看到完整的分项用量。
7. 作为一名对账的运营人员，我希望成功必有 usage、失败必有原因与精确终态标签，以便财务对账与用量审计有确定性依据。
8. 作为一名前端用户，当某分块失败时，我希望看到清晰的分块失败状态（而非整个分析卡死或假成功），以便我知道可以单独重新生成。
9. 作为一名后续维护开发者，我希望新增一类带计费的一元 Worker 任务时只需复用共享管道并给出 run 边界，而不必手写预留/结算/释放样板代码，以便计费规则不会在新任务上漂移。
10. 作为一名排障开发者，我希望模型调用超时、非 200、未知异常三类观测日志仍在（含 analysisId/sectionKey 上下文与耗时），以便生产排障信息不减少。
11. 作为一名平台安全审视者，我希望异步 Worker 不能凭消息载荷中的任意字符串获得免计费特权，以便计费特权不会被伪造。
12. 作为一名并发场景下的用户，当两个相同分块任务同时到达时，我希望已存在结果的一方直接短路返回、不产生任何计费和模型调用，以便资源不被浪费。

## Implementation Decisions

1. **结算边界 = 交付边界**：一元管道的 run 回调边界定义为「模型生成 + 结果归一化 + 结果持久化」整体；整体成功才 finalize('success')，任何一步抛错由管道 finalize('failed') 释放预留并原样重抛。此决策改变奇门 Worker 的现有计费行为：保存失败从「已扣费不可退」变为「不扣费」，依据 ADR-0001「用户没看到结果就不收钱」与 ADR-0002 一元二态语义；代价是平台吸收罕见存储故障下的单次上游模型成本（记入共识，未量化实际故障率）。
2. **共享管道下沉至 db 包的计费模块，Web 端保留 re-export shim**：管道实现与 QuotaSession 同模块放置；4 个现有 Web 一元路由调用方仅各调一行 userRole 两态传参（Decision 5 类型收窄所需，ADR-0049 决策 4），其余零改动。**被推翻项**：ADR-0002 中「置于 apps/web 的 lib/billing」的位置条款（已追加修订附录，语义不变）。被否方案及代价：新建独立 billing 包（30 行函数单建包，过度设计）；放 shared 的 server 子路径（与既有 db→shared 依赖构成包级循环，构建死锁）。
3. **模型调用模块回归纯函数契约**：删除请求阶段钩子（五个），trace 上下文退化为纯数据（analysisId/stage/sectionKey）；分块生成函数改为接收普通输出预算参数、返回「结果 + 用量物料」二元组；输出预算不得超过程序内置上限的收敛逻辑下沉模块内部。**被推翻项**：2026-07 过渡实现的「钩子计费时序」（de facto 约定，无 ADR）。观测日志（请求开始/完成/非 200/超时/未知异常）内聚至模型模块内部，字段、级别、耗时与现状等价。
4. **顺带删除已无调用方的整盘 LLM 排盘入口及其专属 prompt/schema/归一化代码**：盘局已由本地确定性算法排盘，该入口是会产生干支幻觉的废弃过渡路径；全仓核实无生产调用方。
5. **admin 免计费编码采用「协议不变 + 具名纯函数 + 入队断言 + 角色两态」**：BullMQ 任务协议、Redis 盘局结构不变；「计费幂等键缺失 = admin」的推断收敛为具名纯函数，入队端断言非管理员必须携带幂等键（否则拒绝入队）；管道角色参数类型收窄为仅 admin 与缺省两态，Worker 不透传消息载荷中的任意字符串。**被否方案**：任务数据显式增加角色字段（改变任务协议；滚动部署期需双逻辑兼容；特权字符串明文进消息载荷）。
6. **不改变 BullMQ 任务协议、Redis 盘局结构和 QuotaSession 决策表**（审查报告红线）；管道自身语义（两态终态、结算异常隔离、原样重抛、admin 免预留归档）不做任何功能性修改，仅迁移位置。
7. **重复任务短路先于计费**：已存在分块结果时直接返回，不进入管道、不产生计费与模型调用（现状语义保持）。

## Testing Decisions

**好测试的标准**：只断言外部可观察行为——预留/终态的调用与参数、计费结果（扣费/释放/归档）、Redis 状态标记、错误重抛；不断言实现细节（可变 holder、钩子调用顺序、内部日志落点）。

**测试接缝（已在拷问阶段确认，共四个）**：db 计费模块的管道接缝；Worker 分块执行器编排接缝；模型模块的「预算入参 → 结果与用量物料」纯函数接缝；Web shim 的导出兼容接缝。既有接缝复用，不新增。

**落盘与先行艺术**：

- 管道层 7 条用例：随实现下沉至 db 包计费测试目录（先行范本：同目录既有计费会话测试，以 vi.mock 隔离数据库、断言终态调用矩阵）。
- Worker 层 7 条用例：Worker 执行器同级单文件（先行范本：同包既有 Worker 测试，以 mock 隔离 Redis 存储与模型调用）。其中「模型成功但保存失败不扣费」与「非法模型 JSON 不扣费」两条为报告指定的先行红灯用例，必须先写且先红。
- 纯函数三态单测（普通用户 / admin / 缺 userId 抛错）内联于 Worker 测试文件独立 describe。
- Web 端既有 shim 路径测试保留，验证导出无损。
- 完整用例清单（14 条）：管道层＝正常成功生命周期、输出文本缺省兜底、run 异常释放并重抛、成功结算异常隔离、reserve 失败短路、admin 透传与归档、usage 缺失鲁棒；Worker 层＝模型成功但保存失败、非法模型 JSON、模型上游失败、重复任务幂等短路、usage 缺失兼容、管理员全路径、计费上下文解析纯函数三态。

**真实浏览器验收**：触及计费核心链路，阶段 5 不可豁免；P0 冒烟用真实扣费的普通用户账户走完整链路（登录 → 命理工作区奇门分析 → 三分区展示 → 账本可见扣减），不得用 admin 替代（admin 底层免预留，会绕过预留→扣减链路形成假验收）；admin 路径由 Worker 单测全覆盖。用例编号与冻结断言在 `/qa-test-planner` 阶段落盘。

## Out of Scope

- 任何对 BullMQ 任务协议、Redis 盘局结构、QuotaSession 决策表的变更。
- 管道语义本身的功能性修改（仅位置迁移）。
- 「保存失败后 BullMQ 自动重试自愈」能力：受计费防重放熔断保护，同幂等键的终态后重试会被拒绝，此属性在改造前已存在，本规格不扩大也不修复；恢复路径是用户手动重新生成。
- 奇门前端轮询、命理工作区交互的任何改动（本规格无用户可见 UI 变化）。
- 审查报告中的其它候选（C1/C2/C4/C5～C9 及第十节局部修正项）。
- 计费账本、对账表、限额阈值政策的调整。

## Further Notes

- 决策全文与备选方案否决理由见 ADR-0049；ADR-0002 已追加位置修订附录。
- 「模型模块返回形状变化」的影响面已核实：分块生成函数的全仓生产调用方仅奇门 Worker 一处。
- 平台成本口径：保存失败不扣费意味着平台吸收罕见故障下的单次上游成本；该收益按机制描述记入共识，未做故障率量化，不写成已证实收益。
