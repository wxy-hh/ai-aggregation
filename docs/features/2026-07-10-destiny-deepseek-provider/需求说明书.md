# Destiny 多模型（DeepSeek + doubao）接入 需求说明书

- Feature ID: `2026-07-10-destiny-deepseek-provider`
- Level: M（标准 M）
- 创建日期: 2026-07-10
- 需求确认状态: confirmed（见 status.md evidence）

## 1. 背景与目标

`/destiny` 下的八字测算、紫微斗数、奇门遁甲（含 BullMQ Worker）以及报告 copilot 追问，目前全部硬编码走火山方舟 Responses API（doubao 模型）。用户希望在不破坏 doubao 的前提下，新增 DeepSeek 官方模型作为可选提供方，并在三页提供一个共享、可持久记忆的切换入口。

目标：用户在八字/紫微/奇门任意一页选择「doubao」或「DeepSeek」后，该次测算（含奇门 Worker 分块、报告追问）都按所选模型出结果；选择被记住；缺省仍为 doubao，线上旧请求零感知。

## 2. 范围（In / Out）

### In（全量覆盖，已确认）

- REQ-API-1 八字：`apps/web/src/app/api/destiny/report/route.ts`（流式 SSE、分块）。
- REQ-API-2 紫微：`apps/web/src/app/api/destiny/ziwei-report/route.ts`（quick + full 两阶段 JSON）。
- REQ-API-3 奇门：`apps/web/src/app/api/destiny/qimen/analyze/route.ts` + `qimen/analyze/start/route.ts` + `apps/worker/src/workers/qimen-base.ts` / `qimen-section.ts` + `packages/shared/src/qimen-analysis.ts`（Worker 侧独立调 ARK，约 288 / 438 / 1165 行）。
- REQ-API-4 追问：`apps/web/src/app/api/destiny/copilot/route.ts`（流式 SSE）。
- REQ-UI-1 前端 `useDestinyWorkspaceStore` 增加全局 `provider: 'doubao' | 'deepseek'`（默认 `doubao`）+ `setProvider`，三页共享，localStorage 持久化。
- REQ-UI-2 三页共享切换入口组件（移动端优先，热区 ≥44×44），发请求时把 `provider` 放进 body 透传到 API / Worker。
- REQ-USAGE 用量上报 `provider` / `model` 字段从写死 `'doubao'` 改为按实际选择（ziwei-report、report、copilot、qimen 等）。

### Out（本次不做）

- 不重构 `packages/providers/src/deepseek.ts` 工厂（destiny 不走该工厂；DeepSeek 直连由 destiny/shared 专用客户端实现）。
- 不引入 DeepSeek 思考模式（reasoning_content）展示、工具调用、prefix 续写等 beta 能力。
- 不改动 `/chat`、`/resume` 等非 destiny 链路（这些不在本次范围，继续用 doubao/现状）。
- 不调整计费/配额规则（仍按现有 `deductAiQuotaForRoute` / `ANONYMOUS_OPERATION_COSTS`），只修正上报维度。
- 不重命名 `DEEPSEEK_MODEL` 变量（用户决定沿用，承载 DeepSeek 官方 apikey）。

## 3. 关键事实（调研基线）

- 当前 destiny 全部 `fetch(${ARK_BASE_URL}/responses)`，body = `{ model: ARK_DESTINY_MODEL, input, max_output_tokens, reasoning:{effort}, text:{ format: json_schema|json_object } }`，鉴权 `ARK_API_KEY`。模型默认 `doubao-seed-2-1-pro-260628`。
- 通用解析：`apps/web/src/app/api/destiny/_lib/ark-response.ts` 解析方舟 `output[].content[].text` / `output_text`；`mapArkError` 在四文件各一份（report:743、ziwei-report:684、qimen/analyze:828、shared/qimen-analysis:1165）。
- 奇门配置入口：`packages/shared/src/qimen-analysis.ts:438 resolveArkConfig(env)` 读 `ARK_API_KEY` / `ARK_BASE_URL`，web 与 worker 共用。
- 前端 store：`apps/web/src/stores/destiny-workspace-store.ts`（Zustand，当前无持久化）。
- 环境变量：`apps/web/.env.local:38 DEEPSEEK_MODEL="sk-12adaec53ba…"`（DeepSeek 官方 apikey）。`DEEPSEEK_API_KEY`（25 行）为 providers 工厂预留空值，本任务**不使用**。

## 4. 功能需求

- REQ-F1 请求体新增可选 `provider: 'doubao' | 'deepseek'`，各 route 的 Zod schema 用 `.default('doubao')` 保证向后兼容（旧客户端不传 = doubao）。
- REQ-F2 服务端按 `provider` 选择上游协议与凭据：
  - doubao → ARK Responses（现状不变）。
  - deepseek → `POST https://api.deepseek.com/v1/chat/completions`，`Authorization: Bearer ${DEEPSEEK_MODEL}`，`model: deepseek-v4-flash`。
- REQ-F3 结构化输出：doubao 继续 `json_schema`；deepseek 用 `response_format: { type: 'json_object' }` 并在 system/user prompt 含 `json` 字样与结构样例；解析沿用 `parseModelJson` / `extractJsonBlock` 兜底，空 content / `length` 截断要返回可识别错误或按既定 fallback 处理。
- REQ-F4 流式：report / copilot / qimen（若有）按 provider 解析不同帧（ARK `response.output_text.delta` / DeepSeek `delta.content`），对外帧协议（`text-delta` / `done` / `error`）保持不变，前端零改动。
- REQ-F5 奇门 Worker：`provider` 随 job payload 透传；`resolveArkConfig` 扩展为按 provider 解析配置（建议更名/新增 `resolveModelConfig(provider, env)`），Worker 用同一份抽象。
- REQ-F6 前端：三页共享一个切换入口，选择写入 store + localStorage；发请求带 `provider`；切换不丢失已填表单。
- REQ-F7 用量上报 `provider`/`model` 反映真实选择；缺失 `DEEPSEEK_MODEL` 时 deepseek 路径返回清晰 500（`模型未配置`），不泄露 key 值。

## 5. 非功能需求

- 兼容：默认 doubao；不传 `provider` 的旧请求行为完全一致。
- 安全：不硬编码任何 key；错误信息不回显 `DEEPSEEK_MODEL`/`ARK_API_KEY`。
- 验证：`automated-tests: none`，以 `pnpm typecheck` + `pnpm lint` 为静态门禁，dev server 手动验证三测算 × 两 provider + 奇门 Worker + copilot 为行为门禁。
- 中文：UI 文案、错误信息、注释、文档全中文。
- mobile-first：切换入口在小屏可用、热区 ≥44×44、不依赖 hover。

## 6. 已确认决策（HUMAN GATE:requirement_confirmation）

1. 接入路线：DeepSeek 官方直连 `deepseek-v4-flash`，key 用 `DEEPSEEK_MODEL`（官方 sk- 值）。
2. 覆盖：八字 + 紫微 + 奇门（含 Worker）+ copilot 追问（全量）。
3. 切换入口：三页共享全局开关 + localStorage 持久化，默认 doubao。
4. JSON：DeepSeek 用 `json_object`（弱约束）+ 客户端兜底。

## 7. 验收标准（行为）

- AC1 默认（不传 provider）：八字/紫微/奇门/copilot 与改动前完全一致走 doubao。
- AC2 选 DeepSeek：八字流式报告、紫微 quick+full、奇门 base+三块（Worker）、copilot 追问均走 DeepSeek 官方接口并正确渲染；用量上报 `provider=deepseek`、`model=deepseek-v4-flash`。
- AC3 切换记忆：刷新页面后上次选择仍在；三页共用同一选择。
- AC4 DeepSeek JSON 弱约束下若返回非法/空 JSON，前端显示可识别错误而非崩溃；doubao 不受影响。
- AC5 缺少 `DEEPSEEK_MODEL` 时 DeepSeek 路径返回明确中文 500，且响应体不出现 key 字符串。
