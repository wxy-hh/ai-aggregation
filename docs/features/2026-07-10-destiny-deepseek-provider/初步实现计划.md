# Destiny 多模型（DeepSeek + doubao）实现计划

> **使用说明：** 按 `Depends on` 执行。每步用 `- [ ]` 跟踪。本计划只列任务清单，实现任务的 Todo/进行中状态只在 `implementation_approval.status == confirmed` 后创建。

**目标：** 让八字 / 紫微 / 奇门（含 Worker）/ copilot 追问在保留 doubao 的同时新增 DeepSeek 官方模型可选，前端三页共享一个可持久记忆的切换入口。

**技术方案：** 在 `packages/shared` 新增一个**服务端模型调用抽象层**（`destiny-model-client.ts`），把「doubao = 火山方舟 Responses」「deepseek = 官方 Chat Completions」两套协议封装成统一的 `callModel`（非流式）/ `streamModel`（流式）/ `resolveModelConfig` / `mapModelError`，web 各 route 与 worker 共用。请求体新增 `provider`（默认 `doubao`）一路透传到 Worker job payload；前端 store 增加全局 `provider` 并 localStorage 持久化，切换入口组件放到三页共享头部。JSON 对 doubao 用 `json_schema`、对 DeepSeek 用 `json_object` + 抽象层注入结构样例 + 现有 `parseModelJson`/`extractJsonBlock` 兜底。

**架构选型决策（plan-review MEDIUM-3）：** destiny 现以「裸 fetch + 自解析 SSE + json_schema」走 ARK Responses，与 `packages/providers` 的 ai-sdk/OpenAI 契约不兼容——`ChatCompletionOptions` 不承载 json_schema/reasoning/timeout，且 `factory.ts` 仅注册 xunfei/doubao、`packages/providers/src/deepseek.ts` 仍 `Not implemented`；复用需扩展 `AIProvider` 契约并影响 `chat-store`，改动面更大。故抽象放 `packages/shared`（web 与 worker 共同依赖），保留 destiny 现有调用方式、最小改动，新增 deepseek 分支。`packages/providers/deepseek.ts` 本任务不实现（属 OUT-1）。

**技术栈：** Next.js 15 Route Handlers、BullMQ Worker、`packages/shared`、Zustand（含 persist）、Zod、DeepSeek Chat Completions、火山方舟 Responses API。

## 输入资产

- OpenSpec：无（`living_baseline: false`）

## 全局约束

- 默认 doubao；`provider` 缺省 = `doubao`，旧客户端零感知。
- 不硬编码 key；错误信息不回显 `DEEPSEEK_MODEL` / `ARK_API_KEY`。
- DeepSeek 仅 `response_format: { type: 'json_object' }`；prompt 必须含 `json` 字样 + 结构样例；空 content / `finish_reason=='length'` 走兜底。
- 流式对外帧协议（`text-delta` / `done` / `error`）保持现状，前端解析零改动。
- 中文注释与文案；`automated-tests: none`，以 `pnpm typecheck` + `pnpm lint` + dev server 手测为证据。
- 用量上报 `provider` / `model` 改动态，禁止再写死 `'doubao'`。

- [ ] **Step 1: 实现配置解析与错误类型**

```ts
const DEEPSEEK_BASE_URL = 'https://api.deepseek.com/v1';
const DEEPSEEK_DEFAULT_MODEL = 'deepseek-v4-flash';
const ARK_DEFAULT_BASE = 'https://ark.cn-beijing.volces.com/api/v3';
const ARK_DEFAULT_MODEL = 'doubao-seed-2-1-pro-260628';

export class ModelConfigError extends Error {
  status = 500 as const;
  constructor(message: string) { super(message); this.name = 'ModelConfigError'; }
}
export class ModelUpstreamError extends Error {
  constructor(message: string, public status: number) { super(message); this.name = 'ModelUpstreamError'; }
}

export function resolveModelConfig(
  provider: DestinyProvider,
  env: NodeJS.ProcessEnv = process.env
): ModelConfig {
  if (provider === 'deepseek') {
    const apiKey = env.DEEPSEEK_MODEL; // 注意：DEEPSEEK_MODEL 承载 DeepSeek 官方 apikey
    if (!apiKey) throw new ModelConfigError('DeepSeek 模型未配置（缺少 DEEPSEEK_MODEL）');
    return { provider, baseUrl: DEEPSEEK_BASE_URL, apiKey, model: DEEPSEEK_DEFAULT_MODEL, protocol: 'deepseek-chat' };
  }
  const apiKey = env.ARK_API_KEY;
  if (!apiKey) throw new ModelConfigError('doubao 模型未配置（缺少 ARK_API_KEY）');
  return {
    provider: 'doubao',
    baseUrl: env.ARK_BASE_URL || ARK_DEFAULT_BASE,
    apiKey,
    model: env.ARK_DESTINY_MODEL || ARK_DEFAULT_MODEL,
    protocol: 'ark-responses',
  };
}
```

export function mapModelError(status: number): string {
  if (status === 401) return '模型鉴权失败，请联系管理员检查密钥';
  if (status === 402) return '模型账户余额不足';
  if (status === 429) return '请求过于频繁，请稍后重试';
  if (status >= 500) return '模型服务暂时不可用，请稍后重试';
  return '模型调用失败，请稍后重试';
}
// normalizeModelUsage：ARK 取 usage.prompt_tokens 等；DeepSeek 取 usage.prompt_tokens 同名字段；统一映射到 {promptTokens,completionTokens,totalTokens}。

## 风险点与依赖项

- **协议差异**：DeepSeek 仅 `json_object`（弱约束），紫微 quick/full 与八字分块依赖结构化 JSON；必须在 prompt 加 `json` 字样 + 结构样例，并依赖现有 `parseModelJson`/`extractJsonBlock` 兜底。DeepSeek 思考模式默认开启，只取 `content`、丢弃 `reasoning_content`。
- **Worker/Web 版本一致**：奇门 `provider` 经 job payload 透传，web 与 worker 必须同版本部署；部署顺序建议先 worker 后 web（worker 兼容缺省 `?? 'doubao'`，可独立先上）。
- **环境变量**：`DEEPSEEK_MODEL` 承载 DeepSeek 官方 apikey（与 `packages/providers` 预留的 `DEEPSEEK_API_KEY` 不同，本任务不用后者）；CI/生产需同步配置，缺失时 DeepSeek 路径返回中文 500。
- **流式对外帧不变**：report / copilot 前端解析零改动，依赖 `streamModel` 正确归一 ARK/DeepSeek 两种 SSE；需在 Task 1 充分覆盖 `[DONE]`、`include_usage` 末帧、`: keep-alive` 注释。
- **用量/配额**：配额扣减逻辑不变，仅上报维度改动态；避免误把 DeepSeek 上报成 doubao 影响成本核算。
- **TypeScript** 跨包：`packages/shared` 新增导出需被 web 与 worker 同时解析，注意 `exports`/路径别名与构建（`pnpm build` 验证 shared 出包）。
