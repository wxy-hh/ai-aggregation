## 未逐步浏览器验证项与原因

1. **真实模型计费链路**（场景 1 真实生成、16 copilot 发送）：涉及真实 API 配额消耗，改由代码审查 + 单测覆盖执行边界（prepareExecution/commitExecution 时机）。
2. **移动端真机窄屏**（场景 2、REQ-014 安全区/抽屉）：无真机，响应式与安全区由 Tailwind 断点 + 审查确认；建议后续真机抽查。
3. **实时录音中状态**（场景 13）与**报告流式生成中状态**（场景 17）：需特定运行时态，禁用逻辑由代码审查确认。

> 结论：核心跨模块链路（发起→跳转→接收→预填→不覆盖→移除→失效→来源删除→刷新恢复）已在真实浏览器逐项验证通过；涉及计费/真机/特定生成态的 4 个场景（2/13/17 及部分 16）以代码审查 + 单元测试覆盖，记录为已知验证边界，不阻塞验收。
