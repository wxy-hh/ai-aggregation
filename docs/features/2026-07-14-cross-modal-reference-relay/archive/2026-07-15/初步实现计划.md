## 1. 总体架构

```text
发起（来源模块）                接力核心（新增）                    承接（目标模块）
├─ chat ActionButtons  ─┐   ┌──────────────────────────────┐   ┌─ chat ChatInput 预填
├─ image 结果工具栏     ─┤   │ types/relay.ts (shared)      │   ├─ image Prompt 预填
├─ voice 复制/导出行    ─┼──▶│ relay-store (Zustand+Dexie)  │──▶├─ video 描述/参考图
├─ video 预览工具栏     ─┤   │ target-registry + adapters   │   ├─ destiny 待解读→术数选择
└─ destiny 报告段落     ─┘   │ destiny-capabilities         │   └─ history 派生元数据
                              │ components/relay/* (5 组件)   │
                              └──────────────────────────────┘
        URL 跳转仅携带 ?relayId=<id>；快照正文/媒体地址存 Dexie，不进 URL
```

数据流：来源模块调 `relay-store.createBundle(item, targetModule)` → `router.push('/<target>?relayId=<id>')` → 目标页 `relay-store` 按 `relayId` 恢复 → `ReferenceBar` 展示快照 + 确定性适配器生成草稿 → 用户点原有主操作按钮才执行 → 成功后记录派生关系并清除活动引用。

## 4. 决策点（需用户在实现确认门禁拍板）

- **D1（已解决 — 测试基建）**：经审查核实，项目**已配置 Vitest 4 + Playwright**（`project-workflow.md` 现为 `automated_tests: present` / `webapp_testing: enabled`），原「是否引入最小化 Vitest」决策点撤销。默认：接力纯函数（`target-registry`/`adapters`/`destiny-capabilities`）用 Vitest 单测，L 级关键路径用 Playwright 浏览器验证，`pnpm test`/`pnpm test:e2e` 纳入 T13 验证矩阵。
- **D2（右键菜单实现）**：不新增 `@radix-ui/react-context-menu` 依赖，改为在 `contextmenu` 事件复用 `RelayMenu` 浮层（与显式按钮同一菜单）。符合「右键只能复用同一菜单」要求且零新依赖。
- **D3（视频历史接线范围）**：REQ-013 要求视频落历史，但视频模块当前**完全无历史落库**。本计划把「视频生成成功 → 写 video 历史」纳入 T11。如需缩小范围可只加类型不落库，但会与 REQ-013「历史页增加视频筛选/统计/卡片」冲突，**默认纳入**。
- **D4（对比模式派生记录范围 — 新增）**：REQ-016 要求成功记派生，但对比模式记派生需在 `comparison-store.ts` 发送成功处加 hook，触及红线 4。
  - 推荐（A）：v1 在对比发送成功处加**单一附加 hook** 记录派生（`createComparisonHistoryItem` 已存在），改动小且满足 REQ-016；红线 4「不重构对比内核」本意是避免大改，附加 hook 不违背。
  - 备选（B）：v1 对比模式只**发起**接力、不记录派生，派生记录留 v2；与 REQ-016 有缺口，需用户接受。
  - **默认推荐 A**。
- **D5（刷新后草稿恢复粒度 — 新增）**：REQ-004「刷新可恢复」。ChatInput/ComparisonInput 草稿均为组件本地 `useState`，只持久化 bundle 时刷新会丢用户已编辑的草稿。
  - 推荐（A）：relay-store 增 `draftByTarget: Record<RelayModule, string>`，编辑时同步、刷新后恢复，完整满足 REQ-004（已据此修订 T2）。
  - 备选（B）：v1 刷新只恢复引用（bundle），草稿由适配器确定性重生成（刷新前手工编辑丢失），记为 accepted limitation。
  - **默认推荐 A**（成本可控、体验正确）。
- **D6（RTASR active:false=已确认 语义依赖 — 新增）**：实时接力以 `active:false` 判「已确认」，当前代码成立，但 hook 丢弃了网关 `isEnd` 终态信号；若未来网关支持旧 segId 纠错，该解释失效，快照可能含变化中文本。**处置**：v1 维持 `active:false` 判定，在 T8 注释标注语义依赖与风险，不阻塞。

## 5. 风险与不变量（实现红线）

1. **不得自动产生模型费用**：页面跳转、引用恢复、草稿写入、编辑阶段**严禁**触发任何 `/api/*` 模型调用；只有用户点原有主操作按钮（发送/立即生成/生成视频/起局/顾问发送）才执行。这是最高优先级不变量，每个模块接入都要在手动验证中专项核对。
2. **草稿不被静默覆盖**：目标字段已有内容时，只显示引用条 + 「填入…」显式操作，绝不自动覆盖。
3. **来源失效仍可用**：快照存 Dexie，来源删除后快照继续可用、隐藏「查看来源」。
4. **不改无关模块**：不重构各模块无关状态与页面结构；不改动正在开发的并行对比核心逻辑（接力只通过 `focus-answer-pane` 操作区增量接入）。
5. **单引用上限**：协议 `items[]` 是集合，界面/Store 用 `MAX_RELAY_ITEMS=1` 限制；替换需确认且不删草稿。
6. **中文一致性**：所有新文案/注释中文；改动文件的既有英文注释同步翻译。

## 6. 不做范围（与需求 §2.2 一致）

工作流画布/连线/批量/自动触发；多引用同时进入；永久素材篮/标签/文件夹；调用模型优化接力内容；命理自动推荐术数；视频自动抽帧/转图片；文本转语音/配音；独立埋点基建（仅预留事件调用边界）。
