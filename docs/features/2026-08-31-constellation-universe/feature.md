> 本文档是设计文档的可执行规格化整理，不替代设计文档；流程、数据、计算边界、隐私与安全以设计文档为最高优先级。

## Problem Statement

星座/占星类内容有海量轻度用户，但平台现有的八字、紫微、奇门三个命理模块都以传统术数语言呈现，入门门槛高。用户想要一个低门槛的现代占星入口：先看到"这和我有什么关系"的结论，再按需深入专业盘面；同时担心资料不全（不知道出生时间）会得到错误结果，也担心出生资料这类高敏感数据被泄露。

## Solution

在 AI 命理大师中新增第四个同级模块「星座寰宇」：以阳历出生日期、出生城市、可选出生时间为输入，先做确定性星盘真值计算，再由 AI 把真值翻译成生活语言。结果页首屏只聚焦一个核心结论（一句主轴 + 大三要素 + 交互星盘轮），出生时间未知时进入诚实的无宫位降级，分享默认脱敏。视觉上以深色沉浸星空为主打，让用户从入口页看到成品星盘的第一眼就产生兴趣。

## User Stories

**入口与首页**

1. 作为桌面端用户，我希望在命理大师侧栏看到与八字、紫微、奇门同规格的第四项「星座寰宇」，以便不学习术数差异就能找到入口。
2. 作为移动端用户，我希望顶部四段式切换增加「星座」项且四项等宽，以便单手切换模块。
3. 作为首次进入的用户，我希望在填写任何信息前先看到一枚成品级示例星盘，以便预判最终产物的价值。
4. 作为用户，我希望主按钮「开始绘制我的星盘」是入口页唯一主操作且足够醒目，以便 3 秒内理解价值并开始。
5. 作为用户，我希望看到「星体位置为计算结果，解读由 AI 生成」和「用于自我探索与娱乐参考」的说明，以便建立正确预期。
6. 作为不知道出生时间的用户，我希望在入口就看到「不知道出生时间也可以继续」，以便不因资料不全而放弃。
7. 作为有历史记录的用户，我希望入口页出现最近一次报告的低敏摘要卡（不含生日、城市、精确时间与度数），以便一键回到上次结果。

**两步表单**

8. 作为用户，我希望表单只有两步而非长表单，以便降低填写阻力。
9. 作为用户，我希望昵称可选且有占位示例，以便不提供真实姓名也能获得个性化称呼。
10. 作为用户，我希望日期选择器默认阳历并明确「现代占星以阳历生日计算」，以便填对历法。
11. 作为用户，我希望可选单选关注主题（认识自己/感情关系/事业方向/近期状态），以便报告按我关心的主题排序而不改变盘面。
12. 作为用户，我希望表单底部写明出生资料的用途与删除路径，以便放心填写高敏感信息。
13. 作为用户，我希望填完日期后立即看到「你的太阳星座：天秤座」预览条，以便获得即时确定反馈。
14. 作为用户，我希望填写过程中右侧（移动端为表单上方）的预览星盘在填完日期后让太阳节点动画滑到我的真实星座位置，以便产生「这已经是我的盘」的占有感。
15. 作为用户，我希望时间精度只有「准确到分钟/大约时段/完全未知」三档，以便不被更多选项困扰。
16. 作为选择准确到分钟的用户，我希望时、分选择器旁有一只小型可视化钟面即时反馈，且不默认任何推测时刻。
17. 作为选择大约时段的用户，我希望选择可计算的时间区间，并看到琥珀色温和徽章说明仅展示经稳定性校验的结论。
18. 作为选择完全未知的用户，我希望看到「本次可看到/补充时间后可解锁」的双列说明卡和无宫位行星环，以便用「解锁」视角理解降级而非「失去」。
19. 作为用户，我希望城市搜索支持全球城市且必须精确选中（保存经纬度与 IANA 时区），以便计算口径正确。
20. 作为用户，我希望看到「{城市} · {IANA 时区} · {YYYY 年当地时间}」的可读确认，以便校验时区换算。
21. 作为用户，我希望校验错误只在对应字段下以柔和玫瑰红边框 + 一行中文修正说明反馈，以便在安静的页面里修正。
22. 作为用户，我希望测算期间会改变计算事实的字段被禁用但已填信息保留，以便不担心数据丢失。

**加载与转场**

23. 作为用户，我希望加载页用四段真实进度（校准时区/定位行星/绘制宫位相位/AI 整理）替代百分比，以便理解系统在做什么。
24. 作为用户，我希望前三段文案主语是「系统」、第四段才是「AI」，以便区分确定计算与生成内容。
25. 作为用户，我希望动画有 2.5–4 秒最小仪式窗：算得快则平滑快进播完，算得慢则停在真实阶段等待，以便仪式感与诚实兼得。
26. 作为计算失败的用户，我希望看到安静的恢复卡（资料已保留 + 失败类型 + 重新计算/返回修改），以便从容重试。
27. 作为用户，我希望加载完成的星盘连续放大、位移并落定为首屏星盘轮（共享元素转场），以便感受「绘制完成即升入报告」的连续性。
28. 作为用户，我希望真值一锁定就进入结果页、主轴与模块文案流式浮现，以便等待时间最短。

**结果页**

29. 作为用户，我希望结果页顶部是宇宙护照头（昵称、资料摘要、时间精度标签、盘面依据入口），以便确认报告属于我并可校验输入。
30. 作为用户，我希望最先读到一句 18–28 字、有个人张力的主轴，以便被一个结论击中并记住。
31. 作为时间准确的用户，我希望看到太阳、月亮、上升三张大三要素卡（术语层/白话层/行为层/依据层）。
32. 作为时间未知的用户，我希望标题切换为「核心要素」且只展示稳定要素，并有独立「资料范围」提示说明已隐藏内容，以便不被虚构结果误导。
33. 作为用户，我希望星盘轮是首屏视觉主角（直径 520px 以上），以便获得品类独有的视觉震撼。
34. 作为桌面端用户，我希望悬停或键盘聚焦星体时节点放大并浮出中文名 tooltip，以便不认符号也知道在看什么。
35. 作为用户，我希望点选星体后该节点光圈扩散、相关相位提亮、其余降至 55% 透明度，右侧（移动端为底部）出现白话先行的事实卡，以便建立盘面与结论的联系。
36. 作为读屏用户，我希望星盘轮有等价文本清单（白话条目默认、术语列表折叠为「查看全部」），以便不依赖图形。
37. 作为用户，我希望五个生活模块（我是谁/关系/事业/优势与盲点/本周提示）默认正文不超过 120 字并配短标签，以便快速扫读。
38. 作为用户，我希望每个模块可「展开依据」查看对应的已确认星体、星座、宫位或相位事实，以便结果经得起细看。
39. 作为用户，我希望本周行动三角固定输出机会/留意/行动并含日期范围与依据行运，以便把星象翻译成本周可执行安排。
40. 作为用户，我希望深度区 P0 只有「星盘轮」和「关键相位」两个页内标签，以便不在多层页面里迷路。
41. 作为时间未知的用户，我希望深度区用清晰提示卡说明「补充出生时间后可解锁什么」并提供重算入口，而不是置灰假装可用。

**问答、历史与分享**

42. 作为用户，我希望报告完成后可就结果追问（每报告最多 3 问），回答引用盘面事实且不绝对化。
43. 作为用户，我希望触及医疗、财务、法律话题时得到明确的安全提示与自我观察方向，而不是确定性预测。
44. 作为用户，我希望真值完成时结果即写入统一历史记录（标题「星座寰宇 · {昵称}的本命星盘」），解读超时可从同一条记录重试。
45. 作为匿名用户，我希望先完成测算、登录后经确认再迁移临时记录，以便不在填写前被阻断。
46. 作为用户，我希望分享卡是海报级竖版 3:4（深空底 + 星盘缩略 + 主轴大字），以便发出去有面子。
47. 作为用户，我希望分享前在预览浮层里选择「显示昵称/匿名」「显示大三要素/仅主轴」并实时预览，以便掌控隐私暴露面。
48. 作为用户，我希望分享卡默认不含出生日期、精确时间、地点、度数，时间未知时不显示上升，以便社交分享不泄露精确出生时空。

**视觉与可访问性**

49. 作为用户，我希望深色主题下内容区是深空渐变 + 星图的全出血沉浸背景（壳层导航不动），以便获得「午夜观测台」的惊艳感。
50. 作为浅色主题用户，我希望星盘线条保持足够对比度、绝不消融为背景底纹。
51. 作为移动端用户，我希望星盘轮默认在屏宽内完整可见（约 340pt、热区 ≥44pt）、点选聚焦出底部事实卡，以便小屏也有一眼完整的震撼。
52. 作为开启减少动态的用户，我希望所有动效退化为静态/交叉淡入，以便舒适使用。

## Implementation Decisions

- **模块划分**：导航与路由（tab=astrology 第四项）、astrology 工作区状态、两步表单组件、占星计算域（独立服务）、BFF API 与流式协议、结果组件、分享卡、星语问答、设计资产。复用现有壳层：`left-nav.tsx`、`destiny-shell.tsx`、`destiny-result-header.tsx`；星语问答桌面端面板复用 `ai-copilot-panel` 形态、移动端复用既有底部抽屉（`ai-copilot-drawer` 模式）。
- **唯一新接缝——计算域真值接口**：`computeChartFacts(AstroBirthProfile) → AstrologyChartFacts`。全部 UI 消费此接口；前端先行期以符合设计文档 §9.3 数据模型的 mock 真值层实现（含固定虚拟档案「1995-10-08 14:30 上海」冻结的示例盘），未来真实星历服务落地只换实现、不动 UI。表单预览的太阳位置由前端按阳历日期确定性计算，不依赖该接缝。
- **AI 解读不开新接缝**：沿用既有 destiny BFF 流式路由模式，协议顺序为 `chart-facts` → `headline` → `bigThree` → `modules` → `transits` → `complete`；真值锁定即转场进结果页，文案流式浮现。
- **数据模型**：按设计文档 §9.3 的 8 个实体（AstroBirthProfile / AstrologyChartFacts / PlanetPlacement / AspectFact / TransitFact / AstrologyReport / HistoryRecord / QuestionAnswer+ShareSnapshot），事实层与解释层分离存储，AI 不得修改事实层；修订版本化，重算不原地覆盖，删除级联。
- **降级规则**：三档时间精度决定可见模块；约时与未知均执行全区间稳定性校验，不稳定字段及其依赖解读一律隐藏，不以中点或 12:00 补算；无宫位结果不预留占位、不置灰。
- **视觉硬约束（违反即返工）**：壳层逐像素复用；信息架构不增删字段；视觉不虚构数据；正文 ≥14px、热区 ≥44×44、安全区适配、尊重减少动态、星盘轮等价文本。内容区允许全出血沉浸背景；深色主打、浅色达标；主按钮 52–56px；主轴字级 clamp(40px, 4vw, 56px)；星盘轮为首屏视觉主角（≥520px）与主轴构成「上句下盘」。
- **交互规范**：加载四阶段由真实事件驱动 + 2.5–4s 最小仪式窗；加载→结果共享元素转场（约 500ms，减少动态时交叉淡入）；表单步骤横滑约 250ms；星盘轮轮上仅符号与度数，hover/focus 出中文 tooltip，点选开事实卡；分享为海报预览浮层内嵌脱敏选项。
- **分享卡**：P0 即海报级竖版 3:4；默认脱敏；时间未知/约时不稳定时不显示上升；重算后旧分享资产与链接立即失效。
- **各页面视觉方向**：以设计文档 12 段「效果提示词」为已认可方向，实现方在硬约束内自由提升，不设像素级交付稿。

## Testing Decisions

- **好测试的标准**：只测外部行为（给定输入的可见输出与状态流转），不测实现细节；确定性逻辑用纯函数单测，UI 用组件测试验证渲染与交互结果，端到端只覆盖主链路。
- **被测模块**：
  - 计算域（mock 先行，接口不变）：时区与夏令时、DST 不存在/重复时刻、约时区间稳定性、未知时间月亮跨座降级、高纬 Whole Sign 回退、相位容许度版本化、真值版本稳定性。
  - BFF 流式协议：chart-facts 先行、分区顺序、解读超时只重试解读不重算真值。
  - 降级可见性：未知时间不出现上升/宫位/天顶及依赖文案；不稳定字段不渲染。
  - 分享与历史脱敏：分享卡不含出生时空字段、历史列表低敏、删除级联撤销分享令牌。
  - 表单：两步骨架、三档精度互斥、城市必须精确选中、未来日期拦截。
- **先行实践**：`api/destiny/_lib/bazi-chart.test.ts`（确定性计算金样）、`api/destiny/report/route.test.ts`（流式路由）、`share/bazi-share-card.test.tsx` 与 `share-card-data.test.ts`（分享卡数据与脱敏）、`visualization/chart-center-panel.test.tsx`（可视化组件）、`e2e/home.spec.ts`（Playwright 主链路，新增星座寰宇 e2e 仿此）。
- **验收基线**：设计文档第 14 章验收清单逐条核对。

## Out of Scope

- P1：宫位地图、完整近期星运（今天/7 天/30 天）、术语百科浮层、双向盘面索引与复杂动效、资料补全提醒。
- P2：双人关系合盘、双方资料授权与付费逻辑。
- 不纳入路线：每日十二星座信息流、塔罗、真人服务市场。
- ~~真实星历/地理编码服务的生产接入~~ 已由后续规格承接：见 `docs/features/2026-09-19-constellation-real-api/feature.md`（真值计算 + LLM 解读 + 问答三层真实化）。
- 系统导航、命理侧栏、页头等壳层的任何改造。
