# /chat Agent 工具 · 二期：多步自主循环 — 规格说明书

> 日期：2026-10-02 ｜ 状态：**已完成**（真机验收 6/6 通过，见文末「验收结果」）
> 前置文档：一期规格 `docs/features/2026-10-01-chat-agent-tools/spec.md`（D1–D11、§5.1 事件契约、§12 二期规划）
> 本规格的九项决策全部经 `grilling` 拷问逐项确认（Q1–Q9），非单方拟定。

---

## Problem Statement

一期 agent 模式是「单轮工具调用」：决策步 → 执行一轮工具 → 总结步，然后结束。用户提出需要多来源信息的问题（「对比一下 A 和 B 的最新情况」「先查查这个再帮我分析」）时，agent 只能抓一个网页或出一张图就必须收尾——查到了新线索也无法追查，答案深度被锁死在单轮。

同时，一期遗留四笔已确认的债：附件入口放开但输入被静默丢弃（能选图、传不进去）；`ReserveFeature` 未从 `AiUsageFeature` 派生导致加一个值改 5 个文件；静默覆盖 provider/model 未在结算 metadata 留痕；合规检查点 2 的 spec 语义与实现分叉。

## Solution

把 agent 编排从「两段式」升级为**有界多步自主循环**：模型决策 → 执行工具 → 带着结果再决策 → … → 收尾步强制产出最终回答。循环有硬边界（步数、工具次数、时间预算三重封顶），有退化保护（重复调用去重、连败熔断），过程全程可见（旁白+工具调用进过程卡片），最终回答保持干净。计费沿用「一次预留、一次结算」的一口价模式，账本零改动；低余额用户自动降级为少步模式而非被拒绝。

## User Stories

1. 作为用户，我希望 agent 能围绕一个问题连续多轮查证（查→追查→综合），以便得到需要多来源信息的完整回答。
2. 作为用户，我希望在过程卡片里看到每一轮的想法（旁白）和工具调用，以便理解 agent 正在做什么。
3. 作为用户，我希望最终回答干净，不夹杂「我查一下」这类过程前言。
4. 作为用户，我希望循环有明确上限，agent 不会无限跑下去消耗我的额度。
5. 作为用户，我希望单次请求在可预期的时间内（约 4 分钟内）必然结束。
6. 作为低余额用户，我希望余额不足以满配步数时仍能使用 agent（自动降为少步），而不是直接被拒绝。
7. 作为余额极低的用户，我希望得到明确的额度不足提示，而不是静默失败。
8. 作为用户，我希望模型用相同参数重复调同一个工具时不会白白重跑，避免浪费我的额度与时间。
9. 作为用户，我希望工具连续失败时 agent 尽早基于已有信息收尾，而不是把步数耗尽在一串报错上。
10. 作为用户，我希望一次对话的出图张数有上限，避免异常等待与异常内容刷屏。
11. 作为用户，我希望循环中途可以按停止，已产出的正文与图片保留、按部分成功计费。
12. 作为用户，我希望历史记录里能看到当时完整的工具调用过程（一期的持久化能力在多步下继续成立）。
13. 作为用户，当回答因长度被截断时，我希望看到明确提示（延续一期 B-3 行为）。
14. 作为用户，当工具结果命中合规策略时，我希望被拦截并如实告知（延续一期检查点 2）。
15. 作为平台运营，我希望一次 agent 请求只冻结一笔预留、只结算一次，账单可对账、feature 单列。
16. 作为平台运营，我希望预留额度按实际可用步数冻结，余额不足自动缩步，不多冻、不错扣。
17. 作为平台运营，我希望出图成本有硬顶（每请求 3 张），防止一口价模式被刷穿。
18. 作为平台运营，我希望被静默覆盖的 provider/model 记入结算 metadata，审计可追溯。
19. 作为开发者，我希望新增计费 feature 时不再改动 5 个文件（ReserveFeature 单源派生）。
20. 作为用户，agent 模式下我不应看到「能选图却传不进去」的附件入口。

## Implementation Decisions

### D-二期-1：范围（Q1）

二期 = **多步自主循环** + 四笔顺手债（见 D-二期-9）。webhook 工具、会话服务端化+长期记忆、MCP 均不在本期；原规划中 webhook 的「SSRF 专项」前提修正为「密钥存储/注册表/写语义/审计四子系统」，需求未验证前不立项。

### D-二期-2：计费模型（Q2，正式推翻一期 D1 前置）

- 维持**一次 reserve + 一次 finalize**，账本（reserve→finalize 配对结构）零改动；「一对多结算」不再是任何前置。
- 预留额 = `单步输出上限(2048) × 实际步数`，输入估算沿用现有一次性口径；输入放大效应（第 k 步重发累积上下文）暂由冻结冗余吸收，按实测水位校准时再决定是否加系数。
- finalize 汇总全部 N 步 usage（累加器与漏步告警机制一期已具备；漏步仍只记录告警、按少计费方向处理，不补估算兜底）。
- feature 继续单列 `chat-agent`，定价数据连续。

### D-二期-3：低余额自适应降级（Q4）

- reserve 前做一次余额预检，计算 `affordableSteps = clamp(⌊可负担输出 / 2048⌋, 0, 5)`。
- ≥2：按该步数运行（预留同步缩小），**静默降级**，用户获得与一期等价的完整体验。
- <2：拒绝，返回额度不足提示。
- 预检是建议性的，reserve 仍是权威校验（竞态安全）。

### D-二期-4：循环边界（Q3）

| 边界 | 值 | 说明 |
|---|---|---|
| maxSteps | **5** | 最多 4 轮「决策→工具」+ 1 次收尾步；收尾步**不挂 tools**，强制产出文本，终止由编排器保证 |
| 每轮工具上限 | 3（不变） | 一次决策最多执行 3 个工具 |
| 全局工具上限 | **10 / 请求** | 超限后模型只能走收尾 |
| 时间预算 | **240s / 整个请求** | 一期常量语义从「单轮」改为「整请求」；耗尽即跳收尾步优雅降级 |

### D-二期-5：循环退化保护（Q5）

- **重复调用去重**：以「工具名 + 参数稳定序列化」为 key；第 2 次相同调用起**不执行**，返回首次缓存结果，并在注入模型的结果里附软提示（「该调用已执行过，结果同前，请基于现有信息作答或调整参数」）。
- **连败熔断**：连续 **3** 次工具结果为错误 → 立即跳出循环进收尾步。

### D-二期-6：事件契约与前端呈现（Q6）

- **新增契约事件 `agent_note`（过程旁白）**：中间轮决策文本以该事件下发，渲染进过程卡片，**不进正文**；最终回答 = 收尾步正文。此条修订一期「决策前言进正文」行为（单轮下同）。客户端对未知事件本就显式忽略，前后向兼容。
- `tool_call` / `tool_result` 成对有序语义不变（含「tool_result 先于总结步正文」）。
- 过程卡片：**扁平时间线**累积全部轮次的旁白+工具对，不按轮次分组嵌套。
- **折叠时机改为「收尾步正文开始流出」**；循环期间卡片保持展开（多轮下旧信号会放大成秒级折叠-展开循环）。
- 旁白属过程性内容，**不入历史持久化**；工具调用记录的持久化沿用一期 B-10 结构，无需变更。
- **取舍说明**：旁白路由要求决策步文本整步缓冲、步末按路由一次性下发；因此无工具调用的直答路径同样失去逐 token 流式观感（首字节延迟变为整步生成时长）。这是旁白路由的固有代价，评审确认保留、不改码。

### D-二期-7：出图工具专项上限（Q7）

- `image_generate` **每请求硬上限 3 张**（对齐一期单轮实际上限；出图在一口价内不单独计费，是真实资金敞口）。
- 超限调用走一期同款 skip 机制：不执行、推成对事件、给模型「本次对话出图次数已用完」的结果。
- `web_fetch` 不设专项上限（单轮 3 + 全局 10 + 240s 三层约束已足够）。

### D-二期-8：编排器结构

- 主循环：决策（streamText + tools，每轮 stepCountIs(1)）→ 工具顺序执行（不变）→ 工具结果回注 → 再决策 → … → 收尾步（无 tools）。
- 继续走 Chat Completions 路径（一期已实测 Responses 路径回传消息会 400）。
- 三态判定（success/partial/failed）口径不变：「有产出」= 正文或工具成功交付的产物任一存在；中断/异常按 hasOutput 判 partial/failed（对齐 ADR-0001）。
- 截断提示（finishReason==='length' → warning 事件）对收尾步继续生效。

### D-二期-9：顺手债四项（Q8）

| 债 | 处置 |
|---|---|
| 附件入口与输入不一致 | **关闭入口**：agent 模式下不显示附件按钮（一行前端条件）；「支持附件」未来独立立项（涉及视觉能力实测、图片合规机制、多模态计费口径） |
| `ReserveFeature` 未派生 | 改为从 `AiUsageFeature` 单源派生，消除 5 处散弹式修改 |
| 覆盖行为未留痕 | finalize metadata 补记被覆盖的原始 provider/model |
| 合规检查点 2 spec 语义 | **改 spec**：`image_generate` prompt 命中合规时「直接失败」即正确行为，一期 spec 措辞（替换话术）作废 |

### 明确不进本期（Q8）

- 推理流透传（spec §5.6 预留通道）：展示设计有独立验收面，单独排期。
- 并行工具执行：多步落地后收益降低，且扰动折叠信号。

## Testing Decisions

**接缝策略：不新增接缝，全部沿用一期既有最高接缝。**

1. **主接缝 = HTTP 处理器 → SSE 事件流**（一期 `chat-handler.agent.test.ts` 模式：mock AI SDK `streamText` 的 fake result）。编排器的全部新行为都通过该接缝观察外部可见契约：
   - 循环终止：maxSteps 打满后产出收尾步文本，不再出现第 6 次模型调用；
   - 边界三件套：第 4 个工具/第 11 个全局工具被推「未执行」成对事件；
   - 去重：相同参数第 2 次调用不重跑（下游 spy 计数），模型上下文含软提示；
   - 熔断：连续 3 次工具失败后直接收尾；
   - 出图上限：第 4 次 `image_generate` 被拒且模型如实告知；
   - `agent_note`：中间轮文本以旁白事件下发、正文无前言；
   - 降级：低余额时 reserve 调用参数中 maxOutputTokens 按缩减步数传入。
2. **计费断言遵守 ADR-0003**：路由测试只断言 `reserve` 参数与 `finalize(outcome, ctx)`（空壳 session + finalize spy + 共享工厂）；QuotaSession 决策表行为仍单源测试于 `packages/db` 既有测试，**禁止复刻决策表**。
3. **前端测试**沿用既有先例：chat-store 事件处理（`agent_note` → 进 trace、不进正文、不入历史）、过程卡片组件的折叠时机。
4. **好测试的标准**：只断言外部行为（SSE 事件序列、reserve/finalize 参数、store 状态、组件渲染），不断言循环内部计数器等实现细节。整轮 240s 预算路径用缩短预算注入验证，不打真实时钟。
5. `ReserveFeature` 派生是类型层改动，`typecheck` 即验证。

**真机验收判据（三层收口）**

- 门禁：typecheck / lint / test 全绿（命令须 `env -u NODE_OPTIONS` 前缀）。
- 真机清单（ego-browser）：多步链路（≥2 轮循环后收尾）、旁白进卡片且正文干净、循环中停止（产出保留 + partial 计费）、低余额静默降级、诱导第 4 张图被拒、计费核对（finalize 总额 = 各步 usage 之和、feature=chat-agent）。
- 文档回写：一期 spec 的 D1（前置作废）、§5.1（`agent_note`）、§5.4（计费公式）、§12.1（完成标记）、合规检查点 2 语义、B-1 常量语义（单轮→整请求）。

## 验收结果（2026-10-02 真机收口，全部通过）

**门禁**：全仓 `pnpm typecheck` / `pnpm lint` / `pnpm test` 全绿（web 1121 用例、db 58、shared 12 等，5/5 turbo 任务）。

**真机六项（ego-browser + 本地 dev server）**：

| # | 场景 | 结果 | 证据 |
|---|---|---|---|
| 1 | 多步链路 | ✅ | 「抓 example.com → 依主题出图」跑出 2 轮「决策→工具」循环后收尾，第 2 轮决策依赖第 1 轮抓取结果 |
| 2 | 旁白进卡片、正文干净 | ✅ | 中间轮文本以旁白行进卡片时间线；最终正文无「我查一下」类前言；卡片在收尾正文流出后才折叠 |
| 3 | 循环中停止 | ✅ | 出图执行中点停止：消息标「已停止」、过程卡片保留（web_fetch 成功记录 + image_generate 归一为失败）；计费 settle 2209 / release 8077（仅收已完成轮次） |
| 4 | 低余额静默降级 | ✅ | available=7000 → reserve `outputLimit=6144`（2048×3 步，静默降级），功能完整；available=2000 → <2 步直接拒绝，弹窗「文本或语音额度不足」，拒绝发生在 reserve 之前、账本零变动 |
| 5 | 第 4 张图被拒 | ✅ | 一次请求 4 张图：单轮 3 上限拦下第 4 张，模型次轮回补又撞每请求 3 张上限；最终回答如实告知「出图次数已用完（上限 3 次）」，实际渲染 3 张图 |
| 6 | 计费核对 | ✅ | reserve 10308 = settle 3546 + release 6762；feature=`chat-agent`；`ai_usage_records` 与前端展示值一致（usage 逐轮累加）；预留无泄漏（reserved=0）；`metadata` 含 `overriddenProvider/overriddenModel`（顺手债 #3 留痕生效） |

**顺手附带验证**：agent 模式下附件入口真实隐藏（可用钮与置灰钮均不渲染）；全失败场景（上游断连）整笔预留全额退还。

**遗留观察（非阻塞，记入交接文档）**：模型会把部分实质回答写进中间轮决策文本（路由进旁白而非正文），最终回答因此可能偏薄——属模型行为与系统提示词调优空间，非路由缺陷。

## Out of Scope

- 用户自定义 webhook 工具（密钥存储/注册表/写语义/审计四子系统未建，需求未验证）
- 会话服务端化 + 跨会话长期记忆（独立立项）
- MCP 接入（等 webhook 安全模型跑通）
- 推理流（reasoning-delta）透传与展示
- 并行工具执行
- agent 附件输入支持（本期只关闭入口）
- 账本一对多结算改造、按步计费（一次预留+汇总结算已足够）

## Further Notes

- **环境坑沿用**：一切 pnpm/vitest/tsc/eslint 命令加 `env -u NODE_OPTIONS`；匿名身份由 localStorage `ai-device-id`（64 位十六进制）决定；`ai_usage_records."createdAt"` 是 naive UTC。
- **Agnes 出图实测 10.7–13.9s**，出图工具 40s 预算不变；多步循环里混出图时注意 240s 整请求预算的水位。
- **工具不得自查 `ctx.signal.aborted`**（一期边界约定）：取消/超时区分统一在 tool-policy。
- **工单拆分**（拷问 Q9 确认，交 to-tickets 落到 `.scratch/`，不进仓库）：
  01 契约先行（`agent_note` + spec 回写）→ 02 编排器多步循环（骨架+边界+去重+熔断+出图上限）→ 03 计费自适应降级（与 02 串行）｜ 04 前端呈现（旁白渲染+折叠时机+关附件入口，与 02/03 可并行）｜ 05 顺手债三项（独立小包）→ 06 测试补齐+真机验收+文档回写（等 02–05）。
