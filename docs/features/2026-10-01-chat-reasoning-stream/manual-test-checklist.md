## 联调过程中的附带发现（不阻塞发版，建议后续处理）

1. **单聊无停止按钮（既有遗留）**：`chat-input.tsx` 中 `const stop = useChatStore((s) => s.stop)` 已解构但从未调用（死代码）；发送按钮 isLoading 态仅显示转圈且禁用。spec §6「推理中用户停止」在单聊 UI 无直接入口，当前唯一用户可操作路径是点击侧边栏 compare 会话触发 stop()。建议单独立项：发送中按钮切换为「停止」。
2. **流式中切 tab 丢消息（既有竞态，非本 feature 回归）**：单聊流式中切「并行对比」tab（switchMode）**不**触发 stop()；后台流随后被组件卸载 abort，切回单聊时 `loadConversation` 用 conversations-store 旧快照覆盖 chat-store，导致该轮回复（含已流出的推理/正文）整体丢失且不可恢复（实测「从 1 加到 100」案例，仅用户消息留存）。改动前正文流同样存在此竞态，非思考流改造引入。建议：switchMode 切走前先 stop() 并等待 finalize 落盘，或 loadConversation 与后台流互斥。
3. 额度弹窗一次性出现：匿名账号在多路中断流预留额度叠加时触发「额度不足」，预留结算释放后自动恢复，非代码问题。
