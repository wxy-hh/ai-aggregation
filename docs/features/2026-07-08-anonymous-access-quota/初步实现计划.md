# 初步实现计划：匿名访问 + 设备指纹 + 额度限制

## Feature ID

`2026-07-08-anonymous-access-quota`

## 总体策略

1. 数据库侧：在 `User` 表增加 `isAnonymous` 字段，区分真实用户与匿名用户。
2. 客户端侧：使用 `@fingerprintjs/fingerprintjs` 采集浏览器指纹，生成 `deviceId`，并持久化到 `localStorage`。
3. 认证侧：新增 `/api/auth/anonymous` 接口，根据 `deviceId` 查找或创建匿名用户并签发 JWT。
4. 守卫侧：改造 `middleware.ts` 不再强制重定向；改造 `auth-store` 在初始化时优先走匿名认证；`requireAuth()` 保持不变。
5. 额度侧：新增 `checkAndDeductTokens(userId, tokensToDeduct)` 工具函数，使用 Prisma 原子更新防止超扣。
6. UI 侧：新增额度耗尽弹框组件，监听 `QUOTA_EXHAUSTED` 错误码。

## 详细步骤

### Step 1：数据库迁移

1. 修改 `packages/db/prisma/schema.prisma`：
   - 在 `User` 模型增加 `isAnonymous Boolean @default(false)`。
   - （可选）为匿名用户增加 `deviceHash String? @unique` 字段，用于通过设备哈希快速查找匿名用户。
2. 运行 `pnpm db:generate` 和 `pnpm db:migrate`。
3. 确认迁移脚本仅新增字段，不改现有真实用户数据。

### Step 2：额度工具函数

新建 `packages/db/src/quota.ts`：

```typescript
/**
 * 检查并扣减用户额度。
 * @returns 扣减后的余额；余额不足返回 null。
 */
export async function checkAndDeductTokens(
  userId: string,
  amount: number
): Promise<number | null> {
  // 先查询当前余额
  const user = await prisma.user.findUnique({
    where: { id: userId },
    select: { tokens: true, isAnonymous: true },
  });

  if (!user) return null;
  if (!user.isAnonymous) return user.tokens; // 真实用户不扣减
  if (user.tokens < amount) return null;

  // 原子扣减
  const updated = await prisma.user.updateMany({
    where: { id: userId, tokens: { gte: amount } },
    data: { tokens: { decrement: amount } },
  });

  if (updated.count === 0) return null;

  const next = await prisma.user.findUnique({
    where: { id: userId },
    select: { tokens: true },
  });

  return next?.tokens ?? null;
}
```

### Step 3：设备指纹采集

新建 `apps/web/src/lib/device-fingerprint.ts`：

- 使用 `@fingerprintjs/fingerprintjs` 生成浏览器指纹。
- 将指纹与服务端环境变量 `ANONYMOUS_DEVICE_SALT` 组合，使用 SHA-256 生成 `deviceId`。
- 优先从 `localStorage` 读取 `ai-device-id`；不存在时生成并写入。
- 暴露 `getDeviceId(): Promise<string>`。

### Step 4：匿名认证接口

新建 `apps/web/src/app/api/auth/anonymous/route.ts`：

- POST 接收 `{ deviceId: string }`。
- 验证 `deviceId` 格式（必须是 64 位十六进制字符串）。
- 根据 `deviceHash = deviceId` 查找 `User`。
- 找到则签发 JWT；未找到则创建匿名用户并签发 JWT。
- 设置 `refresh_token` cookie（与现有登录保持一致，方便 `requireAuth()` 和 `refresh` 复用）。
- 返回 `{ user, accessToken }`。

### Step 5：改造认证 Store

修改 `apps/web/src/stores/auth-store.ts`：

- `initialize()` 逻辑调整：
  1. 先尝试 `refreshAccessToken()`（兼容已登录真实用户）。
  2. 若失败，调用 `getDeviceId()` 获取 `deviceId`。
  3. 调用 `authApi.anonymous(deviceId)` 获取匿名 token 和用户信息。
  4. 写入 store 的 `accessToken`、`user`、`isAuthenticated = true`。
- 新增 `anonymousSignIn(deviceId)` action。
- `logout()` 对匿名用户额外清除 `localStorage` 中的 `ai-device-id`。

### Step 6：改造中间件

修改 `apps/web/src/middleware.ts`：

- 移除“未登录用户访问受保护页面重定向到登录页”的逻辑。
- `PUBLIC_PATHS` 增加 `/home` 或 `/chat` 等页面（或直接允许所有页面访问）。
- 保留已登录用户访问 `/login`、`/register` 等页面重定向到 `/home` 的逻辑。
- API 路由保持公开，由 handler 内部 `requireAuth()` 处理。

### Step 7：AI 路由额度校验

对每个 AI 调用入口（如 `apps/web/src/app/api/chat/route.ts`、`apps/web/src/app/api/image/route.ts` 等）：

1. 在 `requireAuth(req)` 后获取 `userId`。
2. 根据请求预估本次调用最大 token 消耗（对话可预估输入+输出上限，图像/视频固定扣除额度）。
3. 调用 `checkAndDeductTokens(userId, amount)`。
4. 若返回 `null`，返回 JSON `{ error: '额度已用完', code: 'QUOTA_EXHAUSTED' }`，HTTP 402 或 403。
5. 若成功，继续调用下游 AI 服务。
6. 实际调用完成后，根据真实消耗写入 `AIUsageRecord`（已由现有逻辑完成）。

> 注意：图像/视频等按任务计费的场景，由于调用前无法精确知道 token，先按固定额度预扣；任务完成后根据实际用量写入 usage 记录，但不退还。本需求简化处理：图像/视频按固定值 1 次任务扣减固定 token（如 100 token）。

### Step 8：额度耗尽弹框

新建 `apps/web/src/components/quota-exhausted-dialog.tsx`：

- 使用 shadcn/ui `Dialog`。
- 文案："您的免费额度已用完，可以继续查看历史记录，但无法发起新的 AI 调用。"
- 提供"我知道了"按钮关闭。
- 在 `layout` 或相关页面挂载，监听全局错误事件或直接在 API 错误处理中打开。

### Step 9：API 客户端错误处理

修改 `apps/web/src/lib/api/client.ts`：

- 当响应体包含 `code === 'QUOTA_EXHAUSTED'` 时，触发全局事件（如 `window.dispatchEvent(new CustomEvent('quota-exhausted'))`）。
- 弹框组件监听该事件。

### Step 10：验证

1. `pnpm db:generate`
2. `pnpm db:migrate`（本地数据库）
3. `pnpm typecheck`
4. `pnpm lint`
5. `pnpm build`
6. `pnpm dev` 启动后手动验证：
   - 无痕窗口首次访问获得 3000 额度
   - 多次刷新额度不变
   - 发起对话后额度扣减
   - 额度耗尽后弹框且无法发起新调用
   - 仍可查看历史
   - 真实登录用户流程不受影响

## 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 设备 ID 被伪造 | 仅做基础防刷；服务端对 `deviceId` 加盐哈希；不依赖其做强安全决策。 |
| 并发扣减超扣 | 使用 `updateMany` 原子条件更新 + 失败重试。 |
| 匿名用户数据难以迁移 | `isAnonymous` 字段标记；后续升级可设置 `passwordHash` 和 `username`。 |
| 中间件移除后页面暴露 | API 路由仍由 `requireAuth()` 守卫；页面本身无敏感数据。 |
| 指纹库加载失败 | 降级为随机 UUID + localStorage，保证可用性。 |
