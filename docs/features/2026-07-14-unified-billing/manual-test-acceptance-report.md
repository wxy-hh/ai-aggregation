- **P1（需求符合性）**：T-09 —— 批量预留"弹性缩减 outputLimit"与清单"整批失败"预期冲突，需产品确认以哪个为准；M-04 —— 媒体成功次数实为提交次数，异步失败不回滚。

## 复核与整改记录

### 复核结论

- T-03、T-04、T-10 的原始失败预期与 RULE-08 冲突：Provider 已可能开始执行但没有可审计真实 usage 时，不能按文本估算结算，也不能直接退款。此类请求保持 `billing_pending`，等待自动或人工对账，才符合“按实际用量扣费”。
- M-01、M-03 的 `billableUnits=1` 是图片/视频的成功任务计数，不是文本/语音额度扣款；文本/语音账户四个数不变时即符合媒体任务隔离规则。
- T-09 已按最终产品决定修正为：余额不足以覆盖所有模型的完整配置输出上限时，调用前统一返回额度不足，不再弹性缩短输出上限后启动。

### 已实施修复

1. 多模型比较改为按全部模型的“输入 Token + 配置输出上限”原子预留；不足即统一返回 `QUOTA_INSUFFICIENT`，不调用任一 Provider。
2. 视频提交仅保存供应商任务 ID 并保持本地任务为处理中；轮询到供应商 `SUCCESS` 后才写一次 `video_task`，轮询到 `FAIL` 则标记本地任务失败且不写成功次数。
3. 简历诊断和润色捕获 `BillingError` 后统一返回 402 与错误码；本地开发环境默认将简历 LLM 超时窗口调整为 30 秒，生产默认仍为 8 秒，可由 `RESUME_AI_TIMEOUT_MS` 覆盖。
