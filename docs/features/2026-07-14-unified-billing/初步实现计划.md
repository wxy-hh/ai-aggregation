# 统一额度计费与用量结算改造实施计划

> 执行进度（2026-07-14）：Task 1 至 Task 9 已完成。所有 AI 调用入口（含命理流式与异步 Worker）已接入统一账本；三份 Prisma 迁移已应用到本地测试数据库；自动对账已接入 Worker。

> **使用说明：** 按照 `Depends on` 依赖关系执行。每步使用 checkbox (`- [ ]`) 语法跟踪进度。本计划只覆盖计费、额度、用量统计和相关接口；不重构无关业务。

**目标：** 让匿名用户与注册用户共用同一套实际用量计费链路，文本/语音功能按供应商实际用量结算，图片/视频独立按任务次数统计，并保证流式对话、多模型并发、失败退款和历史迁移可审计。

**技术方案：** 新增额度账户、预留记录和追加式额度流水，替代路由内直接修改 `users.tokens` 的方式。文本/语音请求使用“预留 → 供应商调用 → 实际结算 → 释放差额”，图片/视频写入独立任务次数；`AIUsageRecord` 只保存供应商事实，不再作为余额来源。

**技术栈：** Next.js 15 Route Handler、Prisma 6、PostgreSQL、TypeScript、Vitest、Zustand、SSE。

## 全局约束

- 匿名用户和注册用户只允许有一套扣费实现；用户类型只影响初始额度，不能影响实际结算规则。
- 管理员继续免计费，但所有管理员请求仍可写入用量统计，便于运营分析。
- 业务路由不得直接调用 `deductTokens`、`checkAndDeductTokens` 或自行修改 `users.tokens`。
- `users.tokens` 在迁移期作为兼容余额快照，统一账本上线后只能由额度服务同步更新。
- 文本/语音额度单位使用内部整数 `quotaUnits`；首版默认供应商实际 Token 与 `quotaUnits` 按 1:1 结算，保留供应商/模型倍率字段以支持后续成本换算。
- 图片和视频不扣减文本/语音 `quotaUnits`，只记录 `taskCount`；本次不新增图片/视频次数上限。
- 所有扣费操作必须以 `requestId` 幂等；同一个请求不能重复预留、结算或退款。
- 所有新增注释、错误消息、UI 文案和文档使用中文。
- 预留必须在参数校验、限流检查和业务权限检查之后执行，避免非法请求消耗额度。

```ts

```

结算规则：

- 实际用量小于预留：扣实际值并释放差额。
- 实际用量等于预留：全部结算。
- 供应商调用失败且没有实际用量：释放全部预留。
- 流式部分成功：按最终实际 usage 结算已消耗部分。
- 重复结算同一 `requestId`：返回已有结算结果，不重复扣费。

处理顺序固定为：

1. 获取用户并完成参数、限流和请求次数校验。

- 外层 `catch` 不能作为唯一退款入口，流式异步回调也必须结算。
- 供应商 fetch 需要接收客户端取消信号，避免用户停止后上游仍无限生成。

- [ ] 将讯飞、豆包和 AI SDK 的流式 usage 统一传给计费服务。
- [ ] 设置最大输出限制，避免实际输出超过预留额度。

- 达到额度上限时返回 `QUOTA_LIMIT_REACHED`。
- 客户端主动中止不会重复结算。
- 多模型批量预留失败时不启动任何模型。
- 同一 `requestId` 重复结算只产生一笔扣费。
- 图片/视频只记录任务次数，不修改文本额度。
- 匿名和注册用户走同一计费服务。
- 历史 9413 Token 不会在迁移时再次扣费。

**Rollback idea:** 测试文件和手动验证文档可独立回退；不得为了测试通过而放宽负余额、重复扣费或失败扣费断言。

## 风险点与依赖项

- 供应商 usage 字段可能在流式末帧返回，必须保证服务端等待末帧后再结算。
- 供应商未返回 usage 时需要使用明确的本地计量适配器，不能回退到固定扣 1。
- 多模型批量预留会改变比较模式请求顺序，前端必须先完成预留再启动模型请求。
- 旧用户余额已经混合了固定扣费和实际 usage，迁移只能建立 opening balance，不能凭历史 usage 自动反推真实余额。
- `users.tokens` 在新旧系统并存期间必须只有一个写入入口，否则会产生账本与余额不一致。
- 预留超时需要后台清理任务；清理只能释放 `reserved` 状态，不能修改已结算记录。
- 如果未来需要按供应商真实金额计费，应在 `BillingPolicy` 增加 provider/model 价格倍率，并使用整数微单位，禁止使用浮点金额。

## 回撤边界草案

- Task 1：仅回退类型和策略定义，不影响数据库。
- Task 2：回退数据库迁移和新服务入口；保留账本数据，不删除审计记录。
- Task 3：关闭统一计费开关，恢复兼容包装。
- Task 4：按聊天路由回退流式结算，但保留已产生流水。
- Task 5：关闭多模型批量对比入口，不恢复固定 500 竞争扣费。
- Task 6：按接口分组回退，图片/视频任务统计与文本结算可以独立控制。
- Task 7：恢复旧展示前必须保留新账本查询接口，避免再次把两套口径相加。
- Task 8：使用迁移快照恢复旧余额，禁止重新运行旧的历史 usage 重算脚本。
- Task 9：测试和人工验证资产可独立保留，作为回撤后的验证依据。
