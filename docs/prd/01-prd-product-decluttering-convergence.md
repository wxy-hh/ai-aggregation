## 1. 业务痛点与底层思考

### 1.1 现状与痛点
- **信息过载，信噪比极低**：当前项目有 19 个独立页面、76 个 API 路由。从八字排盘、紫微斗数、奇门遁甲，到文生图、文生视频、语音转写，几乎涵盖了一个个人开发者尝试过的所有方向。
- **面试认知灾难**：
  - 当面试官打开你的产品首页时，映入眼帘的是琳琅满目的工具堆砌。第一直觉是：*“这是一个找各种开源库东拼西凑的玩具聚合站，缺乏技术主线与核心深度。”*
  - 核心最具竞争力的资产（自写 Agent Loop、前后端 SSE 状态机、HMAC 审批、RAG 混合检索）被深埋在不起眼的二级选项里，甚至在默认设置中 `agentModeEnabled` 是 `false`。
  - 应用选择弹窗中还充斥着 `/ppt`、`/legal`、`/code`、`/3d` 等点击后显示“功能开发中”的占位项。
- **文档事实与代码打架**：`README.md` 写着接入了通义千问、智谱、NestJS，但代码里根本没有；宣传 100% 评测，代码里是写死的值。这种矛盾在资深面试官面前是致命的扣分项。

### 1.2 设计原则（张一鸣思维操作系统）
1. **删除一切稀释专注力的元素**：优秀系统的核心是信息分发效率，而不是提供无限的浅层选项。平庸有重力，做加法很容易，敢做减法才能形成逃逸速度。
2. **坦诚清晰，消除不对称**：代码是什么，文档就必须如实写什么；把实际的工程思考（包括负结果）真实呈现，不编造不存在的技术架构。
3. **主航道绝对聚焦**：把 90% 的产品表达力收敛在唯一的王牌生态位——**以交付物（Artifacts）为核心、具备安全治理与状态韧性的现代 AI Agent 全栈平台**。

## 3. 具体改造细则

### 3.1 改造一：默认启用 Agent 模式，重塑 `/chat` 为智能体工作台
1. **默认状态切换**：
   - 修改 `apps/web/src/stores/settings-store.ts`，将 `agentModeEnabled` 默认值从 `false` 改为 `true`。
   - 输入框上方保留快捷切换按钮：`⚡ 智能体模式 (推荐)` vs `💬 极速对话`。
2. **主界面视觉引导**：
   - 打开 `/chat` 首页不再是冷冰冰的输入框，而是展示 Agent 能力矩阵（“知识深度调研”、“代码重构审计”、“带审批的数据提取”）；
   - 右侧直接预留或分屏联动 **Artifacts 交付物面板**，让用户和面试官一进页面就能感知到“这是一个生产力工具，而非单纯打字机”。

### 3.2 改造二：导航与应用菜单做减法（收敛清理）
1. **清理无效占位**：
   - 彻底删除 `components/layout/apps-modal.tsx` 中 `DISABLED_APP_IDS`（即 `ppt`、`legal`、`code`、`3d`）的占位卡片；
   - 绝不向用户展示任何不可用的“半成品”。
2. **设立「实验室 (Playground / Labs)」入口**：
   - 在侧边栏或主菜单底部设立独立的「实验室」或「多模态试验田」折叠菜单；
   - 将八字、紫微、奇门、星座、生图、视频等页面整体归入 `/labs/*` 或归类展示；
   - 附带一句话定位说明：*“此区域为团队多模态算法与特定垂直领域（东方数理）的轻量接入实验，不作为主线生产力核心。”*
   - **效果**：不仅不丢已有成果，反而展现出清晰的模块规划和架构克制感。

### 3.3 改造三：文档与代码事实彻底对齐（消灭简历雷区）
1. **修正模型供应商清单**：
   - 全面更新 `README.md`、`CLAUDE.md`、`docs/project-guide.md`；
   - 纠正为真实代码接入的 **讯飞星火 (Xunfei Spark)、火山引擎豆包 (Doubao)、深度求索 (DeepSeek)** 三大对话供应商，删除虚构的通义千问；
   - 图像/视频准确标注为 Agnes 与智谱。
2. **纠正后端架构描述**：
   - 移除“独立 NestJS 后端”的过时设计设想；
   - 正式定调为：**Next.js 15 Monorepo 全栈架构（Turborepo + Standalone Web BFF + BullMQ 独立常驻常态 Worker）**。这本身就是一个非常现代且受欢迎的技术选型，无需借用 NestJS 贴金。
3. **Worker 占位清理**：
   - 对 `apps/worker/src/workers/stt.ts`, `ppt.ts`, `image.ts` 这类仅有占位符的代码，显式加上 `@deprecated` 或直接下线未消费的队列，确保全仓跑测试与检索时没有任何悬挂死代码。
