## 1. 业务痛点与底层思考

### 1.1 现状与痛点
- **信息过载，信噪比极低**：当前项目有 19 个独立页面、76 个 API 路由。从八字排盘、紫微斗数、奇门遁甲，到文生图、文生视频、语音转写，几乎涵盖了一个个人开发者尝试过的所有方向。
- **面试认知灾难**：
  - 当面试官打开你的产品首页时，映入眼帘的是琳琅满目的工具堆砌。第一直觉是：*“这是一个找各种开源库东拼西凑的玩具聚合站，缺乏技术主线与核心深度。”*
  - 核心最具竞争力的资产（自写 Agent Loop、前后端 SSE 状态机、HMAC 审批、RAG 混合检索）被深埋在不起眼的二级选项里，甚至在默认设置中 `agentModeEnabled` 是 `false`。
  - 应用选择弹窗中还充斥着 `/ppt`、`/legal`、`/code`、`/3d` 等点击后显示“功能开发中”的占位项。
- **文档事实与代码打架**：`README.md` 写着接入了通义千问、智谱对话、NestJS，但代码里根本没有（`packages/providers` 仅接入讯飞、豆包、DeepSeek 三家）；宣传 100% 评测，代码里是写死的值。这种矛盾在资深面试官面前是致命的扣分项。

### 1.2 设计原则（张一鸣思维操作系统与定调纠偏）
1. **删除一切稀释专注力的元素**：优秀系统的核心是信息分发效率，而不是提供无限的浅层选项。平庸有重力，做加法很容易，敢做减法才能形成逃逸速度。
2. **坦诚清晰，消除不对称**：代码是什么，文档就必须如实写什么；把实际的工程思考（包括负结果）真实呈现，不编造不存在的技术架构。
3. **主航道绝对聚焦与定调纠偏（消灭 Over-promising）**：
   - 严禁盲目对外自封“工业级 AI Agent 工作台中枢”，避免把面试官预期拉高到分布式高可用和断点续跑维度；
   - 正式定调为：**「面向交付物（Artifacts）与高安全治理的生产级轻量 AI Agent 应用全栈」**，突出状态机有界性、HMAC 审批防重放、Fail-Closed 等治理深度。

## 3. 具体改造细则

### 3.1 改造一：渐进式工作台 (Progressive Workbench)，重塑 `/chat` 生产力
1. **修复水合 Bug 与状态切换**：
   - 彻底移除 `apps/web/src/stores/settings-store.ts:184` 中 `onRehydrateStorage` 的硬编码清零逻辑 `state?.setAgentMode(false)`；
   - 将 `agentModeEnabled` 默认值设为 `true`，输入框上方保留快捷切换按钮：`⚡ 智能体模式 (推荐)` vs `💬 极速对话`。
2. **环境探针与自动优雅降级（防 500 / 402 崩溃）**：
   - 服务端与客户端增加模型 Key 与配额探测：当未配置 `DEEPSEEK_API_KEY` 或用户 Token 余额不足 4,096 tokens 时，系统**自动优雅降级为极速对话**，并弹出轻量友好 Toast 提示，严禁向新访客直接抛出 500 或 402 错误。
3. **主界面任务矩阵与 300ms 骨架屏**：
   - 打开 `/chat` 首页展示 3 个高频 Agent 能力矩阵卡片（“知识深度调研”、“代码重构审计”、“带审批的数据提取”）；
   - 用户点击或输入时，前端在 **300ms 内**直接呈现 Thought 思考流骨架屏（“🧠 正在规划任务切片...”），消除首字延迟（TTFT）等待焦虑。
4. **移动端 Artifacts 交互规范（严守 CLAUDE.md 红线）**：
   - **桌面端（≥1024px）**：无产物时不预留空面板；产生交付物事件时平滑展开右侧 Dock；
   - **移动端（<768px）**：严禁双栏并排；采用**单视图双 Tab 模式 (`[💬 对话] [📄 交付物 (N)]`) + 底部浮动提示条**；
   - 点击热区严格 `>= 44x44px`，全面适配 iOS `pb-safe` 底部安全区，输入法弹起时不发生遮挡。

### 3.2 改造二：导航与应用菜单做减法（双轨制冷冻与收敛）
1. **物理清理无效占位**：
   - 彻底删除 `components/layout/apps-modal.tsx` 中 `DISABLED_APP_IDS`（即 `ppt`、`legal`、`code`、`3d`）的占位卡片与类型定义。
2. **纯净化「多模态实验室 (/labs)」**：
   - 在侧边栏设立独立的「实验室」折叠入口；
   - `/labs` 仅收敛展示文生图（Agnes）与视频生成（CogVideoX），**严禁任何命理排盘内容混入**。
3. **命理模块双轨制冷冻与旧路由 307 重定向**：
   - 主 UI（侧边栏、顶部导航、应用弹窗、首页推荐卡）彻底抹杀八字、紫微、奇门、星座入口；
   - 底层代码静默冷冻，严禁物理搬迁文件目录；在 `next.config.mjs` 中对 `/destiny/*` 等旧路径配置统一 307 重定向至 `/chat`；
   - 中间件 `middleware.ts` 与根路径 `/` 统一重定向至 `/chat`，彻底消灭首屏算命卡片。

### 3.3 改造三：文档与代码事实彻底对齐（消灭简历雷区）
1. **修正模型供应商清单**：
   - 全面更新 `README.md`、`CLAUDE.md`、`docs/project-guide.md`；
   - 纠正为真实代码接入的 **讯飞星火 (Xunfei Spark)、火山引擎豆包 (Doubao)、深度求索 (DeepSeek)** 三大对话供应商，全仓彻底清理 `DASHSCOPE_API_KEY` 等虚构口径；
   - 图像准确标注为 Agnes 服务，视频准确标注为智谱 CogVideoX。
2. **纠正后端架构描述**：
   - 移除“独立 NestJS 后端”的虚假描述；
   - 正式定调为：**Next.js 15 Monorepo 全栈架构（Turborepo + Standalone Web BFF + BullMQ 独立常驻常态 Worker）**。
3. **Worker 物理剔除与依赖瘦身**：
   - 拒绝“仅打注释的假下线”：直接从 `apps/worker/src/index.ts` 的 `workers` 启动数组中彻底移除伪造的 `sttWorker`, `pptWorker`, `imageWorker`，释放 6 条常驻无效 Redis 轮询连接；
   - 从 `apps/worker/package.json` 彻底卸载专属依赖 `pptxgenjs`，大幅缩减 Docker 构建时间与体积。
