# 0035. QA 审查闭环与修复验证

* **状态**：已接受（决策 4 的原文状态词比对部分被 ADR-0040 取代；部分条款被 ADR-0047 修订）
* **日期**：2026-10-28
* **范围**：QA 工作流正本与指南、根规则、implement / implement-spec / code-review 技能、`tooling/scripts/qa-check.mjs` 与安装模板
* **相关**：ADR-0033（部分取代，逐条见下表）

## 背景

Schema 4 上线后的首个真实需求（agent-kb-loop）`qa-check review` 为 PASS，复盘却发现：主代理照着根规则与 implement 中对子代理行为的复述，用 Agent 工具自行派审查子代理，code-review 项目定制段从未加载，编号与文件名都不规范；宿主向子代理注入「不写报告类 .md」的规则，子代理拒绝落盘，主代理连派多个子代理后代写原文并改写结论；原文无规范编号时编号对账在空输入上静默放行；「已修」只有自述，证据全部早于修复；过程脚本调注册接口造账号、明文写密码、经 `window.__authStore` 后门登录，并用 `setState` 注入产物；对账表上实测不支持断言的行无人核对。

## 决策

坚持「防疏忽，不防对抗：缺材料就响，造假交给人」：

1. **入口只路由**：根规则、安装模板、implement、implement-spec 与正本阶段 6 只写「collect 后用 Skill 工具调用 `code-review`」，不复述子代理行为；正本保留一句 `review/` 产物位置说明。
2. **主代理逐字落盘**：子代理只返回，主代理逐字写入 `review/r<n>-*.md`，不删改、不覆盖；每轴每轮一个子代理，不重派；无返回保持待独立审查。规则只写在 code-review 项目定制段。
3. **原文可对账**：最新一轮原文无规范编号且不含「无发现」时 FAIL `REVIEW_RAW_UNNUMBERED`；转录核验覆盖子代理全部输出，审查包之后无子代理转录或无 `code-review` Skill 调用时给 NOTE。
4. **修复验证**：分流表新增「验证证据」列；「已修」行须引用特性目录 `evidence/`、`screenshots/` 下晚于轮次轨迹所指缺陷审查返回的文件（qa-run 日志 exit 0），或 `静态：<理由>`，否则 FAIL `FIX_UNVERIFIED`。tree 过期仍只给 NOTE。分流表「最终状态」须与该编号在原文中最后一次的状态词（`已修`、`未修`、`修错`，带限定语按未修）一致，否则报 `UNRESOLVED_FINDINGS`；分流表不得掩盖原文结论。
5. **登录在脚本外**：已有会话、用户在可见窗口登录，或 Agent 用用户提供的专用测试账号在真实登录页登录一次；`scripts/` 内密码字面量、登录或注册类接口路径、`window.__*` 上的登录方法并入不可豁免的 `AUTH_BYPASS_IN_SCRIPT`；`.setState(`、`window.__*` 访问与页面内 `localStorage`/`sessionStorage` 的 `setItem` 并入 `SYNTHETIC_INPUT_IN_SCRIPT` NOTE。
6. **对账表交给审查者**：acceptance 把对账表写入 `_qa/reconciliation.md`，Spec 轴逐行核对实测是否证明冻结断言，不成立的报 `[P-W<n>]`；review 时该文件缺失或过期 FAIL `RECONCILIATION_STALE`。

## 对 ADR-0033 的取代

| 被取代项（ADR-0033） | 新决策 | 依据 | 其他选项与代价 |
| --- | --- | --- | --- |
| 决策 1：两轴子代理各自把完整返回写入 `review/` | 子代理只返回，主代理逐字落盘 | 宿主会向子代理注入禁止写报告文件的规则，原假设在真实宿主不成立 | 主代理获得写原文的机会，由转录 NOTE 与人工终审兜底；「子代理优先写、拒绝时主代理写」双路径使检查器与文档复杂度翻倍、收益为零；「坚持子代理写、写不了 BLOCKED」在该类宿主上每次卡住 |
| 阶段 6 规则在根规则、implement、implement-spec、正本多处复述 | 入口只路由到 code-review 技能 | 复述直接诱导主代理跳过技能、自拟 prompt 派子代理 | 入口文档不再自带审查细节，读者需进入 code-review 查看 |

ADR-0033 其余条款继续有效。

## 明确不做

原文与转录的哈希比对、「必须有 Skill 调用记录」的硬失败（宿主转录不是公开契约，且主代理拥有完整写权限，挡不住还会耦合宿主）；模型档位约束（子代理默认继承主会话模型；转录核验发现不一致只 NOTE 提示、不阻断，用于发现宿主环境变量覆盖子代理模型）；补丁式语义规则（识别「0 条」、计时区间内的固定等待等）。

## 后果

- 检查器能发现缺编号、缺修复证据、证据早于修复、脚本内登录与对账表过期；不能发现主代理逐字伪造原文或证据，这类情况只给可核查的 NOTE，交给 retro 与人工终审。
- 本决策只描述机制，不宣称质量收益；效果以下一次真实需求的 dogfood 为证据。
- 停止条件沿用 ADR-0031/0033：同类问题两轮之后仍只能靠提示词约束的，转为人工检查项。
