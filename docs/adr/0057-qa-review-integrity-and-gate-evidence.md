# 0057. QA 对账覆盖、显式视觉目标与收口证据

* **状态**：已接受
* **日期**：2026-11-18
* **范围**：QA 工作流正本与指南、流程技能、`tooling/scripts/{qa-spec-review,qa-check,qa-run,review-package,qa-browser-helper}.mjs`、契约测试与安装模板
* **相关**：ADR-0033、ADR-0040、ADR-0042、ADR-0047、ADR-0048、ADR-0054

## 背景

C8 与 C9 的真实任务产物表明，nonce、原文哈希、对账表和“无发现”结构齐全，仍不能阻止审查者使用另一套 TC 映射、声称不存在的文件已核实，或在计划变更后用较弱的断言取得 PASS。C8 的 Spec 原文引用未进入审查包的 schema/迁移和不存在的 hook；C9 把可观察的“RRF 融合结果”改成“向量召回”，最终截图直接反驳变更理由。两次任务还把结果区、助手消息和对比区域的几何检查缩小为标题或状态卡。

同时，C9 的两条基线命令输出 `No projects matched the filters` 仍 exit 0；两次任务都在独立审查完成前运行最终交付命令，且最终门禁输出没有进入特性证据目录。ADR-0048 已明确来源凭据不证明语义质量，ADR-0054 已明确机器不猜语义；本决策不推翻这些边界，而是让审查者的语义判断具有完整、稳定、可复核的输入和输出位置。

## 决策

1. **SpecReviewChecklist**：Schema 4 计划以 `QA Review Coverage: 1` 显式启用新协议。acceptance 在生成对账表时同步生成版本化、机器可读的 Spec 审查清单，覆盖 PASS、FAIL、BLOCKED，记录每条断言的实测值或绑定、接缝、可用源码入口和是否发生计划变更。新 collect manifest 声明清单版本；没有该声明的历史审查包保持旧逻辑并给人工 NOTE。
2. **对账覆盖表**：新协议的 Spec 原文必须包含 `## 对账覆盖`。每行逐字携带对账实测值或绑定、已核实/未核实结论、源码位置与谓词摘要；相同实测值或绑定的连续断言可合并 ID。检查器只核对 ID 完备、无重复、绑定相等、源码引用存在及接缝来源匹配，未核实为 BLOCKED，不判断谓词是否足以证明断言。
3. **计划变更复核**：冻结原文与当前断言不同的行必须写 `变更成立` 或 `变更不成立`，未变更行写 `不适用`。`变更不成立` 为 FAIL；执行方须恢复原断言、重新验收或如实保留阻塞，不能只靠变更说明取得 PASS。理由和结论的语义正确性仍由人工终审核对。
4. **VisualTarget**：浏览器视觉断言须指明语义目标和稳定定位器。仓库 Helper 提供显式目标截图原语：调用方传入目标标识和 probe，probe 返回同一标识及矩形；硬断言成功后按该矩形裁剪截图。标识不一致、矩形无效或断言失败均不得截图；移动视口封装只增加设置与最终复位。
5. **空证据不是成功**：qa-run 在子进程 exit 0 但输出表明没有匹配项目、没有找到测试文件或测试数为 0 时，写入诊断并以非零退出。qa-check 对既有手工日志也识别同类空证据。计划新包或新测试路径的基线应明确记为“不适用”，不能当作已经运行的绿基线。
6. **计划新建路径显式声明**：Schema 4 的 init 白名单遇到当前与 base 都不存在的路径时，只接受 qa-plan 的 `## 计划新建路径` 中逐字声明的项；其他路径报 `UNKNOWN_SCOPE_PATH`。没有 Schema 4 计划的普通 review-package 使用保持原行为。
7. **最终交付在审查之后**：新 manifest 的交付日志 started 不得早于当前有效双轴原文的最晚 completedAt；可机械核实时违反为 `VERIFICATION_BEFORE_REVIEW`。凭据缺失导致时间不可知时沿用来源核验边界并交人工，不伪造时间。
8. **GateEvidence**：plan、acceptance、review 统一经 qa-run 使用 `gate-<phase>-*` 标签落盘。新 manifest 至少要求一次成功 plan 门禁和当前行为树上的 acceptance 门禁；review 自身由外层 qa-run 落盘，不在内部自证。门禁输出仍是机器结果，不是交付授权。
9. **审查减负与失败暂停**：Standards 只写编号发现、实际覆盖范围和必要依据，不逐 hunk 重复“无发现”；Spec 用对账覆盖表替代泛泛总结。quota、无效模型别名、用户取消或无返回时不得自动换模型、重派同轴同轮代理，保持待独立审查。
10. **可移植性**：新增纯函数模块、核心脚本与浏览器辅助模块同步进入安装模板；安装器复制四个零依赖工具和 `qa-browser-helper.mjs`。正本、指南、规划/实现/审查技能、根门禁与安装模板同步，不新增依赖、Hook、Schema 5、HMAC 或语义正则裁判。

## 备选方案与否决理由

| 备选 | 否决理由 |
| --- | --- |
| 继续只加“认真逐行审查”提示词 | C8/C9 已在长提示下失真，没有稳定输出位置供机械核对 |
| 用正则判断测试谓词是否充分 | 超出机器可靠能力，会把语义误判重新引入门禁 |
| 加强 nonce、HMAC 或转录适配器 | 只解决来源，不解决原文内容失实，且违背 ADR-0048/0054 的维护边界 |
| 所有历史特性立即补对账覆盖表 | 会篡改历史审查轮次；以 manifest 清单声明区分新旧协议 |
| 强制所有 browser 用例使用仓库 Helper | 宿主与页面差异大；Helper 提供可复用机制，自定义脚本仍由 Spec 轴按 VisualTarget 核对 |

## 后果与验证边界

- 新任务多一份机器清单和一份结构化 Spec 覆盖表；以删除 Standards 无发现散文和按唯一绑定分组抵消成本，效果须由后续 dogfood 观察，不预先宣称节时。
- 结构化清单只能防漏行、错绑定、假引用和未经判定的计划变更，不能防止审查者虚假填写“已核实”；独立审查与人工终审仍是语义防线。
- 本轮工具测试、真实 Playwright 目标截图和本特性双轴审查不冒充干净会话 `/implement` 发布 dogfood；QA-WF-01 保持待发布验收。
- C8/C9 的历史原文、执行记录和业务代码不在本决策中自动修改或补审。
