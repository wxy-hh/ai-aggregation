# 0047. QA 审查来源核验与事件时间边界

* **状态**：已接受
* **日期**：2026-11-03
* **范围**：QA 工作流正本与指南、code-review / qa-test-planner 技能、`tooling/scripts/qa-check.mjs` 及其测试
* **相关**：ADR-0035、ADR-0040、ADR-0042（部分修订，见下表）、ADR-0044

## 背景

对 ARCH-CK-03 至 ARCH-CK-06 四次真实运行的复盘发现：

- ARCH-CK-05 的 r2 Spec 原文与子代理实际最终返回明显不同，子代理没有给出报告所称的逐项「已修」结论，最终 `qa-check review` 仍为 PASS；转录核验只有 NOTE，不能阻止失真原文形成表面闭环。
- 同一次运行后来纠正 r1 原文，使文件 mtime 晚于已经执行的 r3 修复日志，检查器误报证据早于缺陷提出；执行者重跑内容相同的 r4，并通过 `touch` 恢复时序。
- ARCH-CK-04 的 Shell 包装使真正的浏览器脚本未被扫描，响应注入与非真实输入标注为空；对账表又只展示 PASS 行，审查者无法看到完整执行结果。

这些事实说明需要调整来源与时间核验的边界，但不证明新增更多流程、审查代理或语义扫描器有效。决策经 `/grill-with-docs` 逐项确认，沿用四次复盘中 GPT-5.6 Sol 与 Kimi K3.1 Pro 的独立分析及交叉评审。

## 决策

继续坚持「防疏忽，不防对抗；机器只判断可靠事实，语义交 Spec 轴与人工终审」。

1. **明确矛盾才阻断来源核验**：沿用 ADR-0044 的宿主边界，只对已有支持的 Claude Code 转录做来源一致性核验。能够定位当轮子代理真实最终返回时，落盘原文与该返回不一致，或复审输入缺少应复核编号，不得给出机器 PASS；已确认没有两份真实独立返回时保持「待独立审查」。无法读取、解析或定位对应转录时标记「来源未核验」，交人工终审，不把「找不到」一律判为流程失败。找不到 Skill 调用记录仍只提示，不另设形式门禁。
2. **模型不参与审查有效性**：独立审查只要求独立上下文、实际审查输入和真实返回。工作流不读取、比较或提示主代理与子代理的模型差异；用户配置优先，无配置时沿用宿主继承行为。
3. **允许同轮原文纠偏**：能定位真实最终返回时，主代理可将当轮失真原文恢复为该返回，不算新审查轮、不重派子代理、不增加 corrected 文件。纠偏只能还原来源，不得润色或补结论；仅为调整格式不得修改原文。无法定位来源时保持未核验，由人工处理。
4. **事件时间取代文件修改时间**：删除审查原文与修复证据的 mtime 门禁；有可靠转录时间、qa-run `started` 等事件时间时才核对先后，无法确定时交人工，不新增时间元数据文件。`treeDigest` 的过期证据拦截保持不变，不用 `touch` 或重复执行修复时间戳。
5. **语义审查不新增流程**：阶段 3B 仍由 planner 在冻结前自查可证伪性；阶段 6 仍由原 Spec 轴逐行对账，只进一步明确须查看绑定测试或过程脚本的实际谓词，若实现错误而谓词仍会通过则报 P-W。不增加冻结前独立评审、审查阶段、子代理或机器语义评分。
6. **对账与分流呈现事实**：对账表自动覆盖 PASS、FAIL、BLOCKED，并在计划变更时并列冻结原文与当前断言，不新增人工字段。分流的当前档位与处置状态写当前事实，历史放已有轮次轨迹；转专项或改档成立不永久锁定后续修复。轮次轨迹同时作为复审与修复事件时间的锚点，不使用编号在正文中的首次出现。

Shell 重定向与静态相对导入的有限脚本闭包属于本次缺陷修复，不扩展为通用静态分析。分流表是唯一缺陷清单，检查器不从正文自动发现缺陷；示例与真实发现的语义由执行方分流和人工终审核对。

## 对既有 ADR 的取代与修订

| 被取代或修订项 | 新决策 | 依据 | 其他选项与代价 |
| --- | --- | --- | --- |
| ADR-0035 决策 2、ADR-0042 决策 3：当轮原文不得删改或覆盖 | 仅允许依据可定位的当轮最终返回做逐字纠偏；其他修改仍禁止 | 复制失真若必须重审，会增加成本、轮次并可能撞上复审上限 | 保留失真文件并重审：文件历史直观，但增加无效审查；另存 corrected 文件：保留两份文本，但增加原文选择与对账复杂度 |
| ADR-0035 决策 3、ADR-0042 决策 3：转录异常只给 NOTE | 已定位来源且存在明确矛盾时阻断；无法定位或解析时仍由人工核对 | ARCH-CK-05 已证明明显失真可在 NOTE 下获得机器 PASS | 全部异常硬阻断：宿主格式变化或跨会话会造成不必要中断；全部维持 NOTE：明确矛盾仍被静默放行 |
| ADR-0035「明确不做」中的模型不一致 NOTE | 完全删除模型读取、比较与提示 | 独立上下文不依赖同模型，用户额度、成本与模型配置不应成为审查门禁 | 保留 NOTE：没有防线价值且增加噪音；强制同模型：干涉用户配置并增加成本 |
| ADR-0035 决策 4 及原文新鲜度中的 mtime 判定 | 使用可靠事件时间；没有则交人工；tree 校验不变 | 纠正 r1 原文曾使真实后产生的 r3 证据被误判，最终诱导重跑与 `touch` | 保留 mtime 兜底：自动覆盖较多，但合理纠偏仍会误报；新增时间元数据：增加产物与同步责任 |
| ADR-0033 决策 1 与 ADR-0040 的自动编号覆盖；正文首次出现作为复审与修复时间锚点 | 分流表是唯一缺陷清单，轮次轨迹是复审与修复时间锚点；只核对已列编号有原文依据 | 本特性 r4 证明同一编号早期是示例、后期是真实缺陷时会污染轮次；`isFindingLine` 又无法可靠区分 Markdown 外形与语义 | 保留自动发现可拦截漏抄，但会误收示例并漏掉碰撞后的真实复审；增强 Markdown 识别要持续追赶格式。代价是漏抄与轨迹失真由人工终审核对 |

ADR-0040 的「不做原文哈希防篡改」继续有效：本决策做的是已定位来源的一致性核对，不承诺防篡改、审查独立性或证据语义正确。ADR-0044 的非 Claude Code 人工来源核对路径继续有效，不新增其他宿主转录适配器。

## 明确不做

模糊相似度放行；模型一致性门禁；通用 Shell/JavaScript 静态分析；新 Schema、新审查轴或裁决代理；逐文件快照、CI/pre-push 强制门禁。通用浏览器模板、命令行便利、grill 决策保存和自动复盘统计不纳入本批交付。

## 后果

- 正常双轴路径不增加阶段；明确复制失真可通过同轮纠偏恢复，无需人工或重新审查。来源无法核验时仍有人工终审负担。
- 非 Claude Code 宿主不再依赖 mtime 自动判断先后，需人工核对来源与事件顺序；机器 PASS 仍只称「机器校验通过」，不构成交付授权。
- Spec 轴需读取相关实际谓词，可能增加审查阅读量，但不新增流程。
- 本决策只描述机制，不宣称质量或耗时收益。实施须以四次历史案例的回归测试及一次干净会话的真实 `/implement` dogfood 验证正常路径不被误阻断。
