# 0037. 产物版本化演进与章节补丁架构 (AGENT-WORKSPACE)

* **状态**：已接受
* **日期**：2026-10-28
* **决策者**：AI 聚合平台工程团队
* **范围**：`packages/shared`（`chat-stream-contract` 产物契约、`artifact-stream-extractor`）、`apps/web`（`chat-store` 产物池与版本链、`ArtifactWorkspace` Diff/回滚/就地预览、`/api/chat` 产物上下文注入、`agent-runner` 提示词）、`apps/web/src/eval`（离线评测）
* **修订关系**：修订 ADR-0015（流式抽取器对未闭合产物的收尾语义、同 `identifier` 再生成语义）与 ADR-0034（`kbDeposit` 增加版本维度）；不取代两者的其余决策。

---

## 背景

ADR-0015 已交付产物工作台（双栏 / 移动端全屏、多产物池、流式抽取），但"产物"仍是一次性实体，无法在多轮对话中被修改。核查现状发现四个阻塞点：

1. **模型看不到上一版**：请求体只回传 `m.content`，产物正文在流式阶段已从 `text-delta` 剥离，历史里只剩一句导语，模型无从在上一版基础上修改；
2. **同 `identifier` 再生成会拼接新旧正文**：`onArtifactStart` 保留旧 `content`，`onArtifactDelta` 继续追加；
3. **中止 / 失败不收尾产物**：中止与失败路径只处理消息，产物 `status` 永远停在 `streaming`；
4. **截断被误标为完成**：抽取器 `flush()` 对未闭合标签补发 `complete`；而收尾步输出上限为 `AGENT_SUMMARY_OUTPUT_LIMIT = 8192` token，长产物整篇重写必然被截断，半篇文档会被当作正式成品。

此外产物池仅存于浏览器 `localStorage`（键 `ai-chat-conversations`），服务端 `ChatSession` / `Message` 无产物字段；项目内无 diff 依赖，无产物相关埋点。

## 决策

### 1. 范围：产物版本化，不做对话区降维

核心做版本链、Markdown 章节补丁、Diff 对照、回滚。界面仅做桌面右栏拖拽调宽（宽度存本地，480px 至约 60% 视口）。不做"对话区降维"，不改 `AppLayout`、消息列表与默认展开行为。

### 2. 版本模型

- 每个产物最多保留 5 个正式版本，存 `localStorage`，不新增数据库表。淘汰最旧版，始终保留首版与当前版；写入超配额时降级为继续淘汰最旧版，不得使会话列表整体写入失败；
- 仅收到 `artifact_end: complete` 的版本成为正式版本。流式中的新版本为草稿，中止或失败即丢弃，工作台保留上一版并提示"本次修改未完成，已保留上一版"。全新产物（无上一版）的半成品保留并标记"未完成"（沿用消息的"有留空删"原则）；
- 回滚为**追加式**：把所选历史版本复制为新的末尾版本并标注"回滚自 vN"，不删除任何版本，所有路径只认末尾版本为当前版；
- 是否同一产物只认 `identifier`，由提示词要求模型修改时沿用。客户端不做启发式并入，漏接时宁可多出一份产物，也不静默覆盖用户内容。

### 3. 章节补丁（Markdown）与整篇替换（其余类型）

- **Markdown 且有标题结构**：模型输出 `<artifact identifier="…" section="## 标题行">新章节内容</artifact>`，仅含被改章节。客户端从当前版解析标题目录（跳过代码围栏内的 `#`）并随上下文提供给模型；
- **定位规则**：`section` 为目录中标题行的原样抄写，仅忽略首尾空白与连续空格，不做模糊匹配。章节范围为该标题行至下一个同级或更高级标题之前（含子章节）；补丁正文必须以标题行开头，否则整体不应用。找不到或标题重复则不应用，当前版不变；
- **多补丁**：同一轮可对同一产物输出多个补丁，只产生一个新版本。成功的补丁应用，失败的不应用并显式提示失败章节，提供"让模型重试"入口（预填失败标题）。定位以原始快照为准，顺序应用时用标题行重新查找，不依赖序号；
- **整篇替换**：代码、表格、无标题短 Markdown 沿用同 `identifier` 整篇输出；模型对 Markdown 产物输出整篇时同样按整篇替换处理；
- **流式预览**：文档拆为"章节前 / 流入的新章节 / 章节后"三块，仅中间块随增量刷新并带"修改中"标记、自动滚动定位；合并后高亮改动并提供"查看改动"入口。

### 4. 产物上下文注入（成本守卫）

- 仅当工作台展开且存在聚焦产物时，在**当次请求**中注入聚焦产物全文；工作台关闭时只提供目录（`identifier`、标题、类型），提示词引导模型请用户打开工作台，不得凭空重写；
- 注入内容不写入消息历史，下一轮按当时状态重新决定，不逐轮累积；
- 长度上限：有标题的 Markdown（走补丁，输出只有被改章节）30,000 字符；其余类型（走整篇替换）仅当全文 ≤ 6,000 字符才注入并允许修改，超限只给目录并引导模型告知用户拆分或新建。服务端复核长度，不信任客户端；
- 单请求继续继承 240 秒运行时间预算与 `AGENT_MAX_STEPS`，不新增工具、不新增步数。

### 5. 既有缺陷修复（随本特性一并交付）

- 抽取器 `flush()` 对未闭合标签改发 `artifact_end: error`；`finishReason === 'length'` 时也强制把当前产物标 `error`；同步修改固化旧行为的测试断言；
- 中止、失败与会话还原路径把残留 `streaming` 的产物收尾为确定状态；
- 同 `identifier` 再生成不再拼接新旧正文。

### 6. 入库状态绑定版本

`kbDeposit` 增加 `versionId`。当前版与已入库版不一致时显示"已入库 vN，当前有新版本"，按钮变为"沉淀最新版"，沿用 ADR-0034 的"另存新文档"语义。老产物无 `versionId` 时按"入库于首版"处理。"覆盖更新已入库文档"后置。

### 7. Diff 对照

统一视图（unified）：行级 diff 加字符级行内高亮，对比相邻两个正式版本的 Markdown 源码。引入 `diff`（jsdiff），实施时用官方文档确认版本并锁定精确版本号。

### 8. 验证与度量

- **离线评测**：新增 `artifact-patch:eval`（参照 `rag:eval`），约 12 条用例用真实模型运行（单章、相邻两章、含子章节、全角标点标题、重复标题、代码围栏内 `#`、该新建而非修改等）。指标：补丁应用成功率、未改章节字节级保持率、误用整篇替换比例、误并入数。**不预设数字门槛**，先跑基线再定；结论按"小样本观察"措辞，不写成已证实的成功率；
  - **评测模型**：固定为线上 agent 实际使用的 `deepseek-flash`（`AGENT_PROVIDER` / `AGENT_MODEL`，agent 模式会覆盖用户所选模型，补丁功能线上只会遇到它），走与线上相同的 `agent-runner`、系统提示词、流式路径与 `AGENT_SUMMARY_OUTPUT_LIMIT = 8192`；换其他模型得到的成功率对线上无参考价值；
  - **输入规模**：单条用例输入（系统提示词 + 标题目录 + 产物全文）按 30,000 字符上限估约 2 至 3 万 token，须有一条贴近该上限的长文用例；`deepseek-flash` 的上下文窗口数值仓库内未声明、**未核实**，执行前以官方文档确认能装下该量级；不涉及文件上传与 Function Calling（补丁走文本 `<artifact>` 标签）；
  - **重复次数**：每条用例至少跑 3 次，以抵消模型输出随机性；先用 2 至 3 条短用例试跑再跑全量；真实调用消耗账户额度，须用户确认后执行，费用以 DeepSeek 官方价目为准，此处不估算；
- **最小埋点**：复用 `trackEvent` 白名单，新增产物复制、导出、补丁成败、回滚、Diff 打开事件；props 仅含产物类型、版本序号、字符数区间，不含标题与正文；
- 计划中"复制 / 导出转化率提升 ≥ 50%"与阅读停留指标**不作为本次验收条件**，只建立基线（当前无历史数据，无法证明提升）。HTML 导出后置。

## 备选方案及否决理由

1. **整篇替换为默认修改方式**（初选，已推翻）：每次小改也要重输全文，且 8192 token 输出上限使 6,000 字符以上的产物必然截断，恰好排除了"长文交付"这一核心场景。仅保留给输出可控的类型。
2. **版本落服务端**：产物目前不在服务端，需先做"产物上云"，要新增表、迁移、API 与同步，范围翻倍并带来生产迁移风险。后置。
3. **指针式回滚 / 版本树**：回滚后再生成会永久丢弃被跳过的版本（破坏性），或需围绕分叉重做淘汰规则与界面。否决。
4. **客户端启发式并入同类产物**：用户聚焦报告时说"另起一份英文版"会被静默并入原链、内容被替换。否决。
5. **每轮都注入聚焦产物 / 注入全部产物 / 新增 `read_artifact` 工具**：前两者成本随会话线性增长；后者占用 `AGENT_MAX_STEPS` 且模型调用稳定性无数据。否决。
6. **并排双栏 Diff / 富文本渲染态 Diff**：右栏宽度放不下两栏、移动端不可用；表格与代码块的单元格级对齐风险高。否决。

## 后果

- **正面**：长文可被稳定局部修改，未改章节由客户端保证不变；失败不污染版本链；半成品不再冒充完成品；入库状态不再对用户说谎。
- **代价与风险**：
  - 章节补丁依赖模型原样抄回标题行与沿用 `identifier`，**成功率无数据**，靠离线评测与埋点观察；失败路径一律"不动当前版、显式提示"；
  - 多补丁部分失败会产生**半改状态**（如第三章已改、第五章未改，内容可能不一致），靠失败提示、Diff 与一键回滚兜底，系统不保证一致性；
  - 回滚占版本名额，5 个名额内连续回滚会挤掉真实生成版本；版本序号不再等于模型生成次数，以"回滚自 vN"标注区分；
  - 版本仅存本浏览器，换设备或清缓存即丢，与现有产物一致；5 个版本最坏体积约为现状 5 倍，**未实测**；
  - 同标题重复的 Markdown 文档无法修改其中任何一个重复章节；粒度为章节而非段落；
  - 已知缺口：超过 6,000 字符的代码 / 表格产物暂无修改能力；6,000 字符为按 8192 token 反推的估算，代码通常更吃 token，需在评测中校准；
  - 沉淀最新版会使知识库同时存在新旧两版文档，检索可能同时命中，覆盖更新后置；
  - `flush()` 语义变更使"截断也能看到半篇"变为"半篇标记未完成"，行为与全新产物半成品规则一致；
  - 流式期间下半部分的跳动感与移动端滚动定位**未实测**，需浏览器验收。
- **后置项**：覆盖更新已入库文档、HTML 导出、长代码 / 表格的局部修改、版本跨设备同步、基于基线数据重估转化率与阅读停留指标。
