# 0055. KnowledgeFaq 匹配政策与场景边界（评审 C8）

- **编号**：ADR-0055
- **状态**：已接受
- **日期**：2026-11-17
- **决策者**：AI 聚合平台工程团队
- **范围**：`apps/web` 聊天入口、FAQ 调度与 `knowledge_search`、`packages/db` FAQ 候选读取与计数、`packages/shared` 聊天请求场景标识
- **来源**：`docs/reports/2026-11-10-core-architecture-review.md` 第九节 C8

---

## 背景

C8 原判为「KnowledgeFaq 匹配政策散落」：阈值判断落在数据库 adapter，默认选库与命中计数分别由普通聊天短路和 Agent `knowledge_search` 维护。经逐场景拷问后，问题不只在于规则重复，还存在四处既有文档与源码不一致：

1. ADR-0027 与术语表把 Agent 多步调用归入 `FaqGroundTruth`，但聊天入口在 Agent 编排前无条件短路，≥0.92 时会跳过工具、引用与正常运行生命周期。
2. 原 FAQ spec 要求显式指定或绑定知识库才短路，当前实际隐式选择最近三个活跃库。
3. 原决策使用「单轮问答」措辞，当前普通聊天只检查最后一条用户消息，允许已有历史。
4. 对比模式先批量预留、再逐模型调用聊天；短路发生在配额接管之前，会产生没有终态的预留。

本决策把场景资格、选库、仲裁、阈值、计数和异常政策收拢为一个 Web 侧政策 module，同时明确哪些现有行为必须保持不变。

## 决策

### 1. 政策与存储分离

- Web 侧 `KnowledgeFaq` 匹配政策 module 拥有场景资格、默认选库、显式选库校验、候选仲裁、双轨阈值、决策结果与命中计数归属。
- 政策输出是判别结果：`short-circuit`、`ground-truth` 或 `no-match`，携带命中的 FAQ 事实与相似度。
- 政策不构造 SSE、不拼装工具提示词；普通聊天把 `short-circuit` 映射为直出流，Agent 把 `ground-truth` 映射为工具结果置顶块。
- 数据库 adapter 只提供当前用户的活跃知识库事实、带 ACL 与启用过滤的相似度候选、按 FAQ ID 的原子计数写入；不再输出 `isShortCircuit` / `isGroundTruth` 业务标志。
- 不新增数据库字段、不迁移历史数据、不调整 ADR-0027 的实体分层、独立问法向量索引或既有阈值数值。

### 2. 场景决策矩阵

| 场景               | 相似度与条件                                                 | 结果                                     |
| ------------------ | ------------------------------------------------------------ | ---------------------------------------- |
| 普通单聊           | ≥0.92；当前消息无附件、非对比模式、问题修剪后不超过 500 字符 | `FaqShortCircuit` 直出，允许会话已有历史 |
| 普通单聊           | 0.78 ≤ Cosine < 0.92                                         | 不注入 FAQ，按未短路进入正常模型链路     |
| Agent 知识检索     | ≥0.78                                                        | 仅 `FaqGroundTruth` 注入，不直出         |
| Agent 章节连续通读 | 无具体问题（query 为空或 `*`）                               | 不匹配 FAQ                               |
| 多模型对比         | 首轮、追问、单模型重试                                       | 不短路，全部进入模型与计费生命周期       |
| 当前用户消息含附件 | 任意相似度                                                   | 不短路，由正常模型读取附件               |
| 任意场景           | 低于对应阈值、FAQ 停用或未命中                               | 无 FAQ 结果                              |

- 普通聊天的「独立匹配」表示当前问题不依赖前文也能构成标准问法，不要求会话只有一轮。
- `0.78` 与 `0.92` 数值不变；本决策没有经过 A/B 或检索质量对照评测，不宣称准确率、幻觉率或性能收益。
- 历史消息曾含附件不影响当前问题独立匹配；附件内容不进入 FAQ 向量化或相似度计算。

### 3. 默认范围与显式选库

- 显式指定知识库时，只匹配该库，并且该库必须属于当前用户且处于活跃状态；不满足时，普通短路按未命中降级，Agent 保持无权访问语义。
- 未指定时，普通聊天与 Agent 的 FAQ 匹配共用同一默认范围：当前用户活跃知识库按最近更新排序，最多三个。
- 该规则只约束 FAQ。Agent 普通文档检索继续按最近创建选取三个知识库，两套范围可以使用不同集合。
- 文档、章节和元数据过滤只约束普通文档切片，不缩小 FAQ 匹配范围；无具体问题的章节连续通读仍跳过 FAQ。
- 500 字符上限仅约束普通短路资格，不扩展到 Agent 的 `FaqGroundTruth`。

### 4. 跨库仲裁

- 在 `FaqMatchScope` 内始终优先全局相似度最高的 `KnowledgeFaq`。
- 相似度同分时，优先最近更新知识库中的候选；仍相同则按稳定标识决胜，保证重复查询结果一致。
- 知识库新旧不覆盖相似度的首要地位；同分决胜是确定性政策，不是口径质量证明。

### 5. 命中计数

- 政策返回 `short-circuit` 或 `ground-truth` 决策时，统一发起一次异步、尽力而为的计数；低于阈值、停用、未命中或未采用不计数。
- 同一聊天请求中的多次 Agent 工具采用可以分别累计；不按用户、会话或请求去重。
- 计数失败不阻断业务；进程终止或写入异常允许少计。`hitCount` 表示匹配结果被采用的使用次数，不是独立用户数、去重请求数、阅读量或精确审计账本。
- 展示阶段不再触发计数；决策后的流构造或展示失败仍可能已计入，接口契约不得承诺展示必然成功。

### 6. 异常与访问控制

- FAQ 选库、向量化或候选查询异常按 `FaqMatchingFallback` 处理：视为未命中，保留服务端告警；普通聊天继续模型链路，Agent 继续普通文档检索。
- 不得在降级时返回未经验证的候选、伪造 FAQ 命中或把结果标记为权威口径。
- 租户归属与活跃状态拒绝是明确的访问约束，不属于可降级异常，不能借故障路径绕过。

### 7. 对比场景必须显式传输

- 对比模式禁止 FAQ 短路，首轮、追问与单模型重试一致。
- 仅在存在 `reservationId` 时跳过短路不足以覆盖对比场景，因为单模型重试不携带预留号；`ChatRequestContract` 必须增加明确的聊天场景标识，并由普通单聊、Agent、对比三条路径显式投影。
- 对比模式仍沿用批量预留与各模型独立结算；本决策不改变 `BatchReservation` 协议或 `QuotaSession` 决策表。

### 8. Agent 执行边界

- 普通聊天前置短路不再拦截 Agent 请求；Agent 的 FAQ 结果只能经 `knowledge_search` 进入工具上下文。
- Agent 即使命中 ≥0.92，也必须保留工具编排、引用、产物、审计与正常运行生命周期。
- 不在普通非 Agent 聊天新增 `FaqGroundTruth` 注入；这一区间继续是未短路，不扩张为新的提示词工程能力。

## 取代与修订

本 ADR 部分取代既有决策，未列出的内容继续有效：

- **ADR-0027 第 3 节**：「常规单轮问答或指定知识库」的短路条件，由本 ADR 的场景矩阵、默认范围与「当前问题独立匹配」语义取代；普通聊天不再被概括为也会注入 0.78–0.92 口径。
- **`.scratch/knowledge-faq-pair/spec.md` 的检索挂载决策**：原「必须显式指定或绑定知识库」被隐式最近更新三库规则取代；原普通聊天单轮限制被多轮当前问题规则取代；原 Agent 高置信度行为明确为只注入不直出。
- **ADR-0027 的其余决策**继续有效，包括 FAQ 与文档的一等资产分层、独立问法向量索引、启停生命周期、CSV 运维与阈值数值。

## 考虑过的替代方案

- **只允许显式绑定知识库短路**：可避免跨库误用权威答案，但当前聊天没有绑定入口，会实际关闭普通聊天短路，或在 C8 内扩张会话绑库 UI 与传输，成本更高。
- **保留对比模式短路并在返回前释放预留**：可保住零模型调用，但同一标准答案会失去多模型对比意义，还需为已有预留建立专门释放编排；选择禁止短路更清晰。
- **按聊天请求对同一 FAQ 去重计数**：指标更接近请求覆盖，但需要请求级去重状态或持久化唯一约束，并隐藏 Agent 多步中的真实重复采用，超出政策收拢范围。
- **FAQ 异常时阻断主链路**：可避免没有权威口径的回答，但会把辅助能力故障扩散为聊天不可用，改变现有可用性策略。
- **普通聊天补齐 0.78–0.92 注入**：可完整覆盖广义双轨描述，但这是新功能，涉及普通模型提示词、Token 用量与回答质量，必须另立 spec 和对照评测。
- **政策模块直接构造直出流与工具提示词**：可让调用方更薄，但会把传输与展示语义塞进政策 module，破坏可复用决策边界。

## 后果与验证约束

- `ChatRequestContract` 的场景字段属于新增契约变化，必须覆盖普通单聊、Agent、对比首轮、对比追问与对比重试的投影与运行时解析。
- 普通短路继续在配额预留前完成，不产生预留；Agent 高置信度不再短路，进入正常配额生命周期；对比模式禁止短路后不再产生无终态批量预留。
- 实施前先建立红灯用例：Agent ≥0.92 不直出、普通多轮仍可直出、当前附件阻断、500 字符仅约束短路、默认 FAQ 选库改为最近更新、Agent 文档选库保持最近创建、显式非活跃库拒绝、跨库同分仲裁、0.78/0.92 边界、停用、跨用户零命中、异常降级、每次采用一次异步计数。
- 实施时验证对比首轮/追问/重试均无 FAQ 直出且预留正常结算或释放，并保留真实浏览器核心链路验收。
- 数据库 adapter 移除业务阈值标志后，更新直接调用 `findBestFaqMatch` 的测试与注入接口；不允许保留两份阈值判定作为兼容层。
