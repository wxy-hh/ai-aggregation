# 0012. Agent 能力发现走 L0 意图提示路径（不默认自动路由）

* **状态**：已接受
* **日期**：2026-10-10
* **决策者**：AI 聚合平台工程团队
* **范围**：`apps/web` 对话输入区（`components/chat/chat-input.tsx`、新增 `agent-intent` 纯函数模块）、`app/api/chat/_lib/chat-handler.ts` 错误文案

---

## 背景

ROADMAP P0a 子项 2 要求弱化 agent 开关：前端意图检测命中时浮出「联网查一下？」芯片，一键切换并发送。评审中浮现的核心分歧是**意图识别该做到什么程度**：

- **L3 全自动路由**（ChatGPT Auto 形态）：模型/路由器自行决定联网，用户零感知；
- **L2 服务端分类器**：每次对话先经便宜模型判一道（+100~300ms 延迟、每次多一次调用成本）；
- **L0 前端规则**：关键词 + URL 正则，零成本零延迟，召回率拍脑袋 30-50%。

两个结构性约束排除了直接上 L2/L3：

1. **计费心智**：本产品按量计费，agent 模式走 quota 步数预检（`resolveAgentStepBudget`），成本显著高于普通对话。替用户做花钱的决定会引发账单争议——ChatGPT 敢默认全开是因为订阅制打包价，计费模型决定交互自由度（ROADMAP 否决记录第 1 条）；
2. **词表天花板**：关键词法是 NLU 的拙劣近似，加宽词表只带来误报率上升（芯片被无视 → 功能贬值），召回天花板不会因为投入而消失。

## 决策

**一期 L0 提示路径**，四件套：

1. **L0 检测 + 芯片提示**：URL 正则 + 16 个查询意图明确的窄关键词（最新/新闻/实时/价格/多少钱/天气/汇率/股价/官网/票房/排名/帮我查/查一下/查下/搜索/搜一下），草稿 ≥4 字符实时触发；追加 **paste 事件即时提示**（贴 URL 是最强信号通道）。芯片是「能力发现装置」而非路由器——首要职能是让用户知道 agent 模式存在，埋点数据是二期 L2 决策的需求证据；
2. **draft 级 dismiss**：点 X 仅本条草稿不再提示，不做全局开关（误报代价低，设置入口过重）；
3. **余额不足禁止自动降级**：芯片点击后若 quota 预检失败（`steps < AGENT_MIN_STEPS`），照走 BillingError 错误路径 + agent 场景化文案（「可充值后重试；或关闭 Agent 模式直接对话」）。**绝不自动以普通模式重发**——普通模式凭旧知识回答时效性问题，用户以为查过实际没查，误导比拒绝更糟；
4. **二期 L2 由数据决定**：是否上服务端分类器，依据 `product_events`（ADR-0013）中芯片曝光/点击/dismiss 数据立项，不在一期膨胀。

## 备选方案及否决理由

1. **一期直接上 L2 服务端分类器**：*否决理由*：每次对话多一次调用成本与延迟，且分类错误的代价与 L0 误报同构（都是多一次 agent 计费）；在没有 L0 埋点数据前无法证明增量收益盖过成本。
2. **词表放宽（今天/最近/现在等时效词全收）**：*否决理由*：创作类意图（「写今天的日记」）同频命中，误报率陡增导致 banner blindness，芯片彻底失效。宁窄勿宽，按点击率数据迭代。
3. **余额不足自动回退普通发送**：*否决理由*：见决策第 3 条，静默降级产出过时答案的误导风险高于如实拒绝。
4. **行业「纯手动开关」现状（DeepSeek/Kimi 形态）**：*否决理由*：无文字标签的 Wrench 图标发现率接近 0，供给再好的编排能力也无人使用；L0 芯片已是行业手动派里的领先形态。

## 后果

- 正面：零成本零延迟上线；每次命中即一次用户教育；为二期 L2 积累决策数据；不与计费心智冲突。
- 负面/已知上限：召回率 30-50% 天花板明确存在；接受它——芯片的基线对比对象是「发现率≈0 的现状」，不是完美路由器。
- 词表与已知误报案例（「用代码实现价格计算函数」命中「价格」属可接受误报）登记在 `agent-intent` 模块注释与单测中。
