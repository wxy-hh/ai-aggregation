# 0058. 记忆输入消息的持久化边界与关闭清除语义

- **编号**：ADR-0058
- **状态**：已接受
- **日期**：2026-11-18
- **决策者**：AI 聚合平台工程团队
- **范围**：`packages/shared` 聊天请求契约、`apps/web` 聊天完成生命周期与客户端发送点、`packages/db` 消息模型与切片写入、`apps/worker` 记忆索引、`apps/web` 会话删除与 profile 更新、设置页记忆开关文案
- **来源**：`.scratch/tc12-memory-index-persistence/BRIEF.md`；C9 特性 `.scratch/server-text-preprocessing/` TC12

## 背景

C9 的知识库检索与知识库问答已通过真实浏览器验收，但 TC12「会话记忆检索」无法构造真实链路。核对 HEAD 后确认以下事实：

1. **记忆 Worker 只读服务端 `messages`**：`apps/worker/src/workers/memory-index/processor.ts:106` 按 `sessionId` 查询 `db.message.findMany`，无行则无切片。
2. **生产代码没有服务端消息写入方**：聊天消息走客户端 Store（`apps/web/src/stores/conversation-orchestrator.ts:35`），历史落 Dexie，`apps/web/src/app/api/history/route.ts:29` 仍是 mock；全仓检索 `message.create|messages.create|createMany(...messages)|prisma.message` 无匹配。
3. **记忆派发受 `conversationId` 门控**：`apps/web/src/app/api/chat/_lib/completion/lifecycle.ts:249` 在没有 `conversationId` 时不派发；新会话由客户端生成 `conv-*` ID（`apps/web/src/stores/conversations-store.ts:177`），服务端没有对应 `ChatSession`。
4. **服务端表是未启用的脚手架**：`ChatSession` / `Message` / `ConversationMemoryChunk` 在初始迁移已存在（`packages/db/prisma/schema.prisma:85-111`、`:597-620`），但没有任何生产写入。
5. **本地优先是既有架构**：`ADR-0046` 规定会话与历史的双快照都在本地；`ADR-0022` 规定记忆检索严格 opt-in，关闭时物理删除切片；`ADR-0050` 规定聊天请求是窄白名单契约。
6. **「会话服务端化 + 长期记忆」已被列为独立立项**：`docs/features/2026-10-01-chat-agent-tools/spec.md:317`、`docs/handoff/2026-10-01-chat-agent-tools-phase1-to-phase2.md:26`，理由是「记忆要可靠必须先有服务端会话存储」。

本决策只解决第 1-3 条形成的阻塞：为记忆索引提供一条真实、可清理的服务端输入；**不**把会话历史迁到服务端，也不建立服务端历史读取 API。

## 决策

### 1. 边界：记忆输入缓冲，不是会话服务端化

- 服务端 `ChatSession` / `Message` 只承载「记忆输入消息」：用户开启会话记忆检索后，完成轮次产生的 user/assistant 纯文本。
- 客户端仍拥有会话与历史的唯一事实源（`ConversationSnapshot` + `ArchivedMessage` + Dexie）；服务端消息不供 UI 读取，不替代 `/api/history`，不回填存量本地历史。
- 对比模式不纳入本次：`apps/web/src/stores/comparison-store.ts:235` 不传 `conversationId`，`ChatScene='compare'` 不写服务端消息、不派发记忆任务；分支语义留给未来的会话服务端化立项。

### 2. 写入方与顺序

- 唯一写入方是 `ChatCompletionLifecycle`：普通聊天与 Agent 模式共用同一收口，避免在路由、客户端或 Worker 各写一份。
- 新增副作用「持久化本轮记忆输入消息」位于记忆派发之前；持久化失败时记录告警并**跳过**记忆派发，避免 Worker 读到不完整会话。
- 不写入附件载荷、工具记录、推理、计划、审批、旁白与产物引用；这些仍只存在于本地快照/归档与 AgentRun 审计中。

### 3. 身份与幂等

- **会话身份**：客户端 `conversationId`（`conv-*`）直接作为 `ChatSession.id`。服务端首次写入时 upsert，并强制校验 `userId` 归属；ID 已属于其他用户时不写入、不派发，只记结构化日志。不引入第二套服务端 ID 或映射表。
- **轮次身份**：请求体新增可选的 `turnId`（≤128，白名单归一化）。客户端发送时取当前 user 消息的本地 ID；重新生成时取被重新生成那一轮的 user 消息 ID；审批恢复时取最近一条 user 消息 ID。旧客户端不传时跳过持久化并告警，不猜测。
- **完成身份**：沿用服务端 `requestId`（`getBillingRequestId`）标识一次完成；重新生成与审批恢复是新请求，产生新 `requestId`。
- **写入规则**：
  - user 消息每轮一条，按 `(sessionId, turnId)` upsert；
  - assistant 消息每次完成一条，按 `(sessionId, requestId)` upsert；
  - 以内部幂等键唯一约束兜底（user 为 `turn:<turnId>`，assistant 为 `complete:<requestId>`），同一完成重复回调不产生第二行；
  - 重新生成与审批恢复追加新的 assistant 行，不覆盖旧行；记忆里可能同时存在同一问题的多个答案，这是「每次完成一条 assistant」的已知语义，不在本次引入按轮次覆盖或切片回滚。

### 4. 内容与终态过滤

- 只写「最后一条 user 正文非空且 `finish.outputText` 非空」的完成轮，覆盖 `success` 与带正文的 `partial`；`failed`、纯附件空文本、纯产物无正文的轮次不写。
- `partial` 正文按原文写入，不额外标记截断；Worker 的切块与向量化语义不变。
- 一条 user + 一条 assistant 在同一事务内写入；`ChatSession.title` 留空，不为了展示引入派生标题。

### 5. 隐私：开关门控写入，关闭即物理清除

- **写入门控**：只有 `memorySearchEnabled=true` 时才写服务端消息；未开启用户的对话完全不落服务端。这与 ADR-0022 §1 的严格 opt-in 一致。
- **关闭清除**：关闭记忆时，在同一事务内更新用户开关并物理删除该用户的记忆会话（`ChatSession` 级联删除 `messages` 与 `conversation_memory_chunks`）。服务端不保留明文聊天正文，也不保留空会话。
- **并发竞态**：Worker 在插入切片前，于同一事务内锁定用户行并复核 `memorySearchEnabled`；关闭接口先锁定同一用户行、更新开关，再删除会话。这样「关闭」与「在途索引」串行化，关闭后不会出现删除之后又被写入的切片。
- **存量语义**：关闭后再开启只从新产生的完成轮建立记忆，与 ADR-0022 §4 已写明的代价一致；不回填本地历史。
- **文案**：设置卡说明同步改为「开启后新产生的对话将建立加密向量索引；关闭后将彻底删除已索引的记忆切片与为记忆保存的对话内容」，避免只提切片造成误导。

### 6. 删除传播

- 新增幂等的服务端删除接口：按 `userId` 过滤的会话批量删除（单删与清空共用），不存在也返回成功。
- 四个本地删除入口都调用：侧栏删会话、历史单删、历史批删、清空历史；本地删除保持即时，服务端失败时提示「服务端记忆清理失败，请重试」，不做静默吞错。
- 账号删除继续依赖 `User` 级联，不新增路径。

### 7. 派发与补派发

- 保留 `jobId: memory-index-${sessionId}` + 30s 防抖，避免同一会话并发切块与向量化。
- 在 Worker 任务收尾时补一次水位线检查：若该会话存在高于已索引水位线的新消息，则以非冲突 jobId 再入队一次追赶任务。该检查只读取消息水位线，不改变切块、分词与向量化契约。
- 关闭记忆后不再派发新任务；Worker 开头的开关检查继续保留，插入前的事务复核是第二道保护。

### 8. 验证与证据

- **Web 单元**：开关门控；`turnId`/`requestId` 幂等；重新生成与审批恢复产生新 assistant 行；failed/空正文/纯附件轮次跳过；跨用户会话拒绝；持久化失败跳过派发；副作用顺序。
- **数据库/接口集成（真实 Postgres）**：会话 upsert 与归属；user/assistant 唯一性；删除级联；删除接口幂等与越权；关闭记忆事务；Worker 插入前锁用户行复核开关的并发用例。
- **Worker 集成**：30s 内两轮完成只产生一个延迟任务且都能索引；前一任务 active 时新完成能补派发；重复完成不产生重复切片；分词失败路径保持 ADR-0056 语义。
- **真实浏览器**：TC12 主链路（真实登录 → 开启记忆 → 发送暗号 → 服务端落盘与索引 → 新会话 Agent 召回 → 截图与断言）；关闭记忆 UI 流程（确认弹窗 → 成功提示 → 服务端消息/切片为 0，且不再派发）。
- **回归**：既有 C4/C5 完成生命周期测试、对比模式不落消息不派发、审批恢复、附件轮次跳过。
- 本决策不宣称记忆检索质量或性能提升；若后续要主张收益，必须提供可复现的对照评测。

## 后果

### 积极收益

1. **TC12 真实链路成立**：完成轮次有服务端消息 → 派发 → Worker 切片 → 新会话 `memory_search` 可召回。
2. **隐私边界闭环**：服务端只在 opt-in 后保存记忆所需正文；关闭即物理清除消息与切片；关闭与在途索引不再竞态。
3. **不破坏本地优先**：会话、历史、归档仍是本地事实源；服务端消息没有读取入口，不会被误当作历史权威。
4. **幂等可验证**：会话身份、轮次身份与完成身份分离，重复回调、重新生成、审批恢复各有确定语义。
5. **删除可传播**：本地删除入口与服务端清除一一对应，删掉的会话不会再被召回。

### 代价与权衡

1. 新增一次数据库迁移（消息幂等字段与唯一约束）；客户端 3 个发送点要补 `turnId`；线上契约增加一个可选字段。
2. 服务端会保存记忆开启用户的聊天正文；这是为记忆可靠付出的隐私面扩大，必须用第 5 节的清除与并发保护兜底。
3. 关闭后再开启只能从新对话建立记忆；存量本地历史不可回填。
4. 同一轮重新生成会留下多条 assistant 记录，记忆可能召回旧答案；按轮次覆盖或切片回滚属于后续优化，不在本次。
5. 对比模式暂时没有长期记忆；删除会话的服务端清理依赖网络，失败时需要用户重试。
6. Worker 补派发与插入前事务复核触碰 C9 已收口文件，需要新增并发与幂等测试，实施时必须跑完整 Worker/DB 回归。

## 备选方案及否决理由

1. **客户端完成时同步整份会话快照**：客户端知道最终状态、天然可替换；但新增第二写入路径，关页/离线即丢，服务端要信任大 payload，且与「服务端完成收口」的单一事实源冲突。否决。
2. **服务端生成 `ChatSession.id` 并回传映射**：主键由服务端掌控；但需要新增响应通道、客户端映射与刷新恢复，且与现有 `AgentRun.conversationId`、队列 `jobId`、历史 ID 形成两套身份。否决。
3. **只用 `requestId` 做幂等**：不改线上契约；但重新生成必须换新 `requestId`，同一轮会产生第二条 user 消息，只能靠内容启发式补救，「继续」等合法重复会误判。否决。
4. **一轮只保留一条 assistant，重新生成覆盖正文**：表面更干净；但 Worker 按消息 ID 与 `createdAt` 水位线去重，覆盖后不会重新索引，记忆停留在旧答案；若连 ID 一起换，旧切片仍在。要正确处理必须给切片加轮次并做回滚重建，超出本次。否决。
5. **所有登录用户始终写消息，开关只控制索引**：可顺带铺服务端历史；但这是 ADR-0046/独立立项级别的隐私与产品变更，当前设置文案不足以覆盖。否决。
6. **回填本地历史**：需要上传接口、独立同意、去重与后台索引排队；与本次最小闭环无关。否决。
7. **不做服务端删除接口**：改动最小；但本地删掉的会话仍可被记忆召回，修复反而引入新的隐私缺口。否决。
8. **只做插入前开关复查、不加事务锁**：改动更小；但关闭与在途索引的竞态仍在，Q2 的「关闭即清空服务端记忆」不成立。否决。
9. **不改派发，接受漏索引**：TC12 单轮可通过；但多轮对话正是记忆最该生效的场景，会出现「刚说过的话想不起来」。否决。

## 与既有决策的关系

- **扩展 ADR-0022**：新增「记忆输入消息」为记忆子系统的输入；关闭清除从 `conversation_memory_chunks` 扩展到记忆会话与消息；用用户行锁关闭在途索引竞态。ADR-0022 的严格 opt-in、双层 ACL、水位线增量与出站标签语义不变。
- **修订 ADR-0050**：聊天请求体新增可选 `turnId`，属于向后兼容的可选字段扩展；白名单剥离、非法值分层与现有字段语义不变。旧客户端不传时跳过持久化，不 400。
- **不改变 ADR-0046**：本地 `ConversationSnapshot` / `ArchivedMessage` 双快照仍是会话与历史的事实源；服务端消息没有读取入口。
- **扩展 ADR-0051**：完成生命周期的副作用顺序在「审计落库」与「观测 flush」之间新增「持久化记忆输入消息」，并保持「记忆派发」最后的顺序；恰好一次守卫与容错不阻断语义不变。
- **不改变 ADR-0056**：Tokenizer、EmbeddingBatch、切块与向量化政策不变；Worker 只增加收尾补派发与插入前事务复核。
- **不替代独立立项**：「会话服务端化 + 长期记忆」仍是独立项目；本 ADR 只建立记忆输入缓冲，不提供会话读取、同步或迁移能力。
