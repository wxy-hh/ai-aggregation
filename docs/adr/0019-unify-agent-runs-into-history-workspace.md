# 0019. 智能体运行记录收拢至历史大厅与架构解耦

* **状态**：已接受
* **日期**：2026-10-19
* **决策者**：AI 聚合平台工程团队
* **范围**：`apps/web`（`/history`、`/profile`、`agent-runs`、`history-workspace`）、`packages/db`（`agent_runs`）

---

## 背景

在 ADR-0015 实施后，平台上线了 `AgentRun` 模型与多步编排审计机制，但其前端呈现与系统历史架构存在以下割裂：
1. **分页缺失与容量硬伤**：个人中心（`/profile`）写死仅拉取首屏 10 条记录，当任务数超出 10 条后，后续记录因无分页器而无法查看；
2. **产品入口与认知冗余**：`/history` 大厅汇集了对话、语音、图片、视频、命理 5 类历史资产，唯独缺失智能体任务；而智能体运行记录却被放置在个人设置页（`/profile`），导致用户产生「历史记录是否与系统重复、为何两处分散」的心智困惑；
3. **页面职责不聚焦**：随着历史任务累积，`/profile` 个人中心被长卡片列表严重拉长，推挤了下方的安全绑定与账户设置。

## 决策

经与架构及产品设计审问对齐（`grilling` 决策树四项一致），确定以下重构方案：

1. **彻底从个人中心（`/profile`）剥离运行记录模块**：
   - 将 `ProfileAgentRunsSection` 从 `/profile` 移除，使个人中心纯化为「个人资料、用量统计看板、工具集成配置、账号安全」专区；
   - 彻底消除同一业务实体在两处分散展示的冗余。

2. **在历史记录大厅（`/history`）设立独立的「智能体」专属 Tab 视图**：
   - 顶部 Tab 栏扩充：`全部`、`对话`、`语音`、`图片`、`视频`、`命理`、`智能体`；
   - 当切换至「智能体」Tab 时，无缝切入专属的 Agent 任务审计看板视图；
   - 在「智能体」视图顶部提供状态过滤胶囊（全部 / 成功 / 部分完成 / 失败），并集成服务端完整分页器（上一页 / 下一页 / 页码选择），彻底解决多条记录的分页展示问题。

3. **数据层架构保持「双轨分离，按需拉取服务端」**：
   - **内容资产（本地缓存流）**：继续由 Dexie（IndexedDB）存储 5 类本地生成内容；「全部」Tab 保持聚合内容资产，不与跨网络分页的 `agent_runs` 强行混编，避免游标抖动与本地存储膨胀；
   - **任务审计（服务端真实源）**：`agent_runs` 保持以 PostgreSQL 数据库为唯一事实源，仅在用户切换到「智能体」Tab 时由服务端分页 API（`GET /api/agent-runs`）按需加载，确保计费与审计数据绝对准确与跨端一致。

4. **交互能力闭环与一致性统一**：
   - **详情回放**：保留 `ProfileAgentRunDetailDrawer`（迁移复用为 `AgentRunDetailDrawer`），提供目标、终态结果、耗时、Quota 消耗、工具调用流水（Tool Calls）及产物引用；
   - **一键重跑**：延续重跑能力，一键唤醒 `/chat?new=true&agent=true&goal=...` 预填任务；
   - **删除能力**：新增 `DELETE /api/agent-runs/:id` 路由，支持单条记录删除，融入 `/history` 的统一历史管理规范。

## 影响评估与收益

- **正面收益**：
  - 彻底理清「内容资产」与「任务审计」的层级关系，统一入口于 `/history` 历史大厅；
  - 彻底解决 10 条以上的记录截断问题，具备完整分页与状态过滤能力；
  - `/profile` 页面恢复轻量、整洁，布局符合 Apple 级设计系统；
  - 数据模型职责分明，服务端权威数据与客户端离线缓存互不污染。
- **代价与权衡**：
  - 需新增 AgentRun 的删除 API 路由与测试；
  - 需在 `/history` 页面处理本地 Store 与服务端异步请求的双模切换逻辑。
