# 0062. Agent 运行时韧性交付：浏览器验收范围收敛与人工终审裁决

* **状态**：已接受
* **日期**：2026-11-23
* **范围**：`docs/prd/02-prd-agent-runtime-checkpoint-resume.md` §5/§8、`.scratch/agent-runtime-resilience/`（qa-plan、review-report、对账表、脚本、截图、checklist、交付说明）
* **相关**：ADR-0054、ADR-0061、ADR-0048、`GLOSSARY.md`「运行时韧性与流式恢复」与「QA 工作流」章节

## 背景与问题

ADR-0061 对应的特性已实现并跑到 r6：`gate-review-6.log` 结果 PASS，`final6-*` 交付验证、`gate-acceptance-12.log` 全 PASS，审查包封存（`treeDigest cb05e8d9…`）。`PRD §8` 记录了七项机器门禁无法自动判定的遗留问题，交人工终审。2026-11-23 经 `/grill-with-docs` 对这七项（拆为九个决定）逐项拷问，形成本 ADR。

机器门禁只校验审查材料结构、交付日志、tree 与范围完整性，不判断证据语义、独立来源与交付授权；以下裁决均属人工终审口径，不改变 `PRD §5` 的能力边界与 §6 Out of Scope 的产品范围。

## 决策

### 1. 接受浏览器验收的正式范围变更（取代 PRD §5 的两处「需真实验证」标注）

`PRD §5` 列九项验收，但 `qa-plan.md` 的 browser 只实跑 TC01/02/03 三条真实浏览器主链路（桌面视口），其余六项——完成后返回、并发防护、进程重启、审批跨刷新、配额准确性、日志回收——只有 integration/unit 证据。

**取代**：`PRD §5` 中「审批跨刷新」「配额准确性」两项标注的「现状回归项，需真实验证」。确认这六项以现有 integration/unit 证据交付，不再补真实浏览器验收。

- **依据**：`ADR-0054 §6` 已把阶段 5 收敛为「1–3 条核心真实浏览器主链路 + 关键视口」；`GLOSSARY.md` 的 `RealLinkSmoke` 只要求「至少一条」走真实链路；这六项的行为边界都在服务端状态机与事件日志上，integration/unit 正是其正确观测点，真实浏览器能额外提供的只是 UI 呈现，而该层已由 TC01/02/03 覆盖。
- **代价（明确接受）**：并发防护、进程重启、审批跨刷新、配额、日志回收将**永远没有真实浏览器证据**；未来这些链路出线上问题时只能回溯 integration/unit 与人工判断。补测方案（模拟容器重启、等待 30 分钟日志过期、多次长任务）成本高且部分场景在真实浏览器中本质上难以稳定复现，还会突破 ADR-0054 的 1–3 条上限与 15 分钟时间盒。

### 2. 窄屏覆盖另案补足，不随范围变更一并豁免

窄屏不是 §5 九项验收之一，而是 `CLAUDE.md` 移动端红线与 `docs/project-guide.md:327` 的独立要求；本特性改了 `message-item.tsx`（消息列表）并新增重连/停止/不可用等状态文案与按钮，现有 7 张截图全为桌面。确认补**一条 TC01 窄屏重放**证据（须写明具体窄屏视口与捕获状态，几何或 DOM 断言只针对该链路实际渲染出的消息与控件，如无横向溢出、已渲染控件热区可见可点），三条主链路不重复跑；同时修订 `qa-plan.md:14` 的时间盒与视口措辞使其符合实际。工具沿用现有 `tc01-refresh-resume.mjs` 与 `ego-browser`（按 ADR-0054 §6 场景分流，需复用真实登录态）。**边界**：TC01 是刷新恢复链路，正常不渲染「正在重新连接」/「停止」等控件，故本证据不笼统宣称已验证这些控件的 44×44 热区；这些态若未在该次运行中出现，交付说明如实注明未覆盖，需要时另定捕获状态。

### 3. 补证据类动作不在需求对齐阶段落地，交下一棒受控闭环

补窄屏证据、补组件断言、补 DOM 证据都会改 `scope.json` 白名单内的测试/qa-plan/截图，按 `docs/agents/qa-workflow.md:141,158-161` 必然触发重新 collect、Spec 轴增量复审、最终交付命令与 `gate-review` 重跑；本特性已跑到 r6（超出自动上限 r2/r3 的人工授权轮次），新增轮次需再次授权。故本次 `/grill-with-docs` 只记录决策与产物，不改 PRD、qa-plan、测试、证据或审查包，保持 r6 封存链完整。下列四项列为 `/to-spec` 的执行清单，按依赖顺序实施：

1. **TC03 停止证据（最高优先级，两步有依赖）**：**第一步只是核查，不是已证实结论**——先取得 `.markdown-body` 的 DOM 文本快照、选择器路径、实测字数与目标区域截图，判定 `tc03-browser-r12.log` 的「停止时正文长度 60」究竟是真实正文，还是 `tc03-true-stop.mjs:31` 取到了「已停止 · 未生成内容」等提示文案。疑点依据：同一次运行的 `tc03-stopped.png` 显示「已停止 · 未生成内容」、无正文，且历轮该值为 188/295/86/69/61/106/65/65/84/80/60 大幅波动。**第二步依赖第一步结果**：若确认取到提示文案，才修正 TC03-2「正文长度 > 0」的断言口径（改为量真实正文节点，或明确改为「停止态可见且正文不再增长」），并认定该断言此前从未真正验证「停止时已生成正文」；若确认是正文，则只需补可定位 DOM 证据解释截图差异。不得在未取得 DOM 文本前接受日志口径关闭此项。
2. **P-W01 重连文案回归**：在 `message-item.test.tsx` 补 `isStreaming: true` + `reconnectingAttempt` 的渲染断言，验证「正在重新连接（第 N 次）…」。主据是**现有测试正文 `message-item.test.tsx:247-264` 没有该文案断言**（只断言放弃后的「重新连接」/「停止」按钮）；`final6-message-item.log` 不含该字符串、仅有 11 tests 汇总行，只能说明日志里没有该文案，不能单独据此证明「没有用例」。据此订正 `review-report.md:7` 的 P-W01「已修」引用口径。TC02-1 浏览器文案断言因 CDP 断网时 SSE 可能静默恢复而删除（`qa-plan.md:286`），不构成组件层不需断言的理由。
3. **`online` / `visibilitychange` 触发源**：在现有挂载 effect 接缝分别派发 `online` 与 `visibilitychange`，断言 `resumePendingRuns` 被调用；约束为「不重构 `conversation-orchestrator.ts`、不引入依赖注入」。codegraph 标注 `resumePendingRuns` 与 `ConversationOrchestratorMount` 均无覆盖测试，而这是 PRD §3.4 第 2 条「移动端锁屏返回立即补挂载」的核心功能点。
4. **TC01 窄屏重放**：见决策 2。

### 4. 口径类裁决（本轮定论，不产生执行动作）

- **`SYNTHETIC_INPUT_IN_SCRIPT` 标注**：人工确认 TC01/TC02 满足真实输入要求。任务输入为真实 `fill`/`click`/`dblclick`；`localStorage.setItem` 仅用于记录 console 错误计数（`tc01:28-31`）与由 `MutationObserver` 记录重连文案是否出现（`tc02:49-55`），不驱动应用状态、不注入登录、不改写消息内容，属于观察探针；`qa-check.mjs:61-70` 的词法命中是「防疏忽、不防对抗」的粗粒度误报（`ADR-0054 §9`）。**保留** NOTE 与对账表 9 行「非真实输入」标注，不改检查器、不改脚本、不重跑；交付说明写明该人工确认。旁证：未使用 `localStorage.setItem` 的 `tc03-true-stop.mjs` 未被标注，但输入方式完全同类。
- **r5 历史原文**：保留为封存的历史轮次快照，不改写、不重封、不删除（ADR-0048 边界）。r5 的 6 个旧实测值与旧行号属于其审查当时；交付说明用一句话解释 r5/r6 差异，当前以 r6 的 65 行 checklist 与 `gate-review-6.log` 为准。
- **交付汇报计数**：统一为 **65 条断言**，提交数在**最终 HEAD 重新计算**后如实写入，不把任何中间值当终值。65 对应 `spec-review-checklist.json` 的 `rows` 数，与提交数无绑定。提交数的病根是用浮动 `..HEAD` 报数——`76a8b299..HEAD` 在 §8 写下的瞬间是 10，写入 §8 的 `53e02e6b` 提交后变成 11（实测 `76a8b299..8e83f352` = 10，`76a8b299..53e02e6b` = 11）；而本 ADR 落盘后尚未提交，后续补证据与规格实施还会产生新提交，故此刻的 11 只是当前值。交付说明的 range 右端必须写**具体 sha** 而非 `HEAD`，并在最终交付时重新计算，作为交付纪律固定下来，避免下一轮再漂。

## 后果与权衡

- 决策 1 放弃了六项真实浏览器证据，换取零新增执行成本与符合 ADR-0054 的成本约束；这是本次唯一改变既有验收结论的裁决，故按 `/grill-with-docs`「推翻既有决策」条款写明取代对象与依据，不写成已证实的收益。
- 决策 3 使本轮不关闭任何遗留问题，交付汇报维持「待人工终审 / 待独立审查」状态；`gate-review-6.log` 的 PASS 只称机器校验通过，不证明独立来源、不判断证据语义、不构成交付授权。
- 决策 4 接受「标注字面与人工结论并存」「仓库存在两套历史实测值」「计数口径一次性重置为 11」三处需要人工终审自行核对的不一致，以换取不动共享工具、不破坏封存链、不触发复审。

## 明确不做

- 不补六项缺失的真实浏览器验收，不突破 ADR-0054 的 1–3 条主链路上限。
- 不为消除 `SYNTHETIC_INPUT_IN_SCRIPT` NOTE 修改 `qa-check.mjs` 或重写浏览器脚本。
- 不改写、重封、删除 r5 及任何已封存的 `.source.json`。
- 不在需求对齐阶段修改 PRD、qa-plan、测试、证据或审查包，不自动发起 r7 复审。
