# 0031. QA 审查串联回归上游 code-review 与验收契约控制点

* **状态**：已接受（部分被 ADR-0033 取代；§5 宿主范围与「明确不做」中的其他宿主适配被 ADR-0044 取代）
* **日期**：2026-10-27
* **决策者**：AI 聚合平台工程团队
* **范围**：QA 工作流正本与指南、流程技能、`tooling/scripts/qa-check.mjs` 与安装模板
* **相关**：ADR-0023、ADR-0024、ADR-0026（部分取代，逐条见“对既有 ADR 的取代”）

## 背景

最近一次按 QA 工作流执行的真实需求（dogfood）没有通过，问题分为以下几类：

1. **审查技能被遮蔽**：本机个人级技能目录里有与项目流程技能同名的 `code-review`。Claude Code 中同名技能个人级优先于项目级，三份历史执行记录的加载行都带着个人版 `allowed-tools` 对应的工具数，加载后也没有任何子代理调用，项目定制的审查步骤从未进入模型上下文。
2. **措辞测试全绿不代表运行时生效**：契约测试只用正则校验仓库内技能的措辞，遮蔽期间全部通过。
3. **验收被静默缩减**：spec 声明的交付命令在规划时被删减；计划冻结检查只比较冻结前后的计划，发现不了。
4. **基线与冻结时机错位**：基线在实现和验收之后才建立，冻结的计划里已有执行结果，再用整目录 add 追认开工前改动。
5. **浏览器证据无法复核**：过程脚本放在特性目录之外，机器检查只要求截图和日志存在。
6. **审查职责过载**：项目版审查技能在上游技能上叠加了 collect、报告、证据审计、Spec 对账、三档分流与复审，实践中这些内容由实现者自行填写。

本轮原计划在只修复遮蔽、审查技能回归上游的状态下做一次盲审，统计子代理转录数与每轴命中数。用户选择先继续实施，盲审未执行；发布验收以后续真实需求的 dogfood 为准。

## 决策

### 1. code-review 回归上游，QA 步骤由工作流串联

`code-review` 使用 Matt Pocock 上游原文（仅 frontmatter 的 description 译为中文），只在末尾追加的“项目定制”段替换 diff 来源：固定点取 `scope.json` 的 base，diff 使用 collect 生成的审查包，审查期间不执行 git 写操作。其余职责如下：

| 环节 | 负责方 |
| --- | --- |
| collect 审查包 | QA 工作流，在调用 code-review 之前 |
| Standards + Spec 双轴 | 上游 code-review，前台并行两个独立上下文子代理 |
| review-report.md 落盘 | QA 工作流：审查方式、两轴原文、三档分流、按需的范围说明 |
| 三档分流 | QA 工作流逐条标注，人工终审确认 |
| 证据审计（确定性） | qa-check |
| 证据审计（语义） | 正本阶段 7 的人工终审清单 |
| 复审 | 本次修之后重新 collect 并重跑 code-review |
| 无独立能力 | 保持待独立审查，不运行最终 qa-check review |

### 2. 三档分流的约束

档位由主 Agent 提议，存在利益冲突，因此同时约束：两轴原文不得删改、不得漏列发现；驳回须引用 ADR 或契约，转专项须写明理由；Standards 轴的硬违规与 Spec 轴“缺失或部分实现”“实现有误”两类发现默认本次修；最终由人工终审确认。

### 3. 验收契约与基线时序

- spec 必须包含 `## 交付命令` 代码块，计划的交付验证必须原样包含其中每条命令；缺少该段时规划检查不通过，在途特性的验收与审查阶段只提示。
- `qa-check plan` 通过后立即 init 建立基线并冻结计划；implement 发现已有 `scope.json` 时不再 init。
- 独立审查完成前不把 backlog、计划等文档写成完成态。

### 4. qa-check 新增的确定性检查

| 代码 | 阶段 | 含义 |
| --- | --- | --- |
| `SHADOWED_WORKFLOW_SKILL`（BLOCKED） | plan、review | 个人级（`CLAUDE_CONFIG_DIR/skills` 或 `~/.claude/skills`）与项目流程技能同名且内容不同；其他同名只给 NOTE |
| `SPEC_COMMAND_MISSING`（FAIL） | plan、acceptance、review | spec 交付命令没有原样进入计划的交付验证；与计划结构问题一样提前结束本次检查，后续检查不输出 |
| `MISSING_SPEC_COMMANDS` | plan 为 FAIL，其余阶段为 NOTE | spec 缺少 `## 交付命令` 代码块 |
| `PLAN_FROZEN_AFTER_EXECUTION` | acceptance、review | 冻结计划已有 PASS/FAIL |
| `EVIDENCE_BEFORE_BASELINE` | acceptance、review（交付日志只在 review 检查） | PASS 证据或交付日志早于基线；修复前红日志不查 |
| 晚建基线 NOTE | review | 开工前范围内已有 GLOSSARY、CONTEXT、ADR 以外的改动 |
| `BROWSER_SCRIPT_OUTSIDE_FEATURE` | acceptance、review | 按 TC 判定：该 TC 的 PASS 日志中没有任何一个的 argv 引用特性目录内存在的脚本文件（.js、.mjs、.cjs、.ts、.mts、.cts、.py、.sh，prechange 快照除外）；只查路径不读内容 |

审查报告不再强制 `## 证据审计` 与 `## Spec 对账`，旧格式报告仍然通过。

### 5. 宿主范围

只保证 Claude Code。交接文档中“`.claude/agents` 作为可选适配层”和“报告强制证据审计与 Spec 对账”的设想取消；`AGENTS.md` 与 `.agents/skills` 符号链接保持原样。

## 对既有 ADR 的取代

本 ADR 取代 ADR-0026 的以下内容，其余条款继续有效：

1. **§5 审查报告结构**：报告不再强制“证据审计”和“Spec 对账”，只强制审查方式、Standards、Spec 与三档分流，范围说明按需。
2. **§5 与 §6 审查职责**：不再由 `code-review` 负责 collect、独立双轴、报告和三档发现，§6 中“`code-review` 只提供独立审查与三档发现”也不再成立；collect、落盘与三档分流改由 QA 工作流负责，`code-review` 只返回两轴发现。
3. **§5 与“影响、代价与边界”中的证据审计**：证据审计不再由审查者独立完成。确定性部分由 qa-check 负责，截图是否支撑断言、是否真实输入等语义部分归正本阶段 7 的人工终审清单；NOTE 处置规则保留，改由 QA 工作流执行。
4. **§5 复审方式**：不再按轴增量复审；本次修之后重新 collect 并重跑完整 `code-review`，只更新日志标签或证据索引时不重跑。
5. **§8 调用方式**：不再要求“前台串行调用只读审查者”，改由上游 `code-review` 在前台并行启动两个独立上下文子代理。
6. **§5 审查来源**：仍不把 ID 或 transcript 当作机器凭据；Claude Code 下，人工终审改为核对会话目录 `subagents/` 中的两份审查者转录。
7. **§7 浏览器脚本扫描**：仍不读取或扫描脚本内容。`BROWSER_SCRIPT_OUTSIDE_FEATURE` 只从日志 argv 中提取路径，并检查文件是否位于特性目录，作为“不新增浏览器脚本启发式扫描”的有限例外。

## 后果

- **正面**：审查技能回到经过上游验证的形态，QA 特有步骤集中在正本，可以独立演进；验收缩减、晚建基线和场外脚本由检查器直接拦截；遮蔽会在规划阶段暴露。
- **代价**：语义证据审计不再有 AI 兜底，完全依赖人工终审清单；三档分流依赖人工确认来约束利益冲突；同名检测只覆盖 Claude Code 默认个人目录。
- **验证方式**：文档与技能改动不新增措辞匹配测试，只校验旧 code-review 措辞的契约测试已删除；检查器行为由夹具测试守护；流程链路以后续真实 dogfood 验证。

## 明确不做

Hooks、Schema 4、exit 2、审查方式格式防伪、浏览器脚本内容扫描、截图语义识别、第三名 QA、宿主 scripts、新依赖、自动重试、企业托管技能目录检测、其他宿主适配。

## 停止条件

同类问题两轮之后仍只能靠提示词约束的，转为人工检查项，不再新增机制。
