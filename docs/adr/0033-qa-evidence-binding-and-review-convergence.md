# 0033. QA 证据绑定与增量复审（Schema 4）

* **状态**：已接受
* **日期**：2026-10-28
* **范围**：QA 工作流正本与指南、流程技能、`tooling/scripts/qa-check.mjs` 与安装模板
* **相关**：ADR-0031（部分取代，逐条见下表）、ADR-0026

## 背景

knowledge-metadata-filter 按 QA 工作流交付，plan、acceptance、review 三道检查全部 PASS，复盘却发现：审查原文被主代理转述失真（漏列 4 条、编造 1 条驳回）；执行记录的 PASS 与过程脚本断言脱节；过程脚本直连数据库签发令牌、改写本地用户密码并注入 Cookie；关键点击被换成页面内 `dispatchEvent`；复审没有收敛点；交付构建打断了正在进行的浏览器验收。共同原因是检查器只核对“写了没有”，Agent 自述即可过关。

## 决策

把自述换成机器可对账的产物，只对机械可修的缺口硬失败，语义判断集中到对账表与分流表交给人工终审：

1. **审查原文落盘与编号对账**：两轴子代理继承主会话模型，各自把完整返回写入 `review/r<n>-standards.md`、`review/r<n>-spec-axis.md`，每条发现带 `S-H/S-J/P-M/P-W/P-X` 编号；原文编号必须全部进入三档分流表，S-H/P-M/P-W 不是本次修时须写理由。原文新鲜度以审查包的 `packagedAt` 判断：tree 未变时重复 collect 沿用首次打包时间，避免交付阶段重新 collect 让已对应当前代码的原文显得过期；审查包与当前代码不一致仍由 `STALE_REVIEW_PACKAGE` 拦截。
2. **增量复审**：复审只核对上轮本次修编号（已修/未修/修错）并只审修复 diff，自动上限 2 轮；用尽后 `UNRESOLVED_FINDINGS` 为 BLOCKED，流程照常走完交付验证，人工授权的追加修复轮不计入上限。
3. **断言标记与用例绑定**：browser/api PASS 需日志中带实测值的 `[TCxx-n] PASS 实测：…` 标记；unit/integration PASS 需「文件 › 标题」绑定，核对文件、标题存在且被证据命令运行。`acceptance` 输出对账表。
4. **过程脚本静态扫描**：`scripts/` 内绕过登录（注入 Cookie、写令牌类存储、引入数据库驱动或 BaaS 管理端 SDK）为不可豁免的 FAIL；页面内模拟输入只给 NOTE 并在对账表标注。该规则写在通用检查器中，不由安装器按宿主开关。
5. **登录**：已有会话 → 用户在对话中提供的专用测试账号经真实登录页登录一次 → 打开登录页提示用户登录；删除 seed 账号与一次性注册路径。
6. **Schema 4 目录**：顶层 spec、qa-plan、review-report；子目录 `review/`、`scripts/`、`evidence/`、`screenshots/`、`_qa/`。删除 Schema 1/2/3 与 LEGACY 兼容，其他 Schema 报 `UNSUPPORTED_SCHEMA`。
7. **交付顺序与文档减负**：交付命令放在全部浏览器验收之后；指南改为不约束 Agent 的说明书；Execution Gate 只在任务首轮与宣称交付时声明，交付时引用 `qa-check review` 输出。

## 对 ADR-0031 的取代

| 被取代项（ADR-0031） | 新决策 | 依据 | 其他选项与代价 |
| --- | --- | --- | --- |
| 不做 Schema 4；Schema 1/2 冻结兼容，未声明返回 LEGACY | 升级 Schema 4，删除旧 Schema 与 LEGACY | 目录重组后旧路径全部失效，兼容分支只增加维护面 | 保留 Schema 3 编号直接改写：旧计划出现语义不明的 FAIL |
| 不做浏览器脚本内容扫描 | 扫描 `scripts/`，仅绕过登录硬失败 | 本次脚本写库、改密码、注入 Cookie，提示词约束已失守 | 维持不扫：同类副作用只能事后发现 |
| 本次修后重跑完整 code-review | 增量复审，自动上限 2 轮 | 全量重审每轮都可能产出新发现，无收敛点 | 无上限全量复审会死循环；不复审则修复引入的问题无人发现 |
| review-report 原样粘贴两轴原文 | 原文由子代理落盘，report 只写审查方式、分流与范围说明 | 本次报告原文被改写、漏列、编造 | 主代理照抄后用转录逐字比对：可信度押在宿主转录格式上 |
| 不把 transcript 当作机器凭据 | 部分保留：转录比对只给 NOTE | 宿主转录格式非公开契约 | 转录比对判 FAIL：宿主格式变化会卡死流程 |

ADR-0031 其余条款（交付命令契约、基线与冻结时序、同名技能遮蔽检测、code-review 回归上游）继续有效。

## 后果

- 检查器能证明产物齐全、编号对得上、标记与绑定存在、脚本没有绕过登录；不能证明实测值的语义、截图对应或日志未伪造，这些由对账表与人工终审承担。`结果: PASS` 只称“机器校验通过”。
- 本决策只描述机制，不宣称质量收益；效果以后续一次真实需求的 dogfood 为证据。
- 停止条件沿用 ADR-0031：同类问题两轮之后仍只能靠提示词约束的，转为人工检查项，不再新增机制。
