# 0034. 对话产物回写知识库与 FAQ 反哺双向数据闭环架构

* **状态**：已接受
* **日期**：2026-10-28
* **决策者**：AI 聚合平台工程团队
* **范围**：`apps/web`（产物工作台一键沉淀、消息栏 FAQ 智能提炼、入库 API、双向溯源 Badge）、`packages/db`（文档切片同步入库事务、FAQ 即时写入）、`packages/shared`（类型契约与分块约束）

---

## 背景

在平台现有的 RAG 与智能对话（`/chat`）架构中，知识库仅作为模型的单向只读信息源（Throughput-only / Read-only RAG）：
1. **知识资产沉淀孤岛**：用户在智能对话中耗费模型算力与推理时间沉淀出的深度行业研报、对比分析表或架构代码，随会话归档而被淹没在历史流中；在后续新会话或团队协同中，依然需要重复提问、重新检索，无法形成知识复利；
2. **长文本切片与高频权威口径脱节**：即使多次调优了长文本的回答，用户确认后的最佳问答无法直接反哺为知识库中具备秒级强短路（ADR-0027）的高置信度官方 FAQ；
3. **入库延迟与可靠性摩擦**：传统文件上传入库依赖 Worker 队列与轮询机制，若将对话中即时生成的结构化文本同样走大文件排队异步流程，会导致用户体验割裂（等待数秒至数十秒）、难以满足端到端 $\le 1.5\text{s}$ 的敏捷沉淀要求；
4. **缺乏溯源与重复入库风险**：用户在多轮对话中无法直观感知某个产物是否已经沉淀入库，重复点击容易造成知识库中存在大量重叠切片，且入库后的文档无法追溯源头会话。

---

## 决策

### 1. 资产双轨分流架构 (Dual-Track Ingestion Architecture)

依据产物形态与语义密度，采用双轨分流存储策略：
- **Artifact 交付物轨道（文档化）**：
  长篇 Markdown 研报、对比表格、代码架构等结构化产物，以独立 `Document` 实体写入用户选定的知识库，文档类型对应标记为 `markdown` / `table` / `code`，建立独立分块与向量索引，支持全文预览（`DocumentPreviewDrawer`）与原样下载；
- **高价值对话问答对轨道（FAQ 权威口径化）**：
  多轮对话中经用户验证的最佳问答，转化为 `KnowledgeFaq` 主表与 `KnowledgeFaqQuestion` 问法表记录，直接进入 ADR-0027 建立的 1024 维 BAAI/bge-m3 向量索引，后续提问可触发 Cosine $\ge 0.92$ 的秒级极速强短路或高权重置顶。

### 2. 受控轻量弹窗与人机协同确认 (Controlled Human-in-the-Loop)

杜绝后台完全静默自动入库（避免低质废稿与模型幻觉污染知识库向量空间）：
- **产物入库弹窗**：点击「沉淀到知识库」呼出轻量弹窗，预填产物标题与智能推荐标签（复用 ADR-0032 元数据机制），支持用户自主下拉选择目标知识库并确认；
- **FAQ 提炼弹窗**：展示提炼后的标准问题、提纯答案及衍生相似问，用户可一键修正后确认入库；
- **防重复沉淀与状态感知**：入库成功后前端本地状态与产物元数据同步标记 `deposited: true`，操作按钮变为「已入库」高亮微标，支持点击直达知识库对应文档；重复点击给出确认覆盖或另存提醒。

### 3. 同步即时切片与向量化流水线 (In-Process Sync Embedding Pipeline)

针对纯文本产物（通常 $< 20,000$ 字符），绕过 Redis/BullMQ Worker 异步调度：
- **轻量内存切块**：在服务端 API 路由内执行确定性切片分块（每块 500 字符，保留 `headingPath`）；
- **并发向量化**：并发调用 Provider 向量计算接口（`BAAI/bge-m3`）计算 1024 维切片向量并同步完成结巴分词；
- **单事务落盘**：在 `prisma.$transaction` 内原子完成 `Document` 创建（直接置为 `ready` 状态）与 `DocumentChunk` 批量写入；端到端耗时收敛于 400ms~1000ms，严格满足 $\le 1.5\text{s}$ 的性能指标。

### 4. 智能语义蒸馏与优雅降级策略 (Semantic Distillation & Graceful Fallback)

针对对话问答转化为 FAQ 时的口语化、代词依赖与冗余寒暄问题：
- **语义蒸馏**：调用低耗快速模型完成 Prompt 提炼，抽取出上下文独立的标准问题（Question）、客观权威的官方答复（Answer）并生成 3 个不同语序/用词的相似问（SimilarQuestions）；
- **弹性降级**：提炼过程设置 2.5 秒超时兜底；若超时或模型接口抖动，无缝降级为原始消息截取预填，绝不阻断用户手动沉淀链路。

### 5. 双向溯源元数据规范 (Bidirectional Provenance Contract)

- **知识库端元数据**：
  入库的 `Document` 与 `KnowledgeFaq` 的 `metadata` 中持久化记录：
  ```json
  {
    "sourceType": "chat_artifact",
    "sourceSessionId": "session_xxx",
    "sourceMessageId": "msg_xxx",
    "sourceArtifactId": "art_xxx",
    "depositedAt": "2026-10-28T10:00:00Z"
  }
  ```
  知识库工作台与全文抽屉中展示「来自对话」徽标，点击可展示关联会话提示；
- **对话端元数据**：
  产物实体与消息扩展记录 `kbDeposit: { deposited: boolean, knowledgeBaseId: string, documentId?: string, faqId?: string }`，驱动前端渲染与跨模块直达。

## 影响与替代方案评估

### 选定方案收益
1. **形成飞轮正反馈**：对话产生的优质资产零门槛沉淀为长期知识，二次检索即刻生效，系统越用越贴合用户业务；
2. **极速零阻塞体验**：同步嵌入方案使入库操作在 1 秒内完成，用户无需等待 worker 轮询刷新；
3. **知识库防污染**：轻量弹窗确认保障了人类最终把关权，杜绝低质切片流入。

### 代价与权衡
- **服务端短时并发**：如果超大产物并发调用向量接口，会占用 Web 进程少许 I/O。对策：对产物入库设置单次 30,000 字符硬截断，超长文本给出友好分段或精简提示。
