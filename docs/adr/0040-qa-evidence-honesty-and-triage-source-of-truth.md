# 0040. QA 证据真实性与分流表唯一状态源

* **状态**：已接受（自动编号覆盖与复审轮次锚点被 ADR-0047 修订）
* **日期**：2026-10-29
* **范围**：QA 工作流正本与指南、qa-test-planner / code-review 技能、`tooling/scripts/qa-check.mjs` 与安装模板
* **相关**：ADR-0035（部分取代，见下表）、ADR-0033、ADR-0031

## 背景

ADR-0035 之后的真实需求 agent-eval-check 最终 `qa-check review` 为 BLOCKED。复盘发现工作流本身的缺口：

- 后端特性没有 UI 改动，执行 Agent 在页面里替换 `window.fetch` 注入整条假 SSE，断言却写服务端行为；检查器只识别输入模拟，碰巧因 `.click()` 才标注。
- 审查者写 `**[P-W1] 已修**`，检查器从原文解析状态词时因紧跟 `*` 静默判为未修，误报 5 条；执行 Agent 为消除误报改写了 `review/` 原文。对 34 份复审原文的回放显示，`**[ID]** 已修`、`[ID]：已修` 等写法完全识别不到。
- 复合断言让一行绑定只覆盖一部分；“最多 1 次”从未构造越界分支。
- S-J 没有不修的出口，修坏味道越出特性范围，引出范围蔓延与新依赖；越界代码标转专项后仍留在本次改动。
- 脚本只断言文本包含，截图遮挡在 r3 才被发现；同一命令每轮以多个标签重跑。

决策经 /grill-me 逐问拷问，每问由 GPT-5.6 Sol 与 Kimi K3.1 Pro 独立设计并互审收敛。

## 决策

坚持 ADR-0035 的“防疏忽，不防对抗”，并补一条：机器只做机械校验且失败即关闭，不从自然语言里猜状态。

1. **真实链路冒烟**：触及核心链路时至少一条 browser 用例走真实登录、真实输入与真实后端，只断言本次新产生的终态，不断言模型非确定性分支。响应注入只在本次改了对应渲染代码时补充，不得替代。
2. **响应注入标注**：检查器内置常量模式表（`window.fetch` 赋值、路由拦截与 fulfill、`cy.intercept`、MSW 处理器），命中给 `RESPONSE_INJECTION_IN_SCRIPT` NOTE 并在对账表标注「响应注入」，不阻断。Spec 轴用窄判据核对：标注行断言服务端行为报 P-W；核心链路无未注入 browser 证据报 P-M。
3. **分流表唯一状态源**：分流表状态列改名「处置状态」（兼容旧名「最终状态」），只校验枚举（`INVALID_DISPOSITION`）；`review/` 原文只作审计材料。新增 `FINDING_NOT_REREVIEWED`：上轮本次修与 S-H、P-M、P-W 改档编号须出现在对应轴其后一轮原文中，只看编号出现与否。分流表自报未修、修错、改档不成立或本次修未填仍 BLOCKED。`qa-check review` 输出「原文核对」段（每个编号最后出现的原文行），仅供人工核对，不参与判定。格式问题不得成为修改原文的理由。
4. **原子断言**：每条断言只陈述一个可由单一证据单元判定的结论；声称边界的须构造越界情形；冻结前逐条自查。不允许一行多绑定。
5. **判断类发现分流**：S-J 默认驳回，仅在由本特性引入、不改变 spec 外行为、只动 r1 审查 diff 已触及文件及其配套测试时本次修；P-X 默认本次修即撤回越界改动；转专项须写证据、不修依据与跟踪位置。已证实行为错误的报 P-W；范围外既有工作区状态不编号。
6. **可见性与成本**：可见、无遮挡、未溢出断言由脚本在截图前硬断言几何；同 argv、同 tree、exit 0 的日志可跨 TC 与交付验证复用；最终汇报只给门禁结果、摘要、验证结论与待裁决编号。

## 被 ADR-0047 修订

- 「检查器核对原文编号覆盖」修订为：分流表是唯一缺陷清单，检查器只核对已列编号有原文依据，不从正文自动发现缺陷。代价是主代理漏抄真实发现不再由 `FINDING_NOT_TRIAGED` 拦截，由人工终审对照两轴原文发现。
- `FINDING_NOT_REREVIEWED` 与修复事件时间不再以编号在正文中的首次出现为轮次锚点，改用分流表已有的轮次轨迹；轨迹忠实性同样由人工终审核对。这样避免同一编号早期只是示例、后期成为真实缺陷时假闭环。

## 明确不做

增强正则或归一化白名单；JSON 结论块；宿主能力探测配置；恢复或重派审查者重写结论；原文哈希防篡改；检查器做 OCR、截图识别或语义判断；一行多绑定；正则匹配“且”“最多”等字眼；新增规划、审查或裁决代理；提高复审轮数；汇报字数机械校验。

## 后果

- 审查原文的任何写法都不再引发状态误报；已进入分流表的编号漏复审由 `FINDING_NOT_REREVIEWED` 拦截。真实发现漏进表、分流表抄错状态与轨迹失真不再被机器拦截，人工终审需对照两轴原文与「原文核对」段。
- 响应注入不再依赖碰巧的输入模拟才被看见；合法的故障态注入用例照常通过。
- 本决策只描述机制，不宣称质量收益；效果以下一次真实需求的 dogfood 为证据。
- 停止条件沿用 ADR-0031/0033/0035：同类问题两轮之后仍只能靠提示词约束的，转为人工检查项。
