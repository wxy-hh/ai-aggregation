# 0039. 独立质检节点与反思自愈架构 (AGENT-EVAL-CHECK)

* **状态**：已接受
* **日期**：2026-10-29
* **决策者**：AI 聚合平台工程团队
* **范围**：`apps/web`（`agent-runner` 质检时序与自愈回路编排、`evaluator` 评估器深模块、可观测性 Langfuse Generation 埋点、`types.ts` 与 `chat-handler.ts` 质检元数据审计与持久化）
* **关联计划**：`docs/plans/chat-agent-evolution-plan.md` (Phase 3 P2: `AGENT-EVAL-CHECK`)

## 背景

在既有的智能体执行流（`agent-runner.ts`）中，模型既充当“执行者”又充当“总结者”（运动员兼裁判员）。在复杂调研和多步骤检索场景下，容易出现以下问题：

1. **动作变形与自我合理化**：模型在检索到不相关网页或工具返回空结果时，倾向于强行收尾并自我脑补似是而非的结论；
2. **多实体维度遗漏**：用户在提问中指定了多个对比实体或核心要求（如“对比 React, Vue 和 Svelte 的最新性能与生态”），模型可能仅查阅了其中一两个便草率进入总结阶段；
3. **缺乏受控自愈能力**：现有的循环受限于固定的单向 step 推进，一旦工具前置阶段出现信息真空，模型无法在收尾前自主停步自省并定向回补。

## 决策

### 1. 触发条件与切入时机：收尾前信息充分度质检

- **条件触发**：仅当本会话执行过至少 1 次工具调用（或包含非空前置计划 Checkpoints）时才激活 Evaluator；纯直接回答类闲聊或无需检索的任务直接跳过质检，实现零额外延迟。
- **切入时序**：在决策循环结束、进入最终收尾步（Summary Step）**之前**介入质检。
- **避免破环流式 TTFT**：如果在收尾步生成长文本后再做审查，会导致前端大段流式内容回滚作废或造成长达数秒的服务端首字等待。收尾前质检能在信息源头把关，保证放行给收尾步的内容具备充分事实依据。

### 2. 模型选型与开销控制：复用当前模型 + 极窄预算 + 快速熔断

- **模型复用**：直接复用会话当前配置的 `agentModel`（由既有 Provider/Key 鉴权体系创建），杜绝跨模型供应商调用导致的凭据缺失或配置断裂；
- **极窄预算**：输出限制为纯 JSON 且 `maxOutputTokens: 256`（仅要求给出 `passed`、`missingAspects` 及简要 `suggestion`），严禁输出长篇解释；
- **快速降级 (Fail-Open)**：设置 `timeoutMs: 5000` 超时保护，遇到超时或解析异常立即静默降级（判定为 pass），绝不阻断正常业务交付。

### 3. 步数预算与硬熔断自愈规则

- **严守既有步数上限**：全局最大决策轮次统一收敛为 `maxDecisionSteps = Math.max(0, effectiveMaxSteps - 1)`（为最终收尾步留出至少 1 步）。质检与自愈决策步在 `roundIndex < maxDecisionSteps` 预算内运转，绝不突破全局步数预算，保证账单与预留额度安全；
- **为自愈预留 1 步**：`maxDecisionSteps >= 2` 时，常规决策循环上限为 `maxDecisionSteps - 1`，预留的 1 步只供质检打回后的自愈决策步使用；质检通过或无需质检时该步不使用，不退还给常规循环（避免「再跑一轮、再质检一次」使状态机复杂化）。`maxDecisionSteps < 2`（如余额降级到 `maxSteps = 2`）时不预留，质检未通过直接走诚实收尾。若常规循环跑满上限（未预留），自愈分支的 `roundIndex < maxDecisionSteps` 永远不成立，自愈不可达，这是预留的原因；
- **取代的默认值**：此前 `AGENT_MAX_STEPS = 5` 下常规决策最多 4 轮、deep-research（8 步）最多 7 轮；本决策后分别为 3 轮与 6 轮。代价是质检通过的任务最多少调 1 轮工具；
- **自愈重试次数硬限制**：整场请求至多触发 **1 次**自愈回补检索；
- **熔断优先于自愈**：管道停止判定 `pipeline.shouldHalt()`（时间预算 ∪ 连败熔断 ∪ 全局工具上限，ADR-0008）为真时，质检打回也不再追加自愈决策步，直接注入局限性约束诚实收尾；自愈决策步执行中触发停止判定时同样不再复检，按首检缺失项注入局限性约束收尾。自愈步本身会调用工具，越过熔断即越过 ADR-0008 的停止语义。代价是 US2「全部 404 后换关键词重新检索」只在连败未达 `AGENT_MAX_CONSECUTIVE_FAILURES`（3 次）时生效；
- **决策步直接作答不经质检**：模型在决策步直接给出回答（`deliver_answer` / `empty_finish`）时，答案已流式下发，不再进入质检；质检只把关「进入收尾步之前」的材料；
- **步数耗尽诚实收尾**：若已达到最大决策轮次时质检仍未通过，不再强行递归，而是将质检的「缺失说明」以轻量约束追加给收尾步提示词（告知模型：“注意：经检测尚缺 xxx 信息，请在最终回答中如实陈述该局限性，不要编造”），实现诚实交付。

### 4. 用户感知与 SSE 流式契约：零破坏性透明呈现

- **无计划卡片时**：质检通过时静默放行；质检未通过时，通过现有的 `agent_note` SSE 事件推送轻量反思摘要（如：“质检反思：检测到缺少竞品价格维度的关键事实，正在追加定向检索...”），在气泡思考区透明呈现，保持 `text-delta` 干净；
- **有计划卡片时 (ADR-0038)**：质检未通过时，将当前步骤保持为 `running`，通过 `plan_step_update` 推送自愈说明，并自动挂载后续追加的工具调用；
- **契约向后兼容**：不引入复杂的新顶层 SSE 事件类型，消费端零改动即可保持视觉一致性。

### 5. 可观测性追踪：独立 Generation 记录与轻量 Metadata

- **Langfuse 独立追踪**：在 Trace 实例中记录名为 `evaluator_check` 的独立 Generation，记录其输入、输出与 Token 消耗；
- **Trace & onFinish Metadata**：
  在 Trace 与 `onFinish` 中追加 `evaluator: { executed: boolean, passed: boolean, remedied: boolean }` 审计字段；
- **数据库无害存储**：保持 `AgentRunRecord` 表主 Schema 不变，作为扩展元数据透明存入，无须引入高风险数据库迁移。

### 6. 审查标准倾向：致命缺陷把关，避免过度干预

- **核心把控范围**：仅审查两项客观致命伤：
  1. **实体与指令覆盖**：用户显式指定的核心实体/比较维度是否在已有材料中有所涉及；
  2. **事实真空 (Truth Vacuum)**：工具调用是否全部失败或返回无有效内容，导致收尾结论缺乏任何事实抓手。
- **宽松放行原则**：不对主观修辞、文字风格或格式做过度严苛的打关，避免“假阳性”造成的无谓重试与延迟劣化。

---

## 代价与权衡

- **延迟开销**：对于执行了工具调用的任务，在收尾步前增加了约 800ms~1500ms 的 Evaluator 结构化判断耗时（受 5s 超时保护）；
- **Token 开销**：每次执行质检产生约几百 Tokens 的额外输入及不超过 256 Tokens 的结构化输出，通过极窄 maxOutputTokens 将增量成本压至最低；
- **收益**：从根本上消除 Agent 面对检索失败时“强行胡说”与严重漏看用户指定实体的动作变形，大幅提升多步复杂交付的严肃可信度。
