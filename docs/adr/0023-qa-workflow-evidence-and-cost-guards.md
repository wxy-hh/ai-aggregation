# 0023. QA 工作流的证据契约、成本边界与无 Hook 实施策略

* **状态**：已接受
* **日期**：2026-10-24
* **决策者**：AI 聚合平台工程团队
* **范围**：`docs/agents`、`.claude/skills`、`tooling/scripts/qa-check.mjs`、根 `package.json`

---

## 背景

现有 QA 工作流已经把规格、实现、浏览器验收和双轴审查串成闭环，但抽查发现部分执行记录只证明入口或开关可见，便将包含多个核心断言的用例整体标为 PASS。与此同时，代码审查以 `base...HEAD` 为输入，与先审查后提交的执行顺序不匹配，可能完全看不到未提交改动。

两项拟议增强也存在现实代价：阻断式 Hooks 可能在模型未按流程行动时反复拦截并诱发修复循环；独立 QA、不同模型和并行实现则无法在不知道宿主模型配置、价格和共享资源状态时安全地默认启用。工作流需要在质量、成本和使用体验之间取得可执行的平衡。

## 决策

### 1. 本期不引入 Hooks，只在阶段边界显式检查

新增零依赖 `qa-check`，仅在规划、验收和审查边界由 Agent 或开发者主动运行。检查器无网络、无模型调用、无自动重试，每次聚合输出全部可检查问题。`.claude/settings.json` 不增加 PreToolUse、Stop、SessionStart 或 Git Hook。

非零退出码只表示本次显式检查未通过，不授权模型反复修改业务断言。LEGACY 退出 0 仅用于旧计划兼容，输出必须明确“未校验”，不得等同于 PASS。

### 2. 默认 inline，独立 QA 仅显式 opt-in

默认由主 Agent 完成对抗性测试规划，不新增独立 QA。只有用户显式选择 `--independent` 时，才增加一个新上下文规划子代理；调用不传模型参数、不自动升级模型、不允许嵌套派发，主 Agent 负责落盘。

独立规划与浏览器执行分离：阶段 5 始终由主 Agent 在当前上下文执行，避免端口、登录态和运行时状态断档。不同阶段不得自动叠加第三名 QA 或裁决代理。

### 3. 默认串行，显式并行必须限制规模和外部风险

日常实现采用单会话连续冲刺。`/implement-spec` 只在用户明确选择并行时使用，最多两个实现子代理；主 Agent 串行合并并按既有 Git 规则获得确认，每次合并后执行约定回归。

Git Worktree 只隔离文件和分支，不隔离数据库、Redis、端口或上游额度。涉及迁移、共享状态或相同文件的高耦合任务必须回退串行。

### 4. 用逐断言三态记录替代整体口头 PASS

新计划使用 `QA Schema: 1`。Spec 保持数字用户故事，每个 TC 显式列出验证断言，执行表复用断言自然序号，不创造额外断言 ID。

状态仅有 PASS、FAIL、BLOCKED。未执行、环境降级和证据不足均为 BLOCKED；任一断言 FAIL 则 TC 为 FAIL，没有 FAIL 但存在 BLOCKED 则为 BLOCKED，全部 PASS 才能通过。文件证据只检查路径边界、存在性和非空，不采用截图大小、mtime 或模型语义判断作为廉价防伪。

### 5. 审查以任务 Base 为基线，完整覆盖未提交改动且不污染 index

实现开始时记录 HEAD SHA 到特性目录 `review-base`。审查时验证该 commit 存在且为 HEAD 祖先，使用 `git diff <base>` 收集 Base 后的已提交、staged 和 unstaged 已跟踪改动；相关未跟踪文本用 `git diff --no-index` 生成标准补丁。

禁止为审查自动 `git add`、`git add -N`、commit 或切换分支。无法纳入的敏感、二进制或超大内容必须标为未审查，不能宣称完整审查。

### 6. 新格式 opt-in，历史产物只读兼容

只有新生成或主动迁移的计划使用 `QA Schema: 1`。无版本标记的历史计划返回 LEGACY，不批量修改 `.scratch` 或历史 handoff。活跃规范、技能和安装模板必须同步，安装器只补齐缺失项，不覆盖已有文档或本地定制。

## 影响评估与收益

### 正面收益

1. 消除 Hooks 反复拦截和自动重试的结构性摩擦，同时保留明确、可测试的阶段检查。
2. 默认新增代理数为零，独立 QA 和并行成本由用户显式选择，不依赖宿主模型价格假设。
3. 逐断言分母与三态结果能阻止“只验入口便整案通过”，并保留阻塞原因。
4. 未提交及新增文本能够进入真实审查，且不会改变用户的 Git 暂存状态。
5. 新格式可逐步采用，历史交付证据无需迁移。

### 代价与边界

- 检查器仍依赖执行者诚实记录命令和证据；结构完整不等于语义真实，人工抽查不可取消。
- Schema 1 需要少量额外 Markdown 元数据，必须通过简洁模板和聚合错误控制格式成本。
- 默认串行可能牺牲部分独立任务的并行速度，但避免共享资源竞争、合并冲突和不可控 Token 放大。
- 旧计划不能用新检查器证明完整性；如需新验证能力，只能在对应特性中显式迁移并重新验收。
