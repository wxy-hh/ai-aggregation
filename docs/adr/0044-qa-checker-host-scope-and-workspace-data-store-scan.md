# 0044. QA 检查器的宿主适用范围与工作区数据存储扫描

* **状态**：已接受
* **日期**：2026-10-31
* **范围**：QA 工作流正本、code-review / implement 技能与安装模板、`tooling/scripts/qa-check.mjs` 与安装模板
* **相关**：ADR-0031（部分取代，见下表）、ADR-0033（修订决策 4，见下表）、ADR-0040、ADR-0035

## 背景

QA 工作流已在 Kimi Code 与 Kiro 上完成过双轴审查，但 `qa-check` 的两项审计写死了 Claude Code 的目录。在 Kimi Code 完成审查的特性上运行 `qa-check review`，转录核验会把本仓库 Claude 会话中的子代理转录当作比对对象，报「原文未出现在任何子代理输出中」，属于误报。Kimi Code 的技能优先级与 Claude Code 相反（项目级覆盖用户级），个人级同名技能只在 Claude Code 中遮蔽项目流程技能。

过程脚本扫描的数据存储名单只含第三方驱动。本仓库 `@repo/db` 直接导出 prisma 客户端，Node 22 起可直接导入 `.ts`，过程脚本以相对或绝对路径导入它即可直连数据库，扫描无法识别。

决策经 /grill-with-docs 逐题拷问，每题由 GPT-5.6 Sol 与 Kimi K3.1 Pro 独立核对后收敛。

## 决策

1. **同名检测不随宿主变化**：逻辑与 `SHADOWED_WORKFLOW_SKILL`（BLOCKED）保持不变，提示补充「在其他宿主运行时同样检查」。它防的是下次在 Claude Code 中执行时流程技能被遮蔽，与当前在哪个宿主运行检查器无关。不检测其他宿主的用户技能目录。
2. **转录核验按审查来源声明适用**：review-report 的审查方式行增加显式宿主字段，写法为 `审查方式：宿主=<宿主名>；<说明>`。声明为非 Claude Code 时跳过转录核验，并输出一条 NOTE 提示人工按审查方式行核对来源；声明为 Claude Code 时照常核验；未声明时沿用原有检查，兼容历史报告。检查器只识别这一种写法。
3. **工作区数据存储包**：从仓库根的 `pnpm-workspace.yaml`（只读取简单列表）或根 `package.json` 的 `workspaces` 字段推导工作区包；`dependencies` 直接包含名单内驱动的包，其包名、子路径及包目录下的相对或绝对导入均判为数据存储模块，与第三方驱动同为不可豁免的 `AUTH_BYPASS_IN_SCRIPT`。只看直接依赖，不沿传递依赖扩散；任务队列与对象存储客户端不在范围内。没有工作区配置时行为不变；解析失败输出 NOTE 并退回基础名单。扫描独立解析仓库根。

## 对既有 ADR 的取代与修订

| 被取代或修订项 | 新决策 | 依据 | 其他选项与代价 |
| --- | --- | --- | --- |
| ADR-0031 §5「只保证 Claude Code」与「明确不做」中的「其他宿主适配」 | 流程仍只保证 Claude Code；检查器中 Claude Code 专用的审计按审查来源声明决定是否适用 | Kimi Code 已完成过完整双轴审查，转录核验在其产物上必然误报 | 按运行环境变量判断：只反映检查器在哪运行，不反映审查在哪完成，普通终端运行时没有信号；实现 Kimi Code 转录核验：再耦合一种非公开转录格式，违背 ADR-0033「转录格式非公开契约」 |
| ADR-0033 决策 4 的数据存储范围（数据库驱动或 BaaS 管理端 SDK） | 增加由工作区推导的、直接依赖数据库驱动的包 | 本仓库 `@repo/db` 可被过程脚本直接导入，现有名单识别不到 | 在检查器中写死本仓库包名：通用检查器出现项目私有名称；同时识别 `redis-cli`、`psql` 等命令行直连：需设计「提及」与「执行」的判定边界，另立题处理 |

宿主声明依据的是产物中的来源声明，不探测运行环境或宿主能力，不属于 ADR-0040 否决的「宿主能力探测配置」。ADR-0040 否决的「增强正则」针对审查原文状态词解析，不涉及过程脚本扫描。ADR-0031、ADR-0033 其余条款继续有效。

## 明确不做

运行环境探测；其他宿主的转录核验；检查其他宿主的用户技能目录；命令行数据存储客户端识别（记入 `docs/plans/qa-workflow-backlog.md`）；任务队列与对象存储客户端识别；沿传递依赖推导。

## 后果

- 在非 Claude Code 宿主完成的审查不再收到误导性的转录 NOTE；审查方式行多一个必填约定。
- 宿主字段是自述，漏写或写错会导致漏检或误导性 NOTE，只决定 NOTE 是否适用，不是审查真实性的凭据。
- 转录核验扫描本仓库全部 Claude 会话，没有绑定特性或会话 ID，可能误报，也可能被其他会话中的相同文本消警，本次不修（记入待办）。
- 工作区推导只覆盖直接依赖数据库驱动的包。过程脚本经应用源码间接导入数据库客户端（例如以相对路径导入依赖 `@repo/db` 的应用模块）不会被识别，属于有意绕过，由人工终审发现；若把依赖已命中包的工作区包也算进去，应用包会整体被判为数据存储模块，误报面过大（记入待办）。
- 检查器增加工作区解析与路径归一化，测试面扩大。
- 本决策只描述机制，不宣称质量收益；效果以下一次真实需求的 dogfood 为证据。
