# 0026. QA 证据绑定、计划冻结与审查完整性

* **状态**：已接受
* **日期**：2026-10-26
* **决策者**：AI 聚合平台工程团队
* **范围**：QA 工作流、审查工具、相关技能与安装模板

## 背景

KB-CHAT-CITE 实现与知识库文档预览缺陷修复两次真实运行暴露了同类失败：检查器只核对格式，执行记录却可用单测、无关命令、自由文本或重复截图证明浏览器场景；修复后还可能沿用旧截图。审查基线曾被手工改写，报告由实现者自查且零发现，交付验证只跑子集却声称全量，认证甚至通过签发令牌或注入 Cookie 绕过。

根因是证据没有绑定原始断言和代码状态，审查缺少独立性与范围完整性。继续增加提示词或 Hooks 不能解决这些事实缺口，反而会增加重复拦截和流程成本。

## 决策

### 1. Schema 3 绑定用例、接缝与证据

新计划使用 Schema 3，每个 TC 声明 `Seam`。browser 的 PASS 必须同时具有该场景截图和 exit 0 的 qa-run 日志，其他接缝至少需要 exit 0 的 qa-run 日志；同一图片不得跨 TC 复用。证据只接受特性目录内文件，不再接受 `command:` / `server:` 自由文本。

Schema 1/2 冻结并按原规则校验，不迁移历史计划。`CURRENT_SCHEMA` 作为当前版本单源，由契约测试守护。检查器聚合同类问题，但通用下一步提示按错误码只完整输出一次。

### 2. 命令证据统一由 qa-run 产生

`qa-run` 不经过 shell 执行命令，记录 argv、HEAD、tree、时间和退出码，并以 `wx` 防止覆盖旧证据。它不提供 `--expect-exit`；负向测试必须写成“断言成立即 exit 0”的命令，避免把预期失败变成流程绿灯。

交付验证命令在规划时声明。review 时核对日志 argv、exit 0、tree 与当前代码一致，审查包也执行相同的新鲜度检查，防止只跑子集或沿用旧结果。

通用工作流直接通过 Node 调用 `qa-run.mjs`。能力必需不等于别名必需：安装器不再注入、修改或要求宿主 `package.json` 的 scripts 别名；项目可自行决定是否保留快捷方式，但通用契约只要求命令可直接由 Node 运行，无 package.json 的纯 Git 仓库亦可正常使用。不采用总控 CLI 或 npx 包装以避免额外侵入。

### 3. 开工冻结计划，修复轮保存同源红绿证据

`review-package init` 同时冻结 `qa-plan.md` 到 `prechange/`。删除 TC、修改 Seam、减少 Covers、改写或删除既有断言、修改或删除交付命令，必须在 `## 计划变更` 记录；追加不受限。检查器保持只读，不重写计划。

已交付特性的修复新建 `QA Kind: fix` 修复轮目录。每个 TC 需要同 argv、早于绿日志且 tree 不同的修复前红日志，证明测试确实捕获过缺陷。非核心小修可不建 qa-plan；一旦建立便遵守上述规则。

### 4. 审查包 v2 消除改写基线的动机

`review-package` 增加 `add`，始终以 base 为前值扩大范围，不修改 Git index。跳过文件记录内容摘要，未变化不计入未审查；范围收窄报 `SCOPE_NARROWED`，并修复中文路径与符号链接处理。

collect 记录开工后新增、继续修改和已提交的范围外改动。属于本任务的文件必须 `add`，其他改动在审查报告 `## 范围说明` 逐项解释；未说明时为 BLOCKED。开工时范围内已有但未 `add` 的改动列为 `preexisting`，不得冒充已审查内容。

### 5. 审查报告与证据审计分离职责

Schema 3 的 Spec 对账和遗留事项移入 `review-report.md`。报告必须写明审查方式、Standards、Spec、证据审计、Spec 对账、三档分流和范围说明；实现者自查为 BLOCKED。宿主提供子代理 ID 时一并记录，供人工复核。

KB-FAQ-PAIR 后续执行进一步证明：只要求报告存在，仍可能被实现者绕过真实技能调用后自行填补。故 `implement` / `implement-spec` 在阶段 5 后必须实际调用 `code-review`，由其负责 collect、独立双轴、报告和三档发现；未实际调用或没有独立结果时保持“待独立审查”，不得凭空生成独立审查报告。主 Agent 可以汇总真实审查返回，但不得改写结论。最终交付命令与机器校验由 QA 工作流负责，不把 `code-review` 扩成 QA 总控。

审查来源按宿主能力核对：优先记录真实技能轨迹或子代理 ID，没有此类标识时记录可定位的独立会话或人工审查者；完全没有独立审查条件时不得宣称完成。通用核心不强制统一 ID、transcript 文件或特定模型，目标是降低跳步概率并支持人工复核，而非宣称机制上绝对防伪。

测试规划按风险核对关键决策的触发条件、排除条件和降级路径，`Covers` 只承担追踪，不等于风险覆盖完整。系统侧结果优先由 api、integration、unit 或 static 证明，browser 断言必须关联本次操作新产生的用户可见结果，不以页面旧文本、按钮可用或固定等待代替目标行为；不机械增加每个 US、P0 或 TC 的用例。

证据审计逐个 TC 对照冻结断言与过程脚本，核对接缝、真实入口、输入事件、注入范围、截图独立性、数值断言和实际目标行为，不只复述“真实有效”。NOTE 处置按变化性质决定：核心实现变化重跑受影响验收，能确认仅为非行为文档变化时记录不重跑理由，无法判断时保持 BLOCKED。TC tree 不一致仍为 NOTE，不改为一律 FAIL，也不按全仓库无关脏文件使证据失效。结构检查不替代这项语义审查。

完整双轴尽量在最终树执行，后续 Standards 受影响只复核 Standards，Spec 或证据受影响只复核 Spec，两边都受影响才同时增量复审。同一 tree、argv、断言与预期结果仅更新日志标签或证据索引时不重复审查代码；非行为文档由 Spec 轻量确认，无法判断时按行为变化处理。报告与证据索引必须指向最终材料，不机械重跑完整双轴。

### 6. 浏览器、探活与门禁规则

服务探活按端口决议范围请求并校验应用标题，不误杀其他进程；本项目可通过 `node tooling/scripts/dev-port.mjs --probe --wait 90` 探活，通用模板不依赖 `dev:probe` 别名。P0 核心链路至少一条从真实入口端到端；注入只构造前置条件并记录，真实交互必须来自真实输入事件。数值阈值在脚本内严格断言，截图不能证明数值。

登录优先使用现有会话、seed 的 `test_user` 或真实注册账号，禁止签发令牌、写库造会话、注入 Cookie。门禁声明降噪；`qa-check review` 的 `结果: PASS` 只称“机器校验通过”，独立审查完成必须以真实 `code-review` 和独立双轴结果为据，人工终审单独认定。最终交付命令与机器校验由 QA 工作流执行，`code-review` 只提供独立审查与三档发现，避免把审查技能扩成 QA 总控。

### 7. 成本边界不变

不新增 Hooks、截图语义识别、scope.json 摘要防伪、浏览器脚本启发式扫描、强制独立规划、自动选择或升级模型。不新增通用总控 CLI、npx 包装、全局 scripts 别名注入或新 npm 依赖。默认 inline 和串行实现，独立规划与并行仍需用户显式选择。模型内部行为不可见不靠 Hooks 解决，工作区事实由 Git 范围、证据文件、独立审查与人工抽查暴露；本地检查器不替代语义真实。

### 8. 独立结果交接与合法暂停（2026-10-27 补充）

独立审查指独立上下文，不要求另开用户会话或物理并发。宿主支持时前台串行调用只读 Standards / Spec 审查者，主 Agent 只机械汇总真实独立审查返回，保留原发现、来源与三档结论；实现串行不排斥这项必要审查。主 Agent 写入报告本身不等于独立审查，没有真实独立输入时不得生成独立结论。

宿主完全没有独立上下文能力时，collect 后只交付待审查材料包并合法暂停，不运行最终 `qa-check review`，由独立会话或人工接续，不自动重试或提出 commit。保留 `qa-check` 的 0/1 退出码与 `结果: PASS`，不引入 `exit 2`。review 的 PASS 仅表示审查材料结构、交付日志、tree 与范围完整性通过，不证明独立来源、不判断证据语义、不构成交付授权；真实性由执行轨迹与人工核对。

全局规则只维护真实 `CLAUDE.md`，`AGENTS.md` 保持既有入口引用。浏览器过程脚本的关键预期必须具有硬断言与失败非零退出；环境无法验证 DOM、真实交互或移动几何时记 BLOCKED 或经计划变更转人工，不用低接缝证据替代 browser。发布验收另以真实 dogfood 检查默认 `/implement` 的独立审查调用与无能力暂停路径，不用工具测试或手动派发 reviewer 冒充。

## 讨论记录

- 主控提出接缝证据、冻结计划、范围外改动和修复轮约束；k3.1-pro 与 gemini 经两轮讨论形成一致方案。
- 采纳 k3.1-pro 的 init 冻结、同源红日志、严格数值断言和交付命令预声明；采纳 gemini 的截图跨 TC 判 FAIL、一键探活与范围收窄报错。
- 驳回就地修改 Schema 2、把共享截图降为 NOTE、设置 `--expect-exit`、机械校验 Standards 文件覆盖或 Spec `path:line`，以及默认 Hooks 和额外代理，理由分别是破坏兼容、削弱证据、混淆负向测试、增加无效成本。

## 与 ADR 0023 / 0024 的关系

ADR 0023 §4 的 `command:` / `server:` 证据仅对 Schema 1/2 保留，Schema 3 不再接受。ADR 0024 §4 的 Schema 2 审查产物规则继续适用于旧计划；新计划使用本 ADR 的 Schema 3 报告结构。`review-base` 仅作为无 `scope.json` 时的兼容回退，不再是新流程首选基线。

## 影响、代价与边界

执行者需要在开工时建立基线、真实运行命令并保存证据，审查者需要独立完成证据审计。增加的文件和步骤用于换取可重跑、可对照的交付事实，不以格式完整替代语义真实。

qa-run 日志、审查方式和截图仍可能被伪造；scope.json 摘要也不承担防伪职责。最终保障来自独立审查、人工抽查和可重跑检查器，而不是宣称工具可以彻底杜绝造假。
