# 0064. 个人远程 MCP 扩展的受控边界与审批信任模型

* **状态**：已接受
* **日期**：2026-11-24
* **范围**：个人 MCP Server 配置、远程传输与连接生命周期、工具定义快照、工具白名单、审批与出站安全、MCP 调用审计及验收边界
* **相关**：`docs/prd/04-prd-mcp-integration-governance.md`、ADR-0008（工具执行管道）、ADR-0041（受控写操作与人机协同审批协议）、`docs/features/2026-10-02-chat-agent-webhook-tools/spec.md`

---

## 背景与问题

原 PRD 同时包含普通用户远程接入、管理员 Stdio、长连接池、完整管理平台和 MCP 专属审批状态，超出了既有调研提出的「接入 1–2 个 MCP 工具并复用现有治理管道」垂直闭环。代码现状则是：用户 Webhook 为私有配置；审批在卡片下发后正常结束流，确认通过新请求恢复，拒绝不自动调用模型；工具管道只有运行级连败熔断，没有 Server 级或跨运行熔断。

2026-11-24 经逐项拷问，确认一期目标不是通用 MCP 管理平台，而是一个可真实验收、明确披露残余风险的个人远程 MCP 垂直闭环。本决策记录其难以逆转的归属、信任与协议边界；具体字段、接口和测试冻结断言由后续 spec 定义。

## 决策

### 1. 私有远程配置，限定协议能力面

- MCP Server 配置归属于登录用户本人，不做平台共享或管理员统一分发；每用户最多 10 个 Server 配置。
- 一期只支持远程 **Streamable HTTP**，只覆盖 `tools/list` 与 `tools/call`。旧版 HTTP+SSE 不纳入兼容范围。
- 明确排除 Stdio、本地子进程托管、resources/prompts、自动 OAuth、Server 市场与自动意图筛选。Stdio 若在平台主机执行，管理员权限本身并不构成容器隔离，不能据此宣称生产安全。
- 认证只支持无鉴权或一个静态鉴权头，沿用加密存储、失败关闭与永不回显原则；完整 OAuth 授权、刷新令牌和回调属于独立身份子系统。

**代价**：不能宣称支持本地文件系统、旧版 SSE 服务或通用 MCP 生态；只支持交互式 OAuth 的服务也无法接入。

### 2. 按运行管理连接，以人工刷新的快照为运行依据

- 不建设全局长连接池与心跳。工具发现使用独立连接；同一 Agent 运行内复用 MCP 客户端，运行结束、失败、中止或审批暂停时可靠关闭。审批恢复按 ADR-0041 属于新运行，另建连接。
- 添加 Server 和用户主动刷新时执行 `tools/list`，保存经过大小与结构校验的工具定义快照。Agent 运行只读取该快照，不在每次运行重新发现，也不后台同步。
- Server 配置可以先于成功发现保存；发现失败是可编辑、可重试的状态，但没有有效快照和已启用工具时不得进入 Agent。
- 新发现工具默认不进入白名单；用户显式启用后才可以挂载，所有 Server 合计最多 8 个。发现数量可以超过 20，快照另受工具数与总字节安全上限，超限拒绝整次刷新，不静默截取。
- SessionToolOverride 只能进一步收窄白名单，不能绕过全局配置扩大；CapabilityPack 对用户 MCP 工具沿用 ADR-0041 中 Webhook 的既有边界。

**代价**：首次配置需要手动选择与刷新；上游 Schema 变化不会自动生效，旧快照可能导致调用失败。每次运行会产生建连开销。换来的是工具定义不会在用户不知情时进入上下文，也不需要处理跨请求连接缓存、多实例粘滞和旧凭证驻留。

### 3. 默认审批，自动执行是数据出站信任而非只读证明

- 新 MCP 工具默认必须审批，只有用户显式设置为允许自动执行后才可跳过卡片。工具名称关键词和服务方注解最多作为展示信息，不参与安全放行。
- 「允许自动执行」表示用户信任该工具把模型生成的参数发送到指定外部服务；它不表示工具只读、无数据泄漏风险或内容可信。
- 复用 ADR-0041 的暂停与恢复协议：审批卡片下发后正常结束流；确认通过新请求直接执行原调用；拒绝只落盘，下一轮历史可见，不自动发起模型降级请求。不改变 Webhook 的既有审批语义。
- 审批展示未经改写的完整参数并设置硬上限，超限拒绝发起审批，不得截断后批准。Server 鉴权头不属于工具参数，永不下发。
- MCP 审批凭证还需覆盖工具快照与安全配置版本；URL、鉴权、Schema 快照、启停状态或审批策略变化后，旧审批一律失效。
- 工具描述、Schema 与返回内容都视为不可信数据，进行大小限制并经过现有工具结果合规检查。一期不新增 MCP 专属污点模式，也不宣称提示注入已被消除；全局外部内容污点治理如需推进，应另立跨工具专项。

**代价**：新工具默认有更多确认点击；拒绝后仍需用户再开口；配置变更会使待审批操作失效。完整审批参数可能包含敏感值，并会进入当前用户的审批卡片和本地会话快照，这是已接受的知情审批代价，不构成自动脱敏保证。不可信输出仍可能诱导模型，已自动放行的后续调用存在残余风险。

### 4. 出站、Schema 与结果均使用有界边界

- 远程 MCP 仅允许 HTTPS，禁止重定向；保存/刷新和后续实际建连均须执行 SSRF 防护，连接级 DNS 校验覆盖私网、回环与元数据地址，不提供生产 localhost 例外。
- 工具参数保留 **JSON Schema 2020-12** 为契约，通过标准校验器接入现有注册表，不做有损的 Zod 等价转换。禁止自动抓取远程 `$ref`，并限制 Schema 大小、深度与校验预算。
- 一期只把文本与 structuredContent/JSON 回注模型；图片、音频和嵌入资源不自动下载或进入上下文。原始响应设置硬上限，之后沿用进模型与前端摘要的两级截断。
- 新增 MCP 专属元数据审计，记录用户、Server、工具、域名、快照版本、结果、耗时、响应大小与错误类别；覆盖真实调用、待审批和安全拦截，不保存原始参数、结果、鉴权信息或 URL 查询串。

**代价**：本地 HTTP 服务不能直接作为生产形态演示；部分多模态 MCP 结果不受支持；审计不能单独用于完整载荷重放。注册表需要增加原生 JSON Schema 校验接缝。

### 5. 复用运行级保护、计费口径与受控验收服务

- 单工具继续沿用 15 秒超时和现有运行级连败熔断，不新增 Server 级或跨运行熔断，不承诺「0ms 快速失败」。
- MCP 调用包含在 chat-agent 一口价内，沿用现有模型请求预留/结算生命周期，只补充调用次数、耗时与结果元数据，不新增按工具计费账务。
- 主验收使用官方 SDK 构建的受控 Streamable HTTP 测试 Server，以 HTTPS 和静态鉴权部署，提供确定性读、写和延迟场景。第三方公共 MCP 兼容性可作为补充证据，但不作为一期发布门禁。

**代价**：一个不稳定 Server 可能触发整个运行终止，下个运行没有跨请求熔断记忆；受控测试服务不能证明对 GitHub 等第三方生态的广泛兼容性。

## 后果与不宣称事项

1. 本决策扩展 ADR-0041 到 MCP，不取代其 Webhook 审批决策；「PAUSED_APPROVAL 新终态」和「拒绝后自动模型降级」不进入一期。
2. 不把白名单、超时或审批机制写成已证明能提高任务成功率、工具匹配精度或降低成本；这些质量与性能结论需要可复现对照评测。
3. 不把 HTTPS、HMAC 和元数据审计写成已经解决提示注入、恶意 Server 或数据外发；用户显式信任和残余风险必须在产品及验收材料中可见。
4. Stdio 沙箱、OAuth、跨运行熔断、全局污点管控、多模态结果和第三方生态兼容均需后续独立决策，不从本 ADR 自动派生。
