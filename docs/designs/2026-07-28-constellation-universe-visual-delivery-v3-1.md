# 星座寰宇最终视觉交付附录（V3.1）

## 1. 交付用途与优先级

本附录是《[AI 命理大师 · 星座寰宇最终设计文档](./2026-07-26-constellation-universe-design.md)》的唯一视觉交付附录，只定义该模块右侧内容区的可开发状态、组件复用和验收方式。

- 主设计文档是流程、数据、计算边界、范围、隐私与安全的唯一真相来源；本附录不能新增字段、功能、计算口径或阶段范围。
- 旧 V3 图稿和修订过程文档已不作为工作区交付物或开发依据。开发、设计和测试均以这两份最终文档为准。
- 若视觉表现与主设计文档冲突，必须按主设计文档修正视觉表现；不得为保留旧图而改变流程或真值边界。

## 2. 强制复用的壳层与组件

星座寰宇是“AI 命理大师”的第四个同级模块，不是一个独立产品。桌面端与移动端都不得重新生成、改造、隐藏或替代现有系统导航和命理模块导航。

| 区域 | 必须复用 | 星座寰宇允许的改动 |
| --- | --- | --- |
| 桌面最左侧 | 既有 AI STUDIO 系统导航 | 无。 |
| 桌面第二栏 | `apps/web/src/app/destiny/_components/layout/left-nav.tsx` 的“命理大师”模块侧栏 | 在既有列表的“奇门遁甲演化”后新增同规格的“星座寰宇”项。桌面端全称固定为“八字格局精批 / 紫微斗数排盘 / 奇门遁甲演化 / 星座寰宇”。 |
| 桌面最右侧 | `destiny-shell.tsx` 的内容容器、`destiny-result-header.tsx` 的结果页头和既有卡片体系 | 新增星座专属的入口、表单、加载、报告、问答和分享内容。 |
| 移动端 | 既有 AI 命理大师页头、四段模块切换与全局底栏 | 短标签固定为“八字 / 紫微 / 奇门 / 星座”；只替换当前模块的内容滚动区。 |

桌面壳层的空间关系固定如下：

```text
┌──────────────┬────────────────────────┬──────────────────────────────┐
│ AI STUDIO    │ 命理大师模块侧栏        │ 星座寰宇右侧内容区             │
│ 既有系统导航 │ 八字格局精批            │ 入口／表单／加载／结果等状态     │
│              │ 紫微斗数排盘            │ （唯一允许设计变化的区域）       │
│              │ 奇门遁甲演化            │                              │
│              │ 星座寰宇                │                              │
└──────────────┴────────────────────────┴──────────────────────────────┘
```

右侧内容区可用宽度达到 960px 时采用 8:4 主内容／洞察轨布局；低于 960px 时在右侧内容区内折为单列。不得压缩、替换既有两侧栏，也不得出现横向滚动。

## 4. P0 边界

| 类别 | 内容 |
| --- | --- |
| P0 必含 | 入口、两步表单、三档时间精度、无宫位降级、真实四段加载、总览、大三要素或核心要素、本周行动三角、五个生活模块、关键相位、基础星盘点选与等价文本列表、当前记录的手动补时重算、每报告最多三问、脱敏分享、统一历史。 |
| P0 禁止 | 未知时间默认 12:00、AM/PM 分支、三步或长表单、主题多选、精度百分比、当前位置、未采集性别、年度运势、统计图、体系切换、设置、双底栏、完整今天 / 7 天 / 30 天时间线。 |
| 导出边界 | 禁止导出原始出生资料、星盘真值、完整报告或含精确出生时空的文件；允许保存或发送按脱敏规则生成的分享卡。 |
| P1 预留 | 宫位地图、术语百科、完整逐日行运、复杂双向索引与连线动效、资料补全后的自动或推送式提醒。它们不出现在 P0 默认导航、标签、占位入口或禁用控件中。 |

## 5. 右侧内容区状态交付

| 状态 | 阶段 | 右侧内容区块顺序 | 必须复用／状态规则 |
| --- | --- | --- | --- |

| 基本资料 1/2 | P0 | 姓名或昵称 → 阳历日期 → 关注主题单选 → 隐私说明 → 下一步 | 字段级错误在原位呈现；不改变两步骨架。 |

| 宫位地图、近期星运、术语百科、自动补全提醒 | P1 | 仅在 P1 上线后提供相应内容 | 使用同一壳层和右侧内容区，不得提前放入 P0 Tab。 |

## 6. 移动端与无障碍规则

- 表单的“下一步／绘制我的星盘”使用内容区既有 sticky 操作位，并为全局底栏与安全区预留空间；它不是第二条底部导航。
- 结果页不新增固定模块操作栏。“问星语”“分享”“重新测算”遵循其他命理模块的结果阅读态；打开既有底部抽屉时，抽屉覆盖内容并锁定背景。
- 星盘轮必须提供含行星、相位和当前选中项的等价文本清单；关键项可通过键盘到达并具有清晰读屏名称。
- 加载进度、流式结果和字段错误必须以状态区向读屏宣布。抽屉打开后焦点移入抽屉；关闭后回到触发控件。
- 所有主要可点击项的热区不少于 44 × 44；图片、星盘和分享卡自适应容器，不产生横向滚动。

## 7. 视觉语言

- 直接复用现有平台的色板 token、圆角、字号阶梯、图标容器、G-3 Hero 玻璃和 Z-4 焦点阴影；不为星座模块新增另一套壳层 token。
- 星座专属视觉只可用于右侧内容内的小面积星体、相位和状态点缀。长文与表单使用高对比实体阅读底，不叠加重玻璃。
- 图标保持既有命理模块的线性风格与容器尺寸；所有用户可见文本使用中文。
