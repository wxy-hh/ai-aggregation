# 多模型聚焦比较对话设计文档

> 状态：设计方案  
> 适用范围：AI 聚合平台「智能对话」桌面端优先，兼顾移动端  
> 关联设计图：[四模型聚焦比较](/Users/weixiaoyu/Desktop/practice/AI-aggregation/docs/designs/chat-four-model-focus-comparison.png)

## 1. 设计目标

当前聊天页以“选一个 Provider，再开始对话”为主路径，用户难以感知平台的聚合价值。本方案将核心心智改为：**同一问题，多模型并发；先看全局，再聚焦比较；选中更好的答案继续工作。**

成功后的用户认知应是：

- 这个平台不是又一个单模型聊天入口，而是帮助我更快判断“哪个模型更适合当前任务”的工作台。
- 选择 3 或 4 个模型不会让页面变成四篇长文的拥挤瀑布流。
- 比较、取舍、继续追问都不会丢失各模型自己的上下文。

### 1.1 设计原则

1. **聚合优先**：新建对话默认进入“并行对比”，单聊是可选的专注模式。
2. **并发与阅读解耦**：最多 4 个模型同时生成，但默认只让 2 篇完整答案同屏阅读。
3. **渐进展开**：所有模型先以状态摘要出现，用户再选择要深读和对照的答案。
4. **分支隔离**：每个模型的多轮上下文独立维护，绝不把 A 模型回复作为 B 模型下一轮的上下文。
5. **故障局部化**：一个模型慢、失败、被取消，都不阻塞另外的结果。

## 2. 页面信息架构

桌面基准画板为 `1600 × 1000`，保留现有“两级侧栏 + 主工作区”的习惯，避免用户重新学习导航。

| 区域 | 建议宽度/高度 | 职责 |
| --- | ---: | --- |
| 全局导航 | 96px 宽 | 首页、智能对话、语音、图像、视频等模块入口；当前高亮“智能对话”。 |
| 会话侧栏 | 280px 宽 | 新建对话、按时间分组的历史会话、搜索入口。比较会话以单个会话记录出现。 |
| 主工作区 | 剩余宽度 | 展示当前问题、模型概览、双列聚焦答案和输入区。 |
| 页面内边距 | 24px | 保持主内容的稳定阅读宽度。 |

主工作区自上而下由六个区块构成：

```text
页头：标题、单聊/并行对比切换、已选模型数、价值提示
  ↓
共享问题：本轮唯一的用户 Prompt
  ↓
模型概览轨道：所有已选模型的状态摘要与替换操作
  ↓
比较工具栏：阅读列数、差异高亮、按模型查看、全屏
  ↓
双列答案区：当前聚焦的两份完整回答
  ↓
输入区：已选模型 Chip、附件/参数入口、同时发送
```

## 3. 页面构成与视觉规格

### 3.1 页头

页头包含以下元素：

- 标题：`对比对话`。
- 分段控制器：`单聊` 与 `并行对比`，默认选中后者。
- 模型选择器：`已选 4 个模型`，点击后打开可勾选的模型列表。
- 价值提示：`4 个模型同时生成，聚焦比较 2 个`。

分段控制器负责改变整条任务链路，而不只是更换页面样式：

| 模式 | 发送行为 | 结果行为 |
| --- | --- | --- |
| 单聊 | 仅向一个已选模型发送 | 使用传统单列消息流。 |
| 并行对比 | 向 2–4 个已选模型并发发送相同输入 | 进入模型概览轨道 + 双列聚焦阅读。 |

### 3.2 共享问题区

每一轮只出现一条全宽用户消息，避免在每个模型列中重复显示 Prompt。

- 视觉：浅蓝信息底色、用户头像、正文一行或多行。
- 示例文案：`为 AI 聚合平台设计多模型对比聊天体验，并说明它为什么值得用。`
- 附件：在问题下方以统一附件条展示；只有兼容该附件类型的模型才会被选中。

### 3.3 模型概览轨道

模型概览轨道是“4 个模型已返回”的状态板，而不是四列答案的缩略图。

每张模型状态卡包含：

- Provider 标识和模型名。
- 状态点：排队、生成中、已完成、已失败、已停止。
- 耗时，例如 `已完成 5.2 秒`。
- 当前是否处于双列焦点中。
- 若未聚焦，提供 `替换左列` 或 `替换右列` 操作。

#### 焦点与替换规则

| 已选模型数 | 概览轨道 | 完整回答区 |
| ---: | --- | --- |
| 2 个 | 两张状态卡均为“正在比较” | 固定双列。 |
| 3 个 | 三张状态卡；其中两张有选中描边 | 双列，第三张可替换任一列。 |
| 4 个 | 四张状态卡；其中两张有选中描边 | 双列，另两张各提供替换入口。 |

替换不是重新请求。它只把已完成或正在流式返回的对应模型结果放进左、右阅读槽位。用户可以随时在 4 个结果间切换，而不会丢失任何结果。

### 3.4 比较工具栏

工具栏位于概览轨道和答案区之间，包含：

- `2 列阅读`：默认模式，保证每列的正文宽度。
- `3 列阅读`：仅在足够宽的桌面屏幕开放，且需要用户主动切换。
- `差异高亮`：对回答中相异的观点、数字、结论或建议做弱强调；不是替用户判定对错。
- `按模型查看`：临时切换到单列纵向阅读，用于长回答深读。
- `全屏`：隐藏两级侧栏，扩大答案阅读区域。

默认不提供“4 列阅读”。四篇完整长文会使行宽不足、对照失焦、滚动成本过高。

### 3.5 双列答案区

双列答案区是整个页面的决策区，每列可独立滚动。

每个答案面板包含：

1. 模型头部：Provider、模型名、状态点、耗时。
2. 回答正文：支持 Markdown、代码块和长文本。
3. 差异锚点：展示如“核心建议”“关键差异”等结构化段落，不要求模型固定输出该格式。
4. 行为栏：`复制`、`收藏`、`重试`、`展开`。
5. 局部状态：流式光标、重试中、失败信息、被截断提醒。

答案卡不采用厚重的彩色侧边条。模型身份通过顶部标识、轻量颜色和明确文本表达，保证正文可读性优先。

### 3.6 输入区

输入区固定在主工作区底部，包含：

- 已选模型 Chip：`讯飞星火`、`豆包`、`通义千问`、`DeepSeek`。
- Chip 的状态：已加入、当前聚焦、暂不支持附件、不可用。
- `添加模型`：打开模型选择器，最大选择数为 4。
- 文本输入框和附件入口。
- 发送主按钮：`同时发送`。
- 辅助文案：`4 个模型并发，当前聚焦比较 2 个`。

模型数量改变时，不立即发送。用户必须点击“同时发送”才会开始新的并发轮次，避免误产生多份成本。

## 4. 核心交互逻辑

### 4.1 新建比较会话

```mermaid
flowchart LR
    A[新建对话] --> B[默认并行对比]
    B --> C[选择 2 至 4 个模型]
    C --> D[输入共享 Prompt]
    D --> E[同时发送]
    E --> F[并发流式请求]
    F --> G[模型概览轨道更新]
    G --> H[双列聚焦比较]
```

规则：

- 最少选 2 个模型才允许进入并行对比。
- 最多选 4 个模型，避免成本、延迟和信息密度失控。
- 新建会话默认沿用上一次的模型组合；首次使用推荐讯飞星火 + 豆包。
- 切换到单聊时保留已选模型组合，但要求指定其中一个作为当前模型。

### 4.2 并发发送与流式返回

发送后，前端为每个模型创建独立请求、独立 AbortController 和独立流式状态。结果不以最慢模型为准，而是分别更新：

| 模型状态 | 概览轨道 | 答案面板 |
| --- | --- | --- |
| 排队中 | 灰色状态点、`等待发送` | 若已被聚焦，显示骨架屏。 |
| 生成中 | 蓝色状态点、已用时间 | 实时追加正文并显示流式光标。 |
| 已完成 | 绿色状态点、总耗时 | 渲染 Markdown 和完整行为栏。 |
| 失败 | 红色状态点、失败原因 | 显示 `重试该模型`，不影响其它列。 |
| 已停止 | 灰色状态点、`已停止` | 保留已生成内容，允许续写或重试。 |

技术边界：复用现有 `/api/chat`，由 UI 层依据已选模型发起多条并发请求；不需要为“比较”新增 Provider 接入。

### 4.3 焦点替换

当已选 3 或 4 个模型时，用户点击某个非焦点状态卡的 `替换左列` / `替换右列`：

1. 目标模型保留原有的生成结果与状态。
2. 对应的左、右阅读槽位立即切换为目标模型。
3. 被替换的模型回到概览轨道，不删除、不取消。
4. 工具栏和行为栏随当前两个焦点模型刷新。

如果目标模型仍在生成，则新列立即显示其当前流式内容；无需等待全部完成。

### 4.4 差异高亮

差异高亮的目的不是生成“裁判结论”，而是降低人工对照成本。

- 开启后：以低饱和蓝色底色标出不同的标题、数字、结论和行动建议。
- 关闭后：两列恢复普通阅读样式。
- 对没有可可靠对齐的长自由文本：不强行逐字 Diff，而只保留段落级提示。
- 未来可扩展“一句话差异摘要”，但不作为首版的必要条件，避免引入额外模型调用。

### 4.5 多轮追问与分支

多轮是比较体验最容易出错的部分。每个模型必须维护独立上下文：

```text
用户问题 P1
├── 讯飞分支：P1 → A1 → P2 → A2
├── 豆包分支：P1 → B1 → P2 → B2
├── 通义分支：P1 → C1 → P2 → C2
└── DeepSeek 分支：P1 → D1 → P2 → D2
```

- 点击“继续比较”：将新的用户问题分别追加到各模型自己的分支后再并发发送。
- 点击“拿来继续”：以某一模型的当前分支创建或进入单聊子会话。
- 不允许将一个模型的答案直接作为另一个模型的隐藏上下文；如用户需要融合，应显式选择“合并为新 Prompt”。

### 4.6 单模型重试与停止

- `重试`：只重新发送该模型当前轮的分支上下文。
- `停止`：只终止该模型的 AbortController，不影响其它模型。
- `重试全部`：只在全部模型失败或用户明确选择时提供。
- 错误提示必须显示模型名和可操作的下一步，例如“豆包暂时不可用，重试该模型”。

## 5. 数据与状态建议

比较模式不能复用单一 `messages + provider + model` 状态结构，应以“会话 → 轮次 → 模型分支”组织：

```ts
type ComparisonMode = 'single' | 'compare';

interface SelectedModel {
  provider: string;
  model: string;
  label: string;
  capabilities: {
    attachment: boolean;
  };
}

interface ModelRun {
  modelKey: string;
  status: 'queued' | 'streaming' | 'completed' | 'failed' | 'stopped';
  startedAt?: number;
  completedAt?: number;
  content: string;
  error?: string;
  branchMessages: Array<{ role: 'user' | 'assistant'; content: string }>;
}

interface ComparisonTurn {
  id: string;
  prompt: string;
  runs: Record<string, ModelRun>;
  focusSlots: {
    left: string;
    right: string;
  };
}
```

关键约束：

- `focusSlots` 只影响 UI 呈现，不影响请求、结果缓存或历史存储。
- 每个 `ModelRun` 有自己的加载、错误和取消状态。
- 历史会话以一个比较会话保存；展开后可看到每一轮和每个模型的分支结果。

## 6. 附件、成本与权限边界

### 6.1 附件兼容性

- 比较模式只允许选择都支持当前附件类型的模型。
- 如果模型集合中有不支持附件的模型，发送前直接说明原因，并提供“移除该模型”或“移除附件”操作。
- 不允许静默丢弃附件后继续发送。

### 6.2 成本提示

并发模型数直接影响调用量。建议在模型选择器和发送按钮附近展示轻量提示：

- `将同时调用 4 个模型`。
- 如存在计费策略，显示预估或实际消耗入口。
- 选择 4 个模型时不增加恐吓式确认弹窗，但应让成本可见。

### 6.3 权限与限流

- 无权限或配额耗尽的模型不应阻塞其它模型。
- 概览卡显示“不可用”并提供原因说明。
- 当可选模型不足 2 个时，自动切回单聊并解释原因。

## 7. 响应式与移动端

移动端不强行并排两篇长文，采用“保持比较、改变阅读容器”的方式：

| 屏幕范围 | 布局策略 |
| --- | --- |
| ≥ 1440px | 默认双列；用户可开启三列阅读。 |
| 1024–1439px | 默认双列，压缩左侧历史栏或收起。 |
| < 1024px | 隐藏桌面侧栏，模型概览轨道横向滚动。 |
| < 768px | 完整答案改为模型 Tab / 左右滑动卡片；顶部固定显示 `正在比较 2/4`。 |

移动端交互要求：

- 模型状态轨道可横向滑动，但当前焦点模型始终可见。
- 输入区固定在底部安全区上方，发送按钮不小于 `44 × 44px`。
- 切换模型使用底部抽屉，不在狭窄屏幕展开大面积下拉菜单。
- 长回答只有一个主滚动容器，避免聊天列表、答案卡、页面三层嵌套滚动。

## 8. 无障碍与可用性

- 所有模型状态不能只靠颜色区分，必须带有文字如“生成中”“已完成”“失败”。
- 键盘焦点顺序：模式切换 → 模型选择 → 概览轨道 → 工具栏 → 左列答案 → 右列答案 → 输入区。
- 左右答案卡提供清晰的标题和模型名，方便读屏软件定位。
- 差异高亮需满足足够对比度，不能用纯浅色背景承载低对比文本。
- “替换左列/右列”必须用明确操作文案，不能只有图标。

## 9. Figma 交付结构

Figma 中建议保留以下可编辑层级与原型帧：

```text
四模型聚焦比较
├── Desktop / 默认双列（讯飞星火 + 豆包）
├── Desktop / 替换左列（通义千问 + 豆包）
├── Desktop / 替换右列（讯飞星火 + DeepSeek）
├── Desktop / 按模型查看
├── Mobile / 模型 Tab 比较
└── 组件与标注
    ├── 模型状态卡
    ├── 焦点答案卡
    ├── 模型 Chip
    └── 状态与异常说明
```

首批原型连线：

- `通义千问 → 替换左列`：进入“通义千问 + 豆包”状态。
- `DeepSeek → 替换右列`：进入“讯飞星火 + DeepSeek”状态。
- `按模型查看`：进入单列深读状态。
- `单聊`：进入单模型消息流状态。

## 10. 验收清单

- [ ] 新建对话默认可见“并行对比”，而非先选择单个 Provider。
- [ ] 用户可选 2–4 个模型，并一键发送同一 Prompt。
- [ ] 4 个模型同时返回时，页面默认只展示 2 篇完整回答。
- [ ] 第 3、4 个模型可在不重发请求的前提下替换左列或右列。
- [ ] 每个模型都能独立流式、停止、失败、重试。
- [ ] 多轮追问不会混用不同模型的上下文。
- [ ] 移动端保持比较能力，但不硬塞双列长文。
- [ ] 所有状态、错误和操作都有中文、可理解的反馈。
