## 1. 结论摘要

星座寰宇不是一个只给出“太阳星座性格标签”的轻量页面，而是命理大师中的现代占星入口：以用户的出生时空为基础，先计算可验证的本命星盘事实，再由 AI 将事实翻译成清晰、克制、可行动的个人洞察。

首期聚焦一个完整闭环：

1. 用户从命理大师模块侧栏或移动端分段控件进入星座寰宇。
2. 从唯一入口开始完整本命星盘；出生时间未知时进入明确的可信降级。
3. 填写阳历日期、出生城市及可选的出生时间；出生时间未知时进入明确降级模式。
4. 系统完成时区、地理坐标、星体位置、宫位和相位的确定性计算，并对时间相关事实执行稳定性校验，再生成分区解读。
5. 用户在结果页先获得可计算的核心要素、情感、事业、优势与本周行动建议，再按需深入 P0 的盘轮和关键相位。
6. 用户可就测算结果进行受限追问、生成脱敏分享卡，或从现有统一历史记录重新查看；结果页不提供删除。

核心原则是“先真值，后叙事；先结论，后术语；先当下可用，后深度探索”。这样既匹配星座用户的直觉阅读习惯，也延续八字和紫微模块的专业可信感。

**系统壳层约束**：星座寰宇不拥有系统级名称、侧边导航或个人资料体系。桌面端必须逐像素复用现有 AI STUDIO 左侧系统导航，以及其右侧的“命理大师”模块侧栏；星座寰宇只新增为“奇门遁甲演化”之后的同级第四个模块项，尺寸、选中态、图标容器、文字层级与其他三个模块一致。任何星座页面只替换右侧内容区，不得重绘、隐藏或另建系统导航和命理模块栏。移动端必须复用“AI 命理大师 / AI 聚合工作台”页头、四分段模块切换与底部全局导航。测算结果是内容页，不是报告管理页；查看与删除都归入现有统一历史记录。

## 2. 设计目标与边界

### 2.1 产品目标

| 目标 | 设计回答 |
| --- | --- |
| 让新用户迅速感知价值 | 首屏先给一条人格主线和可计算的核心要素，不要求先读懂完整盘面。 |
| 让结果经得起细看 | 星体、星座、度数、宫位、相位、时区均来自确定性计算，并可展开查看。 |
| 让用户看到与自己有关的内容 | 结果优先回答“我是什么样的人、关系中需要什么、工作如何发挥、这段时间如何安排”。 |
| 在资料不完整时保持诚实 | 没有出生时间时，明确隐藏上升、宫位、天顶等无法可靠计算的内容。 |
| 形成命理模块的统一体验 | 保留现有命理大师导航、表单、报告、历史和模型切换框架，新增占星专属视觉与信息层。 |
| 兼顾移动端 | 将输入、结果和追问放在单列稳定滚动中，核心操作位于拇指易触达区域。 |

### 2.2 非目标

- 首期不把十二星座运势卡片纳入星座寰宇主流程；若未来需要低输入成本内容，应作为独立“每日星象”能力重新立项。
- 首期不提供医学诊断、投资建议、绝对化婚恋结论或时间点承诺。
- 首期不以 AI 自行推算星盘为依据；AI 不得改写星体位置、宫位和相位事实。
- 首期不制作关系合盘、择日、塔罗、真人咨询市场、体系切换、高级设置、年度运势、元素或模式统计等扩张功能。

### 2.3 成功标准

产品成功不以“文本越长越好”衡量，而以用户是否能在首次结果页完成以下三个判断衡量：

- 我是否被准确、具体地描述，而非看到任何星座都适用的空话。
- 我是否知道近期最值得注意的一到两个主题。
- 我是否知道下一步可以做什么，例如深入看感情、职业，或提出一个具体问题。

建议在上线后跟踪：完成测算率、结果页首屏停留、二级内容展开率、追问发起率、历史回看率、分享率、出生时间未知用户的完成率，以及“有帮助 / 不准确”反馈原因。

## 3. 目标用户与需求优先级

| 用户类型 | 核心诉求 | 关键设计回应 |
| --- | --- | --- |
| 占星入门用户 | 想快速理解自己的性格、感情和近期状态 | 完整本命盘中的易懂结论、术语翻译与可展开依据。 |
| 有出生资料的探索者 | 想看比太阳星座更准确的完整星盘 | 大三要素、星盘轮、关键宫位与相位、可追溯事实。 |
| 深度爱好者 | 关心度数、宫位、相位、行星落点和体系口径 | 默认呈现结论，提供“盘面依据”和术语百科展开。 |
| 出生时间不确定的用户 | 害怕因资料不全得到错误结果 | 明确“不知道时间”分支、可信度标记和不确定内容的隐藏。 |
| 移动端用户 | 希望一只手完成输入与浏览 | 分步录入、底部固定主操作、结果页单列与安全区适配。 |

## 4. 产品定位与信息架构

### 4.1 在命理大师中的位置

AI 聚合工作台中的“AI 命理大师”保留四个并列方法，分别解决不同的“我想知道什么”。桌面端固定保留现有左侧系统导航和紧邻的命理大师模块侧栏；星座寰宇固定在奇门遁甲演化之后，作为与八字、紫微、奇门完全同规格的第四个模块项。右侧内容区随模块切换，导航壳层不变。移动端在现有顶部模块分段中增加第四项“星座”，不新建独立产品导航。

| 方法 | 主要输入 | 最适合回答 | 星座寰宇的区别 |
| --- | --- | --- | --- |
| 八字格局精批 | 农历或阳历出生信息、地点、性别 | 人生结构、五行、阶段趋势 | 星座寰宇采用现代占星的本命盘语言，强调心理动机、关系模式与行运节律。 |
| 紫微斗数排盘 | 出生信息、地点、性别 | 十二宫与人生领域 | 星座寰宇以行星、星座、宫位、相位构成可交互的圆形星盘。 |
| 奇门遁甲演化 | 起局时空与所问之事 | 某个具体问题当下的推演 | 星座寰宇围绕用户的长期本命底色与当前天象，不依赖一个单独问题。 |
| 星座寰宇 | 阳历出生日期、出生城市、可选出生时间 | 性格内核、亲密关系、职业表达与本周行动 | 以“本命盘真值 + 生活语言”降低进入门槛。 |

### 4.2 三级信息架构

1. **立即可懂层**：一句宇宙主题、可计算的核心要素、三个最重要的生活结论、本周行动提示。
2. **个人洞察层**：情感关系、事业表达、优势天赋、情绪触发点、本周行动三角。
3. **专业盘面层**：星盘轮、行星落点、十二宫、关键相位、计算口径、术语百科。

该层级避免把复杂的盘面术语作为第一屏门槛，也保证爱好者不需要离开报告寻找依据。

## 6. 页面与流程详细设计

### 6.1 命理导航入口

**位置**

- 桌面端保留最左侧既有 AI STUDIO 系统导航及其右侧既有“命理大师”模块侧栏；在“命理分析类别”中新增第四项：星座寰宇。
- 移动端顶部四段式切换为：八字、紫微、奇门、星座。标签保持短文案，四项等宽，不以图标替代文字。
- URL 采用 tab=astrology；统一历史记录按命理模块键恢复该次结果，不新建“报告中心”。

**入口卡信息**

- 图标：沿用既有命理模块的图标容器、线性图标尺寸和选中态；内容图形采用简洁星盘线稿，不使用黄道十二宫字符堆叠。
- 标题：星座寰宇。
- 说明：本命星盘 · 关系与星运。
- 激活色：从深空蓝到星云紫，沿用平台蓝紫体系，避免另立品牌色。

**为什么这样设计**

四个模块保持同级，用户不需要理解术数差异才知道去哪里。标题不使用“占卜”作为导航词，是为了传递结构化、可解释的专业定位；“关系与星运”则让用户快速理解收益。

### 6.2 星座寰宇首页与单一入口

首页只在该模块首次进入或用户点击“重新测算”时展示。它不是模式选择页，而是完整本命星盘的价值说明与唯一开始入口：桌面端内容区使用左侧解释文案、右侧星盘线稿；AI 命理大师模块栏始终保留。移动端纵向排列，并把主操作保持在首屏拇指区。

| 区域 | 展示内容 | 交互与规则 |
| --- | --- | --- |
| 页面标题 | 星座寰宇；副标题“以出生时空绘制你的本命星盘” | 标题使用现有页面级视觉规格，副标题不超过两行。 |
| 宇宙说明 | “星体位置为计算结果，解读由 AI 生成”；“用于自我探索与娱乐参考” | 点击“了解计算方式”打开轻量抽屉。 |
| 唯一核心卡 | 绘制你的完整本命星盘；根据资料精度呈现核心要素、关键相位与本周行动提示 | 唯一主按钮“填写出生资料”，进入两步出生资料表单。 |
| 时间未知提示 | “不知道出生时间也可以继续” | 明确说明将隐藏上升、天顶、十二宫及宫位依赖结论；不是另一种服务。 |
| 最近记录 | 最近一次报告的模块名、报告标题、生成日期、低敏摘要、继续查看 | 有记录才展示；不显示生日、城市、精确时间或度数，不抢占首屏。 |

**入口定义**

星座寰宇 V1 只有完整本命星盘这一个产品闭环。阳历日期与精确出生城市为必填；出生时间可选。出生时间未知仍进入同一报告结构，但以数据精度决定哪些模块可见。

| 出生资料状态 | 可输出内容 | 不可输出内容 |
| --- | --- | --- |
| 时间准确到分钟 | 大三要素、宫位、稳定的相位、事业、关系、本周行动三角 | 无。 |
| 大约时段 | 所有经时段稳定性校验的星座、度数、相位、角点、宫位及依赖结论 | 未通过稳定性校验的任何时间相关事实及其解读。 |
| 时间未知 | 太阳，以及在出生城市当地日期区间内稳定的行星星座、关键相位、性格与关系主题 | 上升、天顶、十二宫、宫位依赖结论，以及不稳定的月亮、行星度数、相位和相应解读。 |

时间未知是完整本命盘中的可信降级，不应该被伪装成“完整盘面”。
### 6.3 出生资料输入

采用两步式输入，而不是把所有字段置于一个长表单。桌面端使用左右两列实体内容卡；移动端按顺序单列展示。表单主操作使用内容区既有的 sticky 操作位，预留全局底栏高度与安全区；它不是第二条底部导航。

#### 第一步：身份与出生日期

| 字段 / 元素 | 设计要求 |
| --- | --- |
| 姓名或昵称 | 可选，用于报告称呼；默认占位“例如：小宇”。不要求真实姓名。 |
| 阳历出生日期 | 必填，日期选择器默认阳历；文案明确“现代占星以阳历生日计算”。 |
| 关注主题 | 可选单选：认识自己、感情关系、事业方向、近期状态；用于排序报告而非改变盘面。 |
| 隐私提示 | 表单底部写明“出生资料仅用于本次星盘计算与统一历史记录中的该条结果，可在历史记录删除”。 |
| 预览条 | 日期填写后即时显示太阳星座及日期范围，例如“你的太阳星座：天秤座”。只显示确定事实，不提前生成性格评价。 |

#### 第二步：出生时间与地点

| 字段 / 元素 | 设计要求 |
| --- | --- |
| 时间精度 | 固定为“准确到分钟 / 大约时段 / 完全未知”三档。出生日期已必填，“只知道日期”不构成第四档。 |
| 出生时间 | 准确到分钟时使用时、分选择器；大约时段时选择可计算的时间区间；完全未知时不填时间。时间选择器不默认当前时刻、12:00 或任何推测值。 |
| 约时稳定性 | 原始时段必须保存。计算域对所有时间相关事实执行区间稳定性校验；仅展示稳定的星座、度数、相位、角点、宫位和依赖结论。不稳定时按无宫位范围降级，并标注“约时，部分盘面范围不稳定”。 |
| 出生地点 | 支持全球城市搜索，选中后保存城市、经纬度和 IANA 时区；禁止仅以国家名或当前位置作为精确出生地。 |
| 时区校验 | 根据日期和城市计算历史夏令时；展示“{城市} · {IANA 时区} · {YYYY 年当地时间}”的可读确认，历史换算细节在“盘面依据”中展开。 |
| 资料影响提示 | 以可展开说明显示：“时间影响上升、宫位与天顶；不知道时间时，我们不会生成这些内容。” |
| 操作区 | 主按钮“绘制我的星盘”；次按钮“返回上一步”；最小点击区域 44 × 44。 |

**表单即时反馈**

- 城市未精确匹配时，不允许以模糊文本发起完整星盘；提示用户从候选列表中选择。
- 出生时间未知时，提交按钮仍可用，按钮旁显示“将生成无宫位本命盘”。
- 校验错误只在对应字段下反馈，不改变两步表单骨架，不增加确认页或单页长表单。
- 日期非法或未来日期即时在字段下反馈；错误文案用中文说明如何修正。
- 测算期间所有会改变计算事实的字段禁用，但页面保留已填信息，避免用户以为数据丢失。

**为什么这样设计**

出生时间是占星精度最大的变量。让用户可选择“不知道”，比强迫输入或静默默认为 12:00 更可靠。可选昵称与清晰隐私说明降低敏感信息的输入阻力；把“关注主题”作为阅读排序而非计算变量，既个性化又不损害计算可信度。

### 6.4 星盘校准与加载页

加载页不是装饰动画，而是把不可见的专业步骤变成可理解的进度。

| 顺序 | 状态文案 | 后台任务 | 前台表现 |
| --- | --- | --- | --- |
| 1 | 系统正在校准出生地与当地时区 | 坐标、时区、历史夏令时解析 | 地图针与时区信息淡入。 |
| 2 | 系统正在定位行星与月亮 | 计算太阳、月亮、行星黄经与逆行状态 | 星点依次点亮，显示简洁骨架。 |
| 3 | 系统正在绘制十二宫与关键相位（含宫位）／系统正在整理行星位置与关键相位（无宫位） | 计算相位；仅在含宫位结果中计算上升、天顶与宫位；随后执行稳定性校验 | 星盘轮从中心向外展开，或呈现无宫位行星盘。 |
| 4 | AI 正在基于星盘事实整理宇宙重点 | 以结构化真值请求解读 | 先展示结果页骨架与“核心要素”占位。 |

交互要求：

- 每个状态应基于真实完成事件推进，不设置虚假的固定百分比。
- 确定性真值完成即创建或更新统一历史记录，状态为“解读整理中”；AI 解读完成后更新同一条记录。
- 超过合理等待时间时，显示“解读仍在整理，可继续等待或稍后从历史查看”；保留真值、错误状态与重试入口。重试只重新请求 AI 解读，不重算已锁定的真值。
- 完成确定性星盘后，可以先渲染星盘轮和事实卡，再流式填充解释文本。
- 动画尊重系统的减少动态效果偏好；低性能设备退化为静态进度点。

### 6.5 结果页总览

结果页采用“先生活语言、后专业证据”的顺序。右侧可用内容宽度达到 960px 时，桌面端使用 12 栏响应式网格：主内容 8 栏、右侧洞察轨 4 栏；不足 960px 时在右侧内容区内折为单列。既有系统导航与命理大师模块侧栏不缩窄、不替换，页面不得产生横向滚动。长文本区域使用实体背景，只有外层英雄容器使用玻璃质感。

#### 首屏组成

| 区域 | 用户看到的信息 | 目的 |
| --- | --- | --- |
| 宇宙护照头 | 昵称、出生资料摘要、地点、时间精度标签、计算时间；可展开“盘面依据” | 让用户确认报告确实属于自己，并可校验输入。 |
| 一句主轴 | 18 至 28 字的核心主题，例如“在稳定与自由之间，练习把感受说清楚。” | 先给最可记住的个人结论。 |
| 大三要素／核心要素 | 时间准确或稳定约时时展示太阳、月亮、上升三张卡；时间未知或不稳定约时时将标题切换为“核心要素”，只展示可计算且稳定的要素，并以独立“资料范围”提示说明已隐藏内容 | 命中用户最熟悉、最关心的占星语言，同时不把未知事实伪装成待定事实。 |
| 星盘轮 | 交互式圆形本命盘；点击任一可见星体、稳定宫位或关键相位，右侧或底部出现关联事实 | 建立专业感与探索感，不把它变成阅读门槛。 |
| 本周宇宙提示 | 一项机会、一项留意、一项行动；标明时间范围与依据的行运 | 回答“我现在该关注什么”。 |

#### 用户最关心的五个结果模块

| 排序 | 模块 | 必须展示 | 表达方式 |
| --- | --- | --- | --- |
| 1 | 我是谁 | 核心气质、内在情绪、外在表达；对应太阳、月亮、上升 | 三段短结论 + 一个“你可能会这样表现”的真实场景。 |
| 2 | 关系如何运作 | 亲密需求、沟通偏好、冲突触发点、可练习的关系动作 | 金星、火星、月亮、七宫或其降级依据；不能断言“何时结婚”。 |
| 3 | 事业如何发挥 | 优势场景、工作动机、协作方式、一个本周期行动 | 十宫、天顶、水星、太阳及相关相位；时间未知时清楚切换为非宫位结论。 |
| 4 | 我的优势与盲点 | 三项天赋、一项高频消耗模式、边界提示 | 用“倾向 / 可能 / 值得观察”而非命定措辞。 |
| 5 | 本周宇宙提示 | 一项机会、一项留意、一个行动；含本周时间范围和依据行运 | P0 只提供结果首屏的一周摘要，避免承诺连续行运服务。 |

每个模块的默认正文不超过 120 字，并配 2 至 3 个短标签。P0 中用户点击“展开依据”后，只显示对应的已确认星体、星座、宫位或相位事实与位置；完整术语百科在 P1 提供。

### 6.6 深度探索区

P0 深度区只提供“星盘轮”和“关键相位”两个页内标签；不新开一串难以返回的页面。宫位地图、近期星运和术语百科的标签名称已预留给 P1，但在 P0 中不显示为标签、占位入口或禁用控件。

| 标签 | 阶段 | 信息内容 | 关键交互 |
| --- | --- | --- | --- |
| 本命总览 | P0 | 结果总览、五大生活模块、关键行动 | 结果总览默认展示，不作为额外深度标签。 |
| 星盘轮 | P0 | 行星、星座、稳定的宫位、角度、逆行状态 | P0 支持点选和等价文本清单；完整双向索引进入 P1。 |

当出生时间未知时：

- 隐藏上升、天顶、“宫位地图”和所有依赖上升、天顶的解释，不用置灰假装可用。
- 星盘轮切换为无宫位的行星星座圆盘。
- 用一张清晰提示卡解释“补充出生时间后可解锁：上升、十二宫、事业坐标与关系轴线”，并提供“补充资料后重新计算”。

### 6.7 星语问答、统一历史记录与分享

**星语问答**

- 仅在报告完成后出现，报告已知事实自动作为上下文。
- 提供引导问题：“我在亲密关系里最需要被理解的是什么？”、“本周工作中适合主动争取什么？”、“这个相位如何影响我的表达？”
- 输入框禁止暗示医疗、财务、法律的确定性预测；触及敏感主题时给出安全提示与通用支持建议。
- 回答必须引用盘面模块名称或事实标签，并继续使用不绝对化的中文表述。
- P0 每份报告、每个会话最多支持 3 个用户问题（首问加 2 次追问），不跨报告携带问答上下文；达到上限时提示“本次星语问答已完成，可重新打开报告后继续探索”。敏感拦截态必须清楚说明“不能据此作出医疗、财务或法律判断”，并提供可讨论的自我观察方向；所有回答不得泄露不稳定或已隐藏的盘面事实。

**统一历史记录与分享**

- 已登录用户在确定性真值完成时按现有统一历史记录规范创建或更新一条“命理”类型结果，标题格式为“星座寰宇 · {昵称}的本命星盘”；结果页不另设收藏、档案或报告中心。匿名用户只保留当前会话的临时记录，登录后经明确确认才迁移为统一历史；未确认的临时记录在会话结束后删除。
- 分享默认生成脱敏卡：只含昵称或匿名、可计算的核心要素、主轴文案与生成日期；出生日期、精确时间、地点、度数默认不分享。时间未知或约时不稳定时不显示上升。
- 分享前提供“显示昵称 / 匿名”“显示大三要素 / 仅显示一句主轴”选择；时间未知或约时不稳定时，“显示大三要素”自动只显示已确定的可用项。允许保存或发送脱敏分享卡，但禁止导出原始出生资料、星盘真值、完整报告或包含精确出生时空的文件。

## 8. 视觉与交互规范

### 8.1 与现有设计系统的一致性

星座寰宇遵循 DESIGN.md 的玻璃拟态、柔光阴影、8px 网格、可访问性和移动端降级规范。桌面端先锁定现有 AI STUDIO 系统导航与命理大师模块侧栏，星座寰宇只设计右侧内容区；不允许为星座模块另做系统导航、命理侧栏、品牌或页头：

- 外层英雄区使用既有的 G-3 深度玻璃与 Z-4 阴影；普通信息卡使用平台现有的高对比实体底，不在卡中再叠加重模糊。
- 文字区保持实底与 WCAG 对比度，正文最小 14px，辅助文字最小 12px 且不以低对比度星点背景承载。
- 主按钮沿用平台的 200ms 状态反馈：悬浮轻微放大，按下 0.98 缩放，键盘聚焦有清晰的 2px 焦点环。
- 平板以下移除非必要 backdrop blur，星图背景改为静态低对比渐变，优先保证滚动和表单性能。

### 8.2 星座寰宇的专属语言

| 元素 | 规范 | 原因 |
| --- | --- | --- |
| 主色 | 直接使用现有命理模块的蓝—靛渐变 token | 与平台主色连续，保证导航和按钮不割裂。 |
| 专属点缀 | 仅使用平台现有青、紫、粉色 token 的低面积状态色 | 用于星体、相位连线与状态重点，不大面积铺色。 |
| 结果背景 | 继承平台现有浅色内容底和暗色模式 token；可在右侧英雄区加入低密度星图纹理 | 不另建深空背景体系，保证与现有命理模块连续。 |
| 星盘轮 | 线框优先、文字清晰、星体可点击；不使用高频闪烁和密集粒子 | 专业感来自信息结构，而不是炫技。 |
| 图标 | 使用行星、月亮、上升地平线、相位符号的线性图标，并提供中文文字标签 | 兼顾初学者理解与无障碍。 |
| 动效 | 星盘首次绘制 400 至 600ms；星体顺序淡入；尊重减少动态设置 | 形成仪式感，但不延迟结果。 |

### 8.3 亮点设计

#### 一、P1：星盘与生活语言的完整双向索引

P0 仅提供星体与关键相位的点选、事实定位和等价文本清单。P1 才允许用户点击星盘中的月亮、金星或任一相位后自动滚到对应解读，并支持反向点击解读卡片使星盘轮同步点亮相关星体与连线。

#### 二、宇宙护照与资料精度标签

护照头不只显示出生信息，还展示“时间精度：准确到分钟 / 约时 / 未知”和“盘面范围：含宫位 / 不含宫位”。这让用户立即知道报告可以相信到什么程度，是专业性最直观的来源。

#### 三、近期星运的行动三角

每个时间段固定输出“机会、留意、行动”三项，并显示日期范围与依据行运。相比笼统的“运势很好”，它把占星结果翻译成可执行的生活安排，同时避免制造焦虑。

#### 四、P1：术语即点即懂

P1 中，正文的上升、七宫、合相、逆行可打开小型百科浮层。浮层先用一句白话解释，再提供专业定义和当前报告中的对应位置；P0 只展示必要的事实标签和简短说明。

#### 五、时间未知的诚实模式

未知时间用户仍能完成探索，但所有无法得出的结果被明确排除，并给出“补充出生时间后可解锁什么”。这比默认中午出生更能建立长期信任。

## 9. 计算、内容与数据设计

### 9.1 真值先行架构

星座寰宇必须复用八字模块已经验证的“确定性计算先行，AI 只做解释”的模式。

\`\`\`mermaid
flowchart LR
    A["用户出生资料"] --> B["输入校验与时区解析"]
    B --> C["占星计算域"]
    C --> D["星盘真值：稳定的行星 / 度数 / 宫位 / 相位"]
    D --> E["结构化报告提示"]
    E --> F["AI 分区解读"]
    D --> G["星盘轮与事实卡先行渲染"]
    F --> H["生活模块、星运与问答"]
\`\`\`

必须将以下事实与解释文本分离保存：

| 数据层 | 内容 | 来源 | 是否允许 AI 修改 |
| --- | --- | --- | --- |
| 出生档案 | 日期、时间精度、时间或约时时段、地点、坐标、时区 | 用户输入与地点服务 | 否 |
| 星盘真值 | 黄道体系、宫制、行星位置、星座、度数、宫位、相位、角点、计算版本 | 占星计算服务 | 否 |
| 当前天象 | 计算时间、行运位置、行运与本命的关键相位 | 占星计算服务 | 否 |
| 解读报告 | 主轴、生活模块、行动建议、术语翻译 | AI，严格引用真值 | 可重新生成，但不得改变事实层 |

### 9.2 首期计算口径

为保证结果可复现，首期必须在报告和“计算方式”中公开以下固定口径：

- 黄道体系：回归黄道。
- 观测视角：地心视角。
- 宫制：Placidus 为默认；当计算结果中任一宫位宫头缺失、非有限值或十二宫顺序无法闭合时，使用 Whole Sign 作为明确标注的回退。
- 时间：出生城市对应 IANA 时区、当日历史夏令时与 `tzdbVersion`。本地时刻不存在时阻止提交并要求修正；本地时刻重复时必须选择第一次或第二次出现，并保存 `utcOffsetMinutes` 与 `localTimeDisambiguation`。约时时段跨 DST 切换时按每个对应的 UTC 实例计算。
- 相位：首期计算合相、六合、刑相、拱相、对冲；容许度冻结为合相 / 对冲 8°、刑相 / 拱相 6°、六合 4°，由 `orbTableVersion` 标识，不由 AI 自行判断。
- 大约时段：保存出生地当地时间的半开区间 `[localStart, localEnd)`。对所有面向用户的事实执行全区间稳定性校验；只有字段值在整个区间一致时才输出单值。度数、月亮、相位、角点、宫位或其解读任一不稳定时隐藏该字段及依赖解读，不取区间中点或任意默认时刻作为真值。
- 时间未知：以出生城市当地民用日 `[00:00, 次日 00:00)` 计算。不计算上升、天顶、宫位和所有宫位依赖结论；只展示在整个区间内稳定的星体星座与主要相位。月亮、行星度数、相位或其依赖解读不稳定时显示“当前资料无法确定”，不以 12:00 或任意时刻补算。

这里的“公开”不是用技术术语堆砌结果页，而是在盘面依据中可展开查看。专业口径固定，才能保证同一资料在重新打开报告时不发生无缘由的事实漂移。

### 9.3 推荐数据模型

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| AstroBirthProfile | name、birthDate、birthTime、timeRange（localStart、localEnd、timezone）、timePrecision、city、latitude、longitude、timezone、utcOffsetMinutes、localTimeDisambiguation、tzdbVersion | 只保存测算必需资料；名称可为空；约时保留原始区间，DST 重复时刻可复现。 |
| AstrologyChartFacts | zodiacSystem、houseSystem、calculatedAt、engineVersion、orbTableVersion、calculationRevision、planets、angles、houses、aspects、factStability、dataCompleteness | 本命盘不可变事实层；`factStability` 记录每项可展示性与隐藏原因。 |
| PlanetPlacement | body、sign、degree、house、retrograde、stability | 不稳定的 degree、house 或其他字段为 null，不生成伪单值。 |
| AspectFact | source、target、type、orb、strength、stability | 供星盘轮、相位卡和 AI 引用；不稳定相位不进入可见解释。 |
| TransitFact | startsAt、endsAt、transitingBody、natalTarget、aspect、theme | 支持近期星运按日期范围展示。 |
| AstrologyReport | headline、bigThree、modules、actions、transitGuidance、factReferences | AI 解释层；每段保留事实引用键。 |
| HistoryRecord | historyRecordId、ownerId、status、recalculatedAt、activeRevision | 统一历史中的逻辑记录；已登录用户在真值完成时写入。 |
| QuestionAnswer / ShareSnapshot | historyRecordId、calculationRevision、content 或 asset、shareToken | 问答和分享必须绑定到对应真值修订。 |

当出生日期、城市不变且用户仅补全或提高出生时间精度时，可更新同一逻辑历史记录，并写入 `recalculatedAt` 与新 `calculationRevision`；旧的星盘真值与报告按版本保留，不能原地覆盖。旧问答只在其原修订中只读保留、不自动迁移；旧分享卡资产和服务端分享链接在重算后立即失效。出生日期或城市改变时创建新记录。删除历史记录时级联删除该记录全部修订、出生档案、问答和分享资产，并撤销所有分享令牌；删除不可恢复。

### 9.4 AI 内容约束

- 系统提示明确要求：只解释给定真值；不重新计算、不杜撰星体、宫位或相位。
- 每个生活模块包含：结论、盘面依据、可能表现、行动建议四部分。
- 预测一律使用“倾向、可能、适合留意、可以尝试”等措辞，不使用“必然、注定、一定会”。
- 健康、财务、法律、孕育、死亡等高风险话题不输出结论性判断；必要时建议寻求合格专业人士。
- 当本命数据不完整时，模型仅可讨论可用事实，不得以话术补全上升和宫位。

## 10. 内容结构与示例文案标准

### 10.1 一句主轴

合格标准：

- 有个人张力，不是“你很有魅力，也很善良”。
- 不超过 28 字，能被用户记住。
- 由至少两项真值共同支持。
- 不带绝对化评价。

示例格式：“你的行动感很强，但真正的成长来自把即时反应变成清晰表达。”

### 10.2 大三要素／核心要素卡

含宫位结果的三张卡固定包含以下内容；无宫位结果只展示可计算且稳定的卡片，不为缺失项预留占位：

1. 术语层：太阳落白羊、月亮落巨蟹、上升落天秤。
2. 白话层：核心驱动力、情绪安全感、他人初见的你。
3. 行为层：一个高频表现和一个可练习动作。
4. 依据层：可点击回到星盘轮的具体位置。

### 10.3 P0 本周行动三角

每个周期使用统一结构，避免过度叙事：

| 字段 | 要求 |
| --- | --- |
| 时间 | 明确到开始与结束日期。 |
| 主题 | 一句话指出本周期关注点。 |
| 机会 | 一件值得把握的事。 |
| 留意 | 一项可能的摩擦或消耗。 |
| 行动 | 一件一周内可执行的动作。 |
| 依据 | 展开后显示相关行运与本命对象。 |

## 11. 异常、隐私与可信度设计

### 11.1 异常状态

| 场景 | 页面反馈 | 用户下一步 |
| --- | --- | --- |
| 城市搜索失败 | “暂时无法确认出生地点，请重新搜索或稍后再试。” | 重试搜索，不提交模糊地点。 |
| 日期或时间无效 | 字段下方显示具体错误 | 修正对应字段，已填内容保留。 |
| 占星计算失败 | “星盘绘制未完成，出生资料已保留。” | 重试计算或返回修改资料。 |
| AI 解读超时 | 先展示已完成的事实星盘与“解读仍在整理”；历史记录保留“解读整理中”状态 | 等待、只重试解读，或稍后从历史打开。 |
| 时间未知 | 非错误状态；显示范围说明 | 继续生成，或补充时间以解锁完整结果。 |
| 行运数据不可用 | 隐藏本周行动三角并说明“本命盘报告不受影响” | 继续阅读本命报告。 |

### 11.2 隐私原则

- 出生资料属于高敏感个人数据；已登录用户只用于本次计算及已写入统一历史记录的对应结果，匿名用户只保留在当前会话的临时记录中。
- 分享卡默认脱敏，不能通过一次点击公开精确出生时空。
- 历史列表只显示昵称、模块、日期和摘要，不显示生日、城市或度数。
- 仅在现有全局历史记录的对应条目提供“删除这条历史记录”；结果页不提供删除。删除前明确说明会删除全部计算修订、问答与分享资产，并撤销分享链接。
- 匿名用户可完成一次测算，登录后再询问是否将该次临时记录同步到跨端统一历史记录，不在填写前阻断体验；未确认同步的临时记录会在会话结束后删除。

### 11.3 可信度声明

首次结果页在“盘面依据”入口旁展示简短说明：“本命盘位置基于出生时空计算；内容用于自我探索与娱乐参考。”不在页面上重复长免责声明，但在分享、问答和高风险主题中强化边界。

## 14. 验收清单

### 14.1 流程验收

- [ ] 用户可在桌面端与移动端进入星座寰宇，且四个命理模块切换不丢失各自状态。
- [ ] 用户可完成完整本命盘流程；出生时间未知时按同一流程生成无宫位、无上升的可信降级报告。
- [ ] 未知出生时间时，上升、宫位、天顶和相应文案不会出现。
- [ ] 表单始终为两步，关注主题可空且单选，时间精度只有准确到分钟、大约时段、完全未知三档。
- [ ] 大约时段仅展示经过稳定性校验的角点、宫位与依赖结论；不稳定时自动按无宫位范围降级。
- [ ] 大约时段与完全未知均对全部时间相关事实执行稳定性校验；不稳定的月亮、度数、相位及依赖解读不出现，也不以中点或 12:00 代替。
- [ ] 本地时刻不存在时无法提交；本地时刻重复时用户可明确选择第一次或第二次出现，保存后的真值可复现。
- [ ] 加载进度只在真实计算阶段完成后推进，计算完成后先显示真值再显示解读。
- [ ] 前三段加载文案的主语是系统，只有 AI 解读阶段可使用 AI 主语；无宫位计算不展示“绘制十二宫”。
- [ ] 确定性真值完成即写入已登录用户的统一历史记录；解读超时可从同一条记录重试解读。
- [ ] 统一历史记录可重新打开与删除命理结果；删除入口不出现在测算结果页；删除会级联清除全部修订、问答与分享资产，脱敏分享符合隐私设计。

### 14.2 结果验收

- [ ] 移动端首屏无需滚动即可看到压缩护照、一句主轴和本周行动入口；含宫位或存在至少两个稳定要素时展示至少两张要素卡，其他情形只展示已确认事实；星盘轮位于首屏下方。
- [ ] 情感、事业、优势与本周行动均包含具体行动建议。
- [ ] 任一核心解读都可定位到一个或多个星盘事实。
- [ ] 所有预测性内容均带时间范围且不用绝对化语言。

### 14.3 视觉与无障碍验收

- [ ] 普通信息卡不嵌套重玻璃模糊，长文可读区域为高对比实体背景。
- [ ] 手机端所有主要可点击项不小于 44 × 44，底部操作不被安全区遮挡。
- [ ] 低性能或减少动态模式下不运行高频星点动画。
- [ ] 星盘轮有可访问的等价文本列表；P0 中键盘可选中关键星体与相位，复杂圆盘键盘漫游和完整双向索引属于 P1。
- [ ] 加载进度、流式结果和字段错误有读屏状态宣布；抽屉打开后焦点进入抽屉，关闭后返回触发控件。
- [ ] 表单、按钮、标签、错误提示和术语均使用一致的中文文案。
- [ ] 历史和入口最近记录不展示生日、城市、精确时间与度数；未知时间分享卡不展示上升。
- [ ] P0 视觉中不出现精度百分比、默认 12:00、当前位置、未采集的性别、年度运势、体系切换、设置、原始资料或完整报告导出和完整逐日行运。

## 15. 关键决策记录

| 决策 | 取舍 | 采用原因 |
| --- | --- | --- |
| 只保留完整本命星盘 | 输入成本更高，但结果更有区分度 | 以专业结果建立长期信任；出生时间未知通过同一流程降级，避免产生没有独立结果闭环的分支。 |
| 支持时间未知降级 | 不能展示最完整的星盘 | 避免虚构精确结果，保留没有出生时间用户的可用路径。 |
| 固定计算口径 | 少了一部分高级用户的自定义空间 | 先保证可复现和易解释，后续再评估高级设置。 |
| 先结论后术语 | 深度用户多一次点击 | 大多数用户先要知道“与我有什么关系”，深度信息仍完整保留。 |
| 行运使用行动三角 | 少了大量泛娱乐文案 | 把焦虑式预测转化为具体、克制的当下建议。 |
| 分享默认脱敏 | 分享卡信息较少 | 精确出生资料不可因社交分享被无意泄露。 |
