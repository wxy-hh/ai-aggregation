# 领域文档

本文件规定工程技能如何读取和写入本仓库的领域资产。

## 探索前读取

- **`GLOSSARY.md`**：领域术语、定义与规避同义词的唯一事实源；
- **`docs/adr/`**：与当前改动相关的架构决策记录；
- **`CONTEXT.md`**：仅作为稳定架构背景的补充阅读，不是每个特性都要更新的领域契约。

文件不存在时静默跳过，不为“补齐目录”而创建空文件。

## 写入边界

- 领域术语**默认只写入 `GLOSSARY.md`**，不默认同步 `CONTEXT.md`。
- `CONTEXT.md` 只记录跨特性、长期稳定的架构背景；只有用户明确要求同步时才更新，避免每个特性的术语在多处重复。
- ADR 只在决策难以逆转、脱离背景会令人意外且存在真实取舍时创建。不得为了流程完整而批量制造 ADR。
- `GLOSSARY.md` 不记录实现细节、文件路径或临时工单状态；这些内容分别进入 spec、ADR 或本地 tracker。

## 单上下文文件结构

```text
/
├── GLOSSARY.md
├── CONTEXT.md                 # 可选的稳定架构背景
└── docs/
    └── adr/
        ├── 0001-event-sourced-orders.md
        └── 0002-postgres-for-write-model.md
```

多上下文仓库以 `GLOSSARY-MAP.md` 指向各上下文的术语表；系统级 ADR 仍放在根 `docs/adr/`。

## 使用术语与冲突处理

在 issue 标题、重构提案、假设和测试名称中使用 `GLOSSARY.md` 已定义的术语，不引入其明确规避的同义词。代码或新讨论与术语、ADR 冲突时必须显式提出，不静默覆盖。
