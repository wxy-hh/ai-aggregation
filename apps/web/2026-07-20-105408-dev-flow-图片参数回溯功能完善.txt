  ---
  参数回溯功能产品设计分析

  现状问题

  目前 creative-cockpit.tsx:289-316 的参数回溯区域是纯静态占位——硬编码了 3
  条假数据（Seed/CFG/Steps），没有任何真实数据源和交互能力。它像个"花瓶"，无法真
  正帮助用户复现历史生成结果。

  核心需求

  用户痛点：生成了一张好图但忘记了参数组合，或想基于之前某次成功结果微调参数重新
  生成。

  产品交互设计方案

  一、功能定位

  一句话定义：让每次成功生成的参数组合可追溯、可一键复现，把"这次效果真好"变成"
  下次还能复现"。

  二、重点与亮点

  ┌─────┬───────────────────────────────────────────────────────────────────┐
  │ 维  │                               说明                                │
  │ 度  │                                                                   │
  ├─────┼───────────────────────────────────────────────────────────────────┤
  │ 重  │ 连接历史数据与当前工作流，让"复现"成为最小阻力路径                │
  │ 点  │                                                                   │
  ├─────┼───────────────────────────────────────────────────────────────────┤
  │ 亮  │ 从"参数记忆工具"升级为"创作迭代助手"——不只是回溯，更是基于已有结  │
  │ 点  │ 果的微调和优化                                                    │
  └─────┴───────────────────────────────────────────────────────────────────┘

  三、交互设计

  1. 数据来源

  已有 ImageHistoryItem.parameters 字段存储每次生成的完整参数（history-helpers.t
  s:212），直接复用，无需新增存储。需要补充持久化
  batchSize、negativePrompt、style 等完整参数快照。

  2. 交互形态

  ┌─ 参数回溯 ─────────────────────┐
  │ ⏱ 时间轴列表（最近5条）        │
  │ ┌──────────────────────────┐  │
  │ │ 🖼 缩略图  刚刚           │  │  ← 显示真实生成缩略图
  │ │ Seed: 12345  CFG: 7      │  │  ← 参数摘要
  │ │ Steps: 30  比例: 16:9    │  │
  │ │ [复现参数]  [查看大图]    │  │  ← 双操作按钮
  │ └──────────────────────────┘  │
  │ ┌──────────────────────────┐  │
  │ │ 🖼 缩略图  10分钟前       │  │
  │ │ Seed: 67890  CFG: 9      │  │
  │ │ Steps: 30  比例: 1:1     │  │
  │ │ [复现参数]  [查看大图]    │  │
  │ └──────────────────────────┘  │
  └────────────────────────────────┘

  3. 交互细节

  - 列表条目：展示真实缩略图 + 时间戳 + 核心参数摘要（Seed/CFG/Steps/比例/风格）
  - 点击条目 → 弹出详情面板（显示完整参数 + 大图）
  - "复现参数"按钮 → 一键回填到当前工作区（prompt、negativePrompt、style、ratio
  、steps、cfg、seed、batchSize）
  - "查看大图"按钮 → 查看该历史图片（可复用接力/历史页面）
  - hover 态：条目高亮 + 显示"复现参数"快捷按钮
  - 空状态：无历史记录时显示"暂无生成记录"，点击后自动引导首次生成

  4. 与页面的整合方式

  - 位于 CreativeCockpit 右侧栏底部（当前位置），数据源改为 useHistoryStore 的
  image 类型记录
  - 移动端（lg:hidden）不显示右侧栏，参数回溯改为底部弹层或整合到"历史记录"页
  - 每次生成成功后自动刷新列表（利用现有 addHistoryItem 触发 re-render）

  四、技术实现路径

  改动范围明确：
  1. history-store.ts / history-helpers.ts — 确认 parameters
  字段已持久化完整参数
  2. creative-cockpit.tsx — 参数回溯模块改为真实数据驱动，添加复现交互
  3. image/page.tsx — 提供 onRestoreParams 回调，接收回溯参数并回填

  五、不做范围

  - 不做跨会话的参数收藏/置顶（后续可迭代）
  - 不做参数差异对比（对比两次生成的参数差异）
  - 不做参数模板保存（保存为可复用模板）
