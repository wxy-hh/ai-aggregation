# 03 — LLM 流式解读接入

**What to build:** 结果页的主轴、大三要素、五个生活模块、本周行动三角、关键相位由豆包或 DeepSeek 基于用户真实盘面单次调用流式生成：服务端按报告 JSON schema 约束输出，边流边按 headline → bigThree → modules → transits 分区顺序解析推送，文案逐区浮现。模型切换器对星座生效（默认豆包，DeepSeek 走既有弱约束样例注入）。额度在解读前预留、按真实 usage 结算、失败释放；解读超时/校验失败时真盘保留、文案区诚实失败卡、重试只重跑解读不重算真值。28 条黄金主轴迁移为提示词 few-shot 样例；提示词强制 AI 不解读被降级隐藏的不稳定字段。mock 文案库自此不再服务生产。

**Blocked by:** 02 — 真实星盘端到端（报告路由 + 前端真值接缝）

**Status:** ready-for-agent

- [ ] 完整协议 chart-facts → headline → bigThree → modules → transits → complete 按序推送，前端逐区流式渲染
- [ ] 豆包（json_schema 强约束）与 DeepSeek（json_object 弱约束）双模型均可产出通过校验的报告，模型切换器生效
- [ ] AI 输出只引用已确认稳定的事实层字段，时间未知/约时降级下不编造上升、宫位等内容
- [ ] 额度预留/结算/释放与八字一致，管理员免预留；解读失败重试不重算真值
- [ ] 解读失败时无任何 mock 文案冒充生产输出，仅显示诚实失败卡 + 重试
- [ ] 黄金主轴样例库迁移到位并注入提示词，主轴输出符合 18–28 字要求
- [ ] 路由测试覆盖分区顺序、超时重试、usage 归一化结算
