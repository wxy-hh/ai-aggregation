## QA & 研发闭环默认执行准则 (Default Workflow Directive)

进行特性开发或架构重构时，默认遵循 `docs/agents/qa-workflow.md`，并按改动规模剪裁：
1. **未对齐不写码**：先厘清接口边界、验收标准和必要 ADR。人工独占技能由用户显式触发，Agent 不伪造调用或自问自答。
2. **规格与测试联动**：标准/慢车道在 spec 后运行 `/qa-test-planner`，默认 inline；新计划使用 Schema 1，并在阶段边界显式运行 `qa-check`，不新增 Hooks 或自动重试。
3. **成本与串行默认值**：默认单会话串行实现，不新增独立 QA。只有用户显式选择 `--independent` 或 `/implement-spec` 并行时才增加代理；独立规划最多 1 个，并行实现最多 2 个，均不自动指定或升级模型。
4. **真实浏览器卡点**：触及 {CORE_LINKS} 等核心链路时，交付前必须完成阶段 5 并落盘证据。遵循宿主工具优先级；macOS 且无更高优先级规则时先探活并默认使用 `ego-browser` 可见窗口，无 GUI 或不可用时说明后降级 Playwright。
5. **双轴审查卡点**：中大型改动交付前调用 `code-review` 完成 Standards + Spec 和三档分流，覆盖未提交及相关未跟踪文本；小型快车道按正本豁免。禁止为审查 `git add -N` 或自动 commit。

### 流程自检门禁 (Execution Gate)

涉及代码编写或架构重构的任务，在首轮回复或关键动作开始前（批量冲刺在首张工单开工时声明范围并内部连续推进），必须显式声明：
- **QA 阶段与车道**：[阶段、spec/工单来源、单工单或串行冲刺、快慢车道]
- **核心链路判定**：[是否触及 {CORE_LINKS} 等核心链路]
- **浏览器验收计划**：[触及核心链路时给出 qa-plan 路径和符合宿主优先级的工具；未触及时说明豁免理由]
- **代码审查状态**：[未到审查阶段 / 双轴与三档分流已通过 / 快车道豁免]。未通过或未豁免时禁止发起 commit 提议，交付汇报不得使用完成态表述
- **当前动作**：[本轮具体流程动作]

未声明上述状态即直接写码或声称交付完成，视为流程违规。自检是可见提醒，不能替代真实命令、证据和人工终审。

详见 `docs/agents/qa-workflow.md`。
