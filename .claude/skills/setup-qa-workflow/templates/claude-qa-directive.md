## QA & 研发闭环默认执行准则 (Default Workflow Directive)

进行特性开发或架构重构时，默认遵循 `docs/agents/qa-workflow.md`，并按改动规模剪裁：
1. **未对齐不写码**：先厘清接口边界、验收标准和必要 ADR。人工独占技能由用户显式触发，Agent 不伪造调用或自问自答。
2. **规格与测试联动**：标准车道在 spec 后、慢车道在 `/to-tickets` 后运行 `/qa-test-planner`，默认 inline；新计划使用 Schema 4，证据只认 qa-run 日志、断言标记、用例绑定与截图文件，并在阶段边界显式运行 `qa-check`，不新增 Hooks 或自动重试。
3. **成本与串行默认值**：默认单会话串行实现，不自动增加规划或实现代理；只有用户显式选择 `--independent` 或调用 `/implement-spec`（慢车道）时才增加对应代理，独立规划最多 1 个，并行实现最多 2 个，均不自动指定或升级模型。标准/慢车道的独立 Standards / Spec 审查使用独立上下文，可在同一用户会话前台完成，不属于可选实现代理。
4. **真实浏览器卡点**：触及 {CORE_LINKS} 等核心链路时，交付前必须完成阶段 5 并落盘证据。遵循宿主工具优先级；macOS 且无更高优先级规则时先探活并默认使用 `ego-browser` 可见窗口，无 GUI 或不可用时说明后降级 Playwright。
5. **双轴审查卡点**：标准/慢车道交付前，QA 工作流先 collect 审查包，再用 Skill 工具调用 `code-review`（参数写明特性目录与轮次）；审查子代理的派发、编号与落盘规则只在该技能内，不要用 Agent 工具自行派审查子代理。三档分流按编号逐条对账（驳回须引 ADR 或契约），增量复审自动上限 2 轮，人工终审确认。拿不到两份子代理报告时只交付待审查材料包并保持待独立审查，不运行最终 `qa-check review`，由独立会话或人工接续；小型快车道按正本豁免。禁止为审查 `git add -N` 或自动 commit。

### 流程自检门禁 (Execution Gate)

涉及代码编写或架构重构的任务，只在任务首轮与宣称交付时完整声明以下内容；其他回合不重复，状态变化时最多补充一行：
- **QA 阶段与车道**：[阶段、spec/工单来源、快/标准/慢车道]
- **核心链路判定**：[是否触及 {CORE_LINKS} 等核心链路]
- **浏览器验收计划**：[触及核心链路时给出 qa-plan 路径和符合宿主优先级的工具；未触及时说明豁免理由]
- **代码审查状态**：首轮写 [未到审查阶段 / 快车道豁免]；交付时不自填，直接引用 `node tooling/scripts/qa-check.mjs review` 输出的结果行与范围说明行（拿不到两份子代理原文时写“待独立审查”）。其 `结果: PASS` 只称“机器校验通过”，不证明独立来源、不判断证据语义、不构成交付授权，不替代独立审查与人工终审。未通过或未豁免时禁止发起 commit 提议，交付汇报不得使用完成态表述
- **当前动作**：[本轮具体流程动作]

未声明上述状态即直接写码或声称交付完成，视为流程违规。自检是可见提醒，不能替代真实命令、证据和人工终审。

详见 `docs/agents/qa-workflow.md`。
